### T006 - Add Deterministic Dataset Filter Contracts

#### Objective

Add a small explicit filter model that evaluates retained local rows into a
row-id-aligned mask. Support numeric ranges and categorical sets with clear
missing-value semantics and AND composition, without introducing a query
language or dataframe engine.

#### Scope

- Create `crates/rawscope-data/src/dataset_filter.rs`.
- Define validated numeric and categorical predicates by column name.
- Evaluate predicates against `LoadedSourceTable` and T005 field catalog.
- Return a `FilterMask` aligned to visual row ids plus included/excluded counts.
- Add stable filter revision support for workbench/GPU caching.
- Support filter removal, replacement by column, and clear-all operations.
- Export narrow types/functions through `rawscope-data/src/lib.rs`.

#### Out Of Scope

- No parser, expression language, OR groups, regex, substring matching,
  computed columns, SQL, or remote execution.
- No workbench controls or GPU buffers; T008 owns integration.
- No projection or brush-as-filter behavior.
- No serde; T015 creates evidence DTOs.

#### Blocked By

T005.

#### Why It Is Blocked

Predicate validation and control choices need the authoritative field kinds and
domains from the visual field catalog.

#### Implementation Details

Define explicit filter contracts:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum DatasetFilter {
    NumericRange {
        column_name: String,
        min_inclusive: f64,
        max_inclusive: f64,
        include_missing: bool,
    },
    Categories {
        column_name: String,
        included_values: Vec<String>,
        include_missing: bool,
    },
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Default)]
pub struct FilterRevision(pub u64);

#[derive(Debug, Clone, PartialEq, Default)]
pub struct FilterSet {
    pub filters: Vec<DatasetFilter>,
    pub revision: FilterRevision,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FilterMask {
    included: Vec<u32>,
    included_count: usize,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FilterEvaluation {
    pub mask: FilterMask,
    pub included_count: usize,
    pub excluded_count: usize,
    pub revision: FilterRevision,
}
```

Expose mask methods without leaking mutable storage:

```rust
impl FilterMask {
    pub fn includes(&self, row_id: RowId) -> bool;
    pub fn as_gpu_u32_slice(&self) -> &[u32];
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}
```

The vector contains exactly `0` or `1` for every source row. Index `i` maps to
`RowId(i)` and evaluation returns an error if retained rows violate contiguous
row-id alignment.

FilterSet APIs:

```rust
impl FilterSet {
    pub fn replace_for_column(&mut self, filter: DatasetFilter);
    pub fn remove_column(&mut self, column_name: &str) -> bool;
    pub fn clear(&mut self);
    pub fn is_active(&self) -> bool;
}

pub fn evaluate_filters(
    source: &LoadedSourceTable,
    catalog: &VisualFieldCatalog,
    filters: &FilterSet,
) -> Result<FilterEvaluation, FilterError>;
```

Increment revision only when effective filter content changes. Replacing a
predicate with an equal predicate does not increment it.

Rules:

- Predicates across columns use AND.
- Numeric min/max are inclusive; reject NaN, infinity, or min > max.
- Category matching is exact after the same outer trim used by T005.
- Sort/deduplicate `included_values` at construction or replacement.
- Empty category set includes no non-missing rows. It is not equivalent to
  removing the filter.
- Missing values match only when `include_missing` is true.
- Numeric parse failures are treated as invalid/missing for matching and never
  coerced to zero.
- Empty `FilterSet` returns an all-ones mask.

Errors:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum FilterError {
    UnknownColumn { column_name: String },
    IncompatibleColumnKind { column_name: String },
    InvalidNumericRange { column_name: String },
    NonContiguousRowIds { expected: RowId, actual: RowId },
    RowWidthMismatch { row_id: RowId },
}
```

Implement `Display` and `Error` with useful column/row context. Do not log row
values.

#### Migration Notes

- No existing loader or point representation changes.
- No serialized artifact changes.
- Synthetic datasets without source rows remain unfiltered until a later
  explicit synthetic-field catalog exists.
- Keep filter errors recoverable; workbench integration decides presentation.

#### Misinterpretations To Prevent

- Wrong interpretation: compact the points vector to filtered rows.
  Correct rule: preserve one mask entry per original row id.
- Wrong interpretation: empty category selection means all categories.
  Correct rule: it means no non-missing category values.
- Wrong interpretation: add arbitrary predicate expressions.
  Correct rule: only numeric range and exact category set.
- Wrong interpretation: serialize from data crate.
  Correct rule: T015 maps contracts into render-owned DTOs.

#### Invariants

- Mask length equals source row count.
- Mask values are only zero or one.
- Mask index equals stable row id.
- Filter composition is deterministic AND.
- Revisions change only on effective state changes.
- Missing and invalid values follow explicit predicate flags.

#### Acceptance Criteria

- [ ] Empty filters produce all rows.
- [ ] Numeric/category filters and AND composition produce expected masks.
- [ ] Missing/invalid/empty-category cases are covered.
- [ ] Unknown/incompatible columns return contextual errors.
- [ ] Equal replacement leaves revision unchanged; real replacement increments.
- [ ] No query/parser/serde/UI dependency is introduced.
- [ ] Focused tests, formatting, and workspace check pass.

  mutation/revision APIs, tests, facade.

- Human review: empty-category semantics and inclusive range wording.

  numeric and exact-category predicates now evaluate retained rows into a
  contiguous GPU-ready `u32` mask with deterministic AND semantics.
- Architectural decisions: normalized category sets both on replacement and
  evaluation, kept revisions content-sensitive, and treated invalid numeric
  input through the predicate's explicit missing policy without coercion.
- Validation: all six named filter tests, all 36 `rawscope-data` tests,
  `cargo fmt --all --check`, and `cargo check --workspace` passed.
- Not run: no GPU upload or workbench UI validation; T008 owns both consumers.
- Remaining risk: revision overflow follows normal `u64` arithmetic and is not
  expected in realistic sessions; T008 should cache by revision and row count.
