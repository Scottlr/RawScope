### T017 - Add Progressive GPU Pan Reprojection And Refinement

#### Objective

Make panning the 200,000-row scatter view feel immediate without weakening the
final analytical result. Cursor movement must update only viewport and render
state; the last completed density field is reprojected on GPU while dragging,
preview rebins are coalesced and frame-bounded, and pointer release produces one
exact full-resolution field plus current CPU summaries.

#### Scope

- Split interactive density scheduling out of oversized workbench owners into
  `apps/rawscope-workbench/src/app_render_schedule.rs`.
- Snapshot the viewport represented by each completed density count buffer.
- Reproject the last completed field from its source viewport into the current
  display viewport in the render shader while a pan gesture is active.
- Coalesce any number of cursor moves into one latest viewport revision.
- Dispatch at most one bounded preview rebin per presented frame and never
  dispatch another while the previous preview is still in flight.
- Use a 128x128 preview grid no more often than every 50 ms by default so newly
  exposed regions can fill during a long drag without rebuilding the exact
  256x256 field for every event.
- Swap completed preview fields through T007's double-buffered density
  resources without blanking or blocking the currently rendered field.
- Defer CPU marginals, inspection-cache rebuilds, settled stats readback, and
  window-title/report state refresh while the pointer is moving.
- On pointer release, cancel stale preview intent, dispatch one exact 256x256
  rebin for the latest viewport, and refresh settled CPU-facing state once.
- Expose a subtle existing-status-surface `Refining` state; do not add a
  diagnostics panel, FPS counter, or developer overlay.
- Apply the same scheduler contract to wheel zoom once pan behavior is proven,
  because both are viewport gestures over the same density field.

#### Out Of Scope

- No benchmark dashboard, public throughput/FPS claim, synthetic performance
  demo, temporary diagnostic command, or startup/window/screenshot test.
- No reduction of the final 256x256 density grid or permanent row sampling.
- No change to pan direction, zoom anchoring, plot geometry, density transform,
  palette, bin semantics, or source row identity.
- No background thread, async runtime, sleep-based test, continuous busy loop,
  or redraw after the scheduler becomes idle.
- No filter-mask semantics, point reveal, comparison mode, relief, transitions,
  evidence schema, or timeline scheduling. Later tasks consume this contract.
- No CPU interpolation that invents bins outside the source field's covered
  data range.

#### Implementation Details

Create the render-owned pure contract in
`crates/rawscope-render/src/scatter_density_reprojection.rs`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DensityQualityTier {
    Preview,
    Exact,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct DensityFieldViewport {
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub grid_width: u32,
    pub grid_height: u32,
    pub viewport_revision: u64,
    pub quality: DensityQualityTier,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct DensityReprojection {
    pub source: DensityFieldViewport,
    pub display_x_range: F32Range,
    pub display_y_range: F32Range,
}
```

Provide a pure mapping from current plot UV to source density UV. Screen y grows
downward, while data y grows upward:

```text
data_x = display_x_min + display_u * display_x_span
data_y = display_y_max - display_v * display_y_span
source_u = (data_x - source_x_min) / source_x_span
source_v = (source_y_max - data_y) / source_y_span
```

If either source coordinate lies outside `[0, 1]`, return uncovered rather than
clamping to an edge bin. The render shader draws the normal plot background in
that uncovered region until a preview or exact field covers it. Reprojection
does not alter counts and does not claim the old bins are an exact rebin of the
new viewport.

Extend the scatter render parameters with source and display ranges or a
precomputed affine transform. Keep the uniform aligned for the locked wgpu
version and test any padding explicitly. The fragment shader samples the
currently completed count buffer through transformed UV only while the
scheduler is not `SettledExact`.

Create the workbench-owned state in
`apps/rawscope-workbench/src/app_render_schedule.rs`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum InteractiveDensityPhase {
    SettledExact,
    Reprojecting,
    PreviewInFlight,
    FinalRefinePending,
    FinalRefineInFlight,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) struct InteractiveDensityConfig {
    pub(crate) preview_grid_width: u32,
    pub(crate) preview_grid_height: u32,
    pub(crate) preview_rebin_interval_ms: u64,
}

pub(crate) struct RenderSchedule {
    phase: InteractiveDensityPhase,
    latest_viewport_revision: u64,
    source_viewport_revision: u64,
    dispatched_viewport_revision: Option<u64>,
    last_preview_dispatch_at: Option<Instant>,
}
```

Use named defaults owned next to this config:

```rust
const PREVIEW_GRID_WIDTH: u32 = 128;
const PREVIEW_GRID_HEIGHT: u32 = 128;
const PREVIEW_REBIN_INTERVAL_MS: u64 = 50;
```

The values are internal quality policy, not user-facing controls. Keep them in
one typed config so future profiling can change them without scattering magic
numbers. Validate non-zero dimensions and interval. Do not expose shader or
frame-budget knobs in the UI.

The state machine must enforce these transitions:

1. Gesture start snapshots the last completed exact/preview field and source
   viewport, then enters `Reprojecting`.
2. Each cursor move updates `ScatterViewport`, bumps one viewport revision,
   writes only display/reprojection uniforms, and requests redraw. It does not
   scan points, dispatch compute, map GPU memory, recreate buffers, update CPU
   marginals, or update evidence/report state.
3. Frame preparation may dispatch one 128x128 preview only when the configured
   interval has elapsed and no preview is in flight. Multiple move revisions
   collapse to the latest one.
4. A completed preview swaps into the visible source buffer and records the
   viewport it represents. Continued dragging reprojects from that newer field.
5. Gesture release records the latest viewport, invalidates queued stale
   preview intent, and schedules exactly one 256x256 exact update.
6. Final completion swaps the exact field, performs at most one settled
   full-count readback, refreshes marginals/inspection caches/stats, clears the
   `Refining` status, and returns to `SettledExact`.

Do not call the exact density path directly from `CursorMoved`. Event handlers
mutate state and request a frame; frame preparation owns GPU submission. The
scheduler may use `Instant` in production, but tests pass explicit monotonic
times or elapsed durations and never sleep.

Wheel zoom uses the same begin/update/finalize contract. A discrete wheel event
may schedule its exact settle after the existing platform event burst closes;
do not add an arbitrary blocking sleep. If winit exposes no explicit wheel-end
event, use a redraw-driven quiet deadline stored in the scheduler and test it
with injected times.

The status surface distinguishes analytical freshness without noisy technical
language:

- `Refining` while a reprojected/preview field is visible.
- Existing normal status once the exact field and summaries match the viewport.

Do not display grid sizes, milliseconds, dispatch counts, FPS, paths, or GPU
internals in persistent chrome.

#### Before / After

**Before:**

```rust
viewport.pan_by(data_delta_x, data_delta_y);
self.last_drag_position = Some(position);
self.recompute_density()?;
```

**After:**

```rust
viewport.pan_by(data_delta_x, data_delta_y);
self.last_drag_position = Some(position);
self.render_schedule.viewport_changed(*viewport);
self.scatter_density_renderer
    .set_display_viewport(*viewport, self.render_schedule.latest_revision());
self.request_redraw();
```

GPU compute and settled CPU summaries then run from frame preparation according
to the state machine, never directly from the pointer callback.

#### Misinterpretations To Prevent

- Wrong interpretation: throttle `CursorMoved` but still perform a complete
  synchronous rebin/readback in selected callbacks.
  Correct rule: cursor callbacks perform constant-size state/uniform work only.
- Wrong interpretation: stretch the last texture in screen space.
  Correct rule: map current screen UV through data coordinates into the source
  field so direction and scale remain analytically aligned.
- Wrong interpretation: clamp uncovered source UV and smear edge bins.
  Correct rule: render uncovered plot background until a new field covers it.
- Wrong interpretation: keep the 128x128 preview as the final result.
  Correct rule: release always settles to the exact 256x256 field.
- Wrong interpretation: recompute marginals for every preview.
  Correct rule: CPU summaries and inspection caches refresh only for the final
  settled revision.
- Wrong interpretation: claim a target FPS without measurement.
  Correct rule: accept observable interaction behavior and record hardware/data
  during manual review without publishing a benchmark claim.

#### Invariants

- Cursor movement performs no point upload, pipeline creation, count-grid map,
  source-table scan, or CPU marginal scan.
- The latest viewport state is visible immediately through reprojection.
- At most one preview dispatch is submitted per presented frame, and at most
  one preview is in flight.
- Preview completion can never overwrite a newer final-revision result.
- Every completed density field records the exact viewport and quality tier it
  represents.
- Uncovered reprojection regions never sample clamped edge bins.
- Gesture release produces one exact full-resolution result for the latest
  viewport revision.
- Settled CPU summaries, inspection data, stats, and evidence-facing revisions
  describe the same exact field.
- Horizontal and vertical pan directions remain exactly as approved by the
  user.
- Idle state does not request continuous redraw.
