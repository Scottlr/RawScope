### T009 - Add Density Inspection Lens And Pinned Evidence

#### Objective

Make dense pixels inspectable without pretending they are individual points.
Hovering a plot bin should reveal its exact data range, included-row count, and
bounded row/category evidence; clicking pins that inspection in the right rail.

#### Scope

- Create `crates/rawscope-render/src/scatter_inspection.rs` with a deterministic
  viewport-aligned inspection grid built from points plus active filter mask.
- Reuse aggregate binning conventions and retain bounded, sorted row-id samples.
- Add plot-point to bin lookup with exact x/y bin ranges.
- Create a lightweight probe overlay renderer or extend the existing brush
  overlay through an explicit non-selection variant.
- Create `apps/rawscope-workbench/src/app_scatter_inspection.rs` for hover/pin
  state and cache revisions.
- Create `apps/rawscope-workbench/src/ui_scatter_inspection.rs` for compact
  tooltip and pinned inspector content.
- Populate profile-relevant category summaries from retained source rows only
  when an inspection is pinned, not on every pointer move.
- Disable hover probing while pan/brush gestures are active or while the
  inspection cache is stale during an interactive render update.

#### Out Of Scope

- No individual-point glyphs; T010 owns point reveal.
- No full source-row scan per hover and no GPU readback per hover.
- No arbitrary tooltip table, free-form aggregation, or every-column summary.
- No evidence artifact changes; T015 serializes pinned inspection context.

#### Blocked By

T002, T004, and T008.

#### Why It Is Blocked

Inspection needs solved plot coordinates/axes, explicit Inspect mode, and the
same filter mask/revision as rendered density.

#### Related Code

#### Implementation Details

Add render-owned inspection types:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ScatterInspectionConfig {
    pub grid_width: u32,
    pub grid_height: u32,
    pub max_row_ids_per_bin: usize,
}

impl Default for ScatterInspectionConfig {
    fn default() -> Self {
        Self {
            grid_width: 256,
            grid_height: 256,
            max_row_ids_per_bin: 16,
        }
    }
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ScatterInspectionBin {
    pub count: u32,
    pub row_ids: Vec<RowId>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterInspectionGrid {
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub grid_width: u32,
    pub grid_height: u32,
    pub filter_revision: FilterRevision,
    pub bins: Vec<ScatterInspectionBin>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterInspectionHit {
    pub bin_x: u32,
    pub bin_y: u32,
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub count: u32,
    pub row_ids: Vec<RowId>,
}
```

Builder and hit API:

```rust
pub fn build_scatter_inspection_grid(
    points: &[ScatterPointRecord],
    mask: &FilterMask,
    x_range: F32Range,
    y_range: F32Range,
    filter_revision: FilterRevision,
    config: ScatterInspectionConfig,
) -> Result<ScatterInspectionGrid, ScatterInspectionError>;

impl ScatterInspectionGrid {
    pub fn inspect_fraction(&self, x_fraction: f32, y_fraction: f32)
        -> Option<ScatterInspectionHit>;
}
```

Use the active density renderer's exact grid width/height rather than an
independent inspection resolution. The default above matches the current
256x256 grid, but workbench construction must overwrite it when the renderer
uses another valid size. Use the same edge convention as density compute: max
values enter the final bin, screen y is inverted into data y, and out-of-range
points are excluded.
Row samples are the lowest row ids encountered in deterministic point order.
Counts include every masked-in row even when samples are truncated.

The workbench state:

```rust
#[derive(Debug, Clone, Default)]
pub(crate) struct ScatterInspectionState {
    pub(crate) grid: Option<ScatterInspectionGrid>,
    pub(crate) hovered: Option<ScatterInspectionHit>,
    pub(crate) pinned: Option<PinnedScatterInspection>,
    pub(crate) cache_viewport_revision: u64,
    pub(crate) cache_filter_revision: FilterRevision,
}

#[derive(Debug, Clone, PartialEq)]
pub(crate) struct PinnedScatterInspection {
    pub(crate) hit: ScatterInspectionHit,
    pub(crate) category_summaries: Vec<PinnedCategorySummary>,
    pub(crate) source_rows: Vec<LoadedSourceRow>,
}
```

Rebuild the grid after a settled viewport/filter update. Pointer movement in
Inspect mode performs only plot fraction conversion plus O(1) bin lookup and UI
projection. Pinning may look up the bounded row sample and summarize only
profile-priority categorical fields for those sampled rows. Display explicit
wording such as `16 sampled rows of 842 in bin` when truncated.

Probe overlay uses a distinct thin high-contrast rectangle/contour and must not
publish a linked selection or alter brush state. It is clipped to T001 plot.

Tooltip content is bounded:

- row count;
- x range;
- y range;
- sample disclosure;
- at most three profile-priority category lines.

Pinned right-rail content may show bounded source rows through existing
drilldown formatting, but remains a separate inspection concept from brush
selection.

#### Migration Notes

- No existing selection/evidence behavior changes.
- Clear hover on mode change, gesture start, surface switch, or stale cache.
- Preserve pinned inspection through non-destructive UI repaints; clear it on
  dataset, projection, or filter revision change.
- No serde until T015.

#### Misinterpretations To Prevent

- Wrong interpretation: read the GPU count buffer on every cursor move.
  Correct rule: O(1) CPU inspection-grid lookup.
- Wrong interpretation: call sampled row ids the complete bin membership.
  Correct rule: disclose count and sample limit separately.
- Wrong interpretation: publish hover as a linked selection.
  Correct rule: hover/pin are inspection state; brush remains selection.
- Wrong interpretation: summarize all source columns in a tooltip.
  Correct rule: bounded profile-priority context only.

#### Invariants

- Inspection grid uses the same viewport and filter revisions as settled density.
- Inspection grid dimensions equal the active density grid dimensions.
- Pointer-time work is independent of total dataset size.
- Count is exact for the cached cohort; row ids are explicitly sampled.
- Hover never mutates selection/filter/evidence state.
- Pinned row lookups preserve stable row ids.
- Probe overlay stays inside the plot.

#### Acceptance Criteria

- [x] Inspection bin math matches density edge conventions.
- [x] Filtered-out rows never appear in counts or samples.
- [x] Hover lookup is O(1) and allocation-free after cache build.
- [x] Pinning discloses sample count versus exact bin count.
- [x] Active pan/brush hides the probe and avoids cache rebuild.
- [x] Dataset/filter/projection changes clear stale pins.
- [x] Focused tests, formatting, and workspace check pass.

## Final Notes

- Recommended implementation order: grid math, revision state, probe overlay,
  hover UI, pin summaries, native review.
- Unresolved questions: final default inspection grid/sample size after human
  review.
- Risks: cache rebuild cost and confusing sample versus exact membership.
- Human review: tooltip density, probe contrast, and pinned inspector hierarchy.
- Completion: implemented on `codex/t009-density-inspection`; exact settled
  density bins now have a mask-aligned CPU inspection cache, O(1) hover lookup,
  a clipped teal probe, concise tooltip, and click-to-pin source-row context.
- Architectural decisions: render owns bin math, exact counts, bounded sorted
  samples, and probe rendering; workbench owns cache revisions and pin lifecycle.
  Samples use `Arc<[RowId]>` so hover clones no row vector, while source lookup
  and up to three four-value category summaries occur only when pinning.
- Validation: 32 render unit tests and all render integrations, 82 workbench
  tests, `cargo fmt --all --check`, and `cargo check --workspace` passed. Native
  Lichess review on 200,000 rows pinned an exact 22-row rating bin, disclosed
  16 sampled rows, showed stable source IDs and bounded winner/category/time
  control context, and cleared hover/pin after filtering to 99,649 rows.
- Not run: no hover screenshot test, window/startup test, benchmark, GPU
  readback diagnostic, or timing assertion was added or run.
- Remaining risk: topographic reconstruction can color a zero-count bin from
  neighboring bins; inspection deliberately reports the exact addressed bin
  rather than inventing interpolated row membership. T010 should reuse this
  cache and preserve that disclosure distinction.
