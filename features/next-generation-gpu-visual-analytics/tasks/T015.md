### T015 - Add Evidence V4 Visual Query Context

#### Objective

Add an additive scatter evidence v4 that records the exact active cohort and
visual query: filters, projection, density mode/presentation, point reveal,
pinned inspection, and relief config. Preserve all v1/v2/v3 APIs and artifact
shapes unchanged.

#### Scope

- Create `crates/rawscope-render/src/scatter_selection_evidence_v4.rs`.
- Create `crates/rawscope-render/src/scatter_selection_export_v4.rs`.
- Create `apps/rawscope-workbench/src/app_report_bundle_v4.rs` rather than
  adding bulk to the existing report owner.
- Add JSON/Markdown v4 artifact constants and deterministic formatters.
- Map data-owned filter/projection contracts into render-owned serde DTOs.
- Include active/full cohort counts, filter revision-independent definitions,
  difference formula/baseline, point-reveal disclosure, pinned inspection, and
  relief settings when applicable.
- Make v4 the default new scatter report after this feature; keep explicit
  legacy v1/v2/v3 functions callable and tested.
- Add `docs/schemas/scatter-selection-evidence-v4.md` because artifact shape
  changes are real product behavior.

#### Out Of Scope

- No mutation of v1/v2/v3 structs, JSON keys, Markdown text, or constants.
- No timeline v4 in this task.
- No screenshot/image capture, binary artifact, cloud upload, or database.
- No serialization in `rawscope-data`.
- No transient hover or animation progress in evidence.

#### Blocked By

T009, T010, T011, T012, and T013.

#### Why It Is Blocked

V4 must serialize final stable contracts rather than placeholders that later
tasks would invalidate. T014 motion is intentionally not a blocker because
transient progress is excluded.

Add version constants:

Add render-owned evidence contracts (field types may reference stable
render/data types where they do not derive serde):

```rust
#[derive(Debug, Clone, PartialEq)]
pub struct ScatterSelectionEvidenceV4 {
    pub schema_version: u32,
    pub dataset_identity: DatasetIdentity,
    pub active_dataset_profile: Option<DatasetProfileId>,
    pub visual_query: ScatterVisualQueryV4,
    pub cohort: ScatterCohortEvidence,
    pub selected_row_count: usize,
    pub selected_percentage: f32,
    pub selected_row_id_sample: Vec<RowId>,
    pub selected_record_sample: Vec<SelectedPointSampleV2>,
    pub selected_source_column_names: Vec<String>,
    pub selected_source_row_sample: Vec<SelectedSourceRowSample>,
    pub comparison: ScatterSelectionComparison,
    pub aggregate_context: ScatterAggregateEvidenceContext,
    pub pinned_inspection: Option<PinnedScatterInspectionEvidence>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterVisualQueryV4 {
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub grid_width: u32,
    pub grid_height: u32,
    pub projection: ScatterProjection,
    pub filters: Vec<DatasetFilter>,
    pub density_mode: ScatterDensityMode,
    pub density_encoding: DensityEncoding,
    pub density_presentation: ScatterDensityPresentation,
    pub difference: Option<DifferenceDensityEvidenceConfig>,
    pub point_reveal: PointRevealEvidence,
    pub relief: Option<ReliefFieldConfig>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ScatterCohortEvidence {
    pub full_row_count: usize,
    pub included_row_count: usize,
    pub excluded_row_count: usize,
}

#[derive(Debug, Clone, PartialEq)]
pub struct PointRevealEvidence {
    pub mode: PointRevealMode,
    pub eligible_count: usize,
    pub rendered_count: usize,
    pub sampled: bool,
}

#[derive(Debug, Clone, PartialEq)]
pub struct DifferenceDensityEvidenceConfig {
    pub formula: &'static str,
    pub baseline: &'static str,
    pub baseline_total: u64,
    pub active_total: u64,
    pub max_abs_delta: f32,
}

#[derive(Debug, Clone, PartialEq)]
pub struct PinnedScatterInspectionEvidence {
    pub bin_x: u32,
    pub bin_y: u32,
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub row_count: u32,
    pub row_id_sample: Vec<RowId>,
    pub sample_limit: usize,
}
```

V4 intentionally repeats the explicit v3 selection/sample fields shown above.
Do not extract a shared v3/v4 base struct or refactor v3 merely to remove this
duplication.

Pinned inspection evidence includes exact bin range/count, bounded row-id
sample, and explicit sample limit. It excludes transient screen coordinates and
hover state.

Serde artifacts remain private to `scatter_selection_export_v4.rs`. Use:

```rust
#[derive(Debug, Serialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
enum DatasetFilterArtifact {
    NumericRange {
        column_name: String,
        min_inclusive: f64,
        max_inclusive: f64,
        include_missing: bool,
    },
    Categories {
        column_name: String,
        included_values: Vec<String>,
        include_missing: bool,
    },
}
```

Exact JSON requirements:

- stable `artifact_kind` and `schema_version`;
- filters in deterministic profile/UI order, with category values sorted;
- projection variant plus explicit mean/difference sign label;
- difference formula identifier
  `active_share_minus_full_baseline_share`;
- point sample disclosure;
- relief config only when presentation is ReliefField;
- no filter revision, animation progress, cursor position, full category catalog,
  GPU adapter, or transient stats freshness flag.

Report integration:

- add `write_scatter_bundle_v4()` in the new focused module;
- manifest identifies evidence v4 and generated file names;
- visual context text uses v4 query fields;
- default scatter export routes to v4 after all constructors are available;
- retain explicit `write_scatter_bundle`, `v2`, and `v3` tests/APIs.

#### Migration Notes

- V1/V2/V3 artifacts are immutable compatibility baselines.
- Default new report output moves to v4; callers requesting older APIs still
  receive exactly old formats.
- Add schema docs only for v4.
- Full local path behavior remains as current evidence contract unless a
  separately approved privacy migration changes it.

#### Misinterpretations To Prevent

- Wrong interpretation: add fields to v3 with `serde(default)`.
  Correct rule: new v4 types/artifact; old shapes unchanged.
- Wrong interpretation: serialize filter revision or animation progress.
  Correct rule: serialize semantic query only.
- Wrong interpretation: call sampled point/bin ids exact membership.
  Correct rule: include exact counts and sample disclosure.
- Wrong interpretation: put serde derives on data filter types.
  Correct rule: private render DTO mapping.

#### Invariants

- Legacy JSON/Markdown outputs remain byte-for-byte where fixtures exist.
- V4 constructor rejects incoherent mode/config combinations.
- V4 rejects FilteredDifference evidence that claims Relief or rendered points.
- Filter definitions and category order are deterministic.
- Cohort counts add up exactly.
- Difference formula/baseline and sampling disclosure are explicit.
- Transient UI/GPU state never enters evidence.
- Report code is split instead of growing the existing >400-line owner.

## Final Notes

- Recommended implementation order: v4 in-memory types, coherence validation,
  DTO/JSON, Markdown, report module, default routing, schema doc.
- Unresolved questions: whether evidence paths need a future redaction option.
- Risks: accidental legacy output changes and report-owner growth.
- Human review: v4 field names, difference formula wording, and sample disclosure.
- Completion: implemented on `codex/t015-evidence-v4`; new scatter exports now
  prefer schema v4 and support filtered cohorts with reproducible projection,
  filter, mode, encoding, point-reveal, pin, relief, and difference context.
- Files changed: additive render v4 contract, private DTO mapper, JSON/Markdown
  formatter, integration tests and facade; focused workbench v4 report writer,
  export assembly/default routing, filtered-export availability, report tests;
  v4 schema document, task index, and this handoff.
- Architectural decisions: v4 extends an immutable v3 value in memory and reuses
  the untouched v3 serializer only for repeated legacy payload fields. Semantic
  data contracts remain serde-free; all DTO mapping stays private to render.
  Difference max-absolute share delta is reconstructed from settled active and
  baseline inspection grids at export time, so the artifact records the same
  formula and cohort totals as the GPU field without readback coupling.
- Validation: 56 render unit tests plus all integrations, 93 workbench tests,
  the named v2/v3/v4 compatibility/export tests, `cargo fmt --all --check`, and
  `cargo check --workspace` passed. The native 200,000-row Lichess app loaded
  the v4 build and filtered cohort without runtime or WGPU errors.
- Not run: no screenshot/window/startup test or GPU adapter sweep was needed for
  this CPU/report task. A native brush export was attempted, but Windows input
  automation did not deliver a selection gesture; bundle emission and default
  v4 artifact contents are covered by focused behavior tests instead.
- Remaining risk: local source paths remain intentionally present under the
  established evidence identity contract. Any redaction option needs a separate
  compatibility design rather than an implicit v4 change.
