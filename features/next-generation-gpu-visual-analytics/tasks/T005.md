### T005 - Add Visual Field Catalog And Lichess Profile Hints

#### Objective

Describe retained local columns as deterministic numeric or categorical visual
fields and enrich dataset profiles with optional, human-reviewed suggestions.
This gives later filters and projections real metadata without turning profiles
into ETL recipes or UI code.

#### Scope

- Create `crates/rawscope-data/src/visual_field_catalog.rs`.
- Build a catalog from `LoadedSourceTable` schema and row-aligned string values.
- Record numeric ranges/missing counts and bounded categorical dictionaries with
  deterministic counts/order and explicit truncation.
- Extend `DatasetProfile` with optional visual hints for filters, equality
  guides, and mean/difference projection availability.
- Add Lichess hints for `winner`, `event`, `opening`, `eco`, `time_control`,
  `termination`, `category`, and `weekday` when those columns are present.
- Keep only the four existing Lichess required columns required; optional hints
  must not make the compact profile contract fail.
- Export narrow catalog/profile types from `rawscope-data/src/lib.rs`.

#### Out Of Scope

- No filtering or row mask; T006 owns evaluation.
- No UI controls; T008 consumes the catalog.
- No data download, schema rewrite, conversion script, or committed large
  dataset.
- No serde and no render/workbench dependency in `rawscope-data`.
- No automatic semantic inference from arbitrary column names beyond schema
  kind; profile hints remain human reviewed.

#### Blocked By

None.

#### Why It Is Blocked

This is a pure data contract over existing retained rows and can run in

#### Implementation Details

Add data-owned field contracts:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum VisualFieldSummary {
    Numeric(NumericFieldSummary),
    Categorical(CategoricalFieldSummary),
    Empty { missing_count: usize },
}

#[derive(Debug, Clone, PartialEq)]
pub struct NumericFieldSummary {
    pub min: f64,
    pub max: f64,
    pub valid_count: usize,
    pub missing_count: usize,
    pub invalid_count: usize,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CategoryValueCount {
    pub value: String,
    pub count: usize,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CategoricalFieldSummary {
    pub values: Vec<CategoryValueCount>,
    pub distinct_count: usize,
    pub missing_count: usize,
    pub truncated: bool,
}

#[derive(Debug, Clone, PartialEq)]
pub struct VisualFieldDescriptor {
    pub column_name: String,
    pub column_index: usize,
    pub source_kind: LoadedColumnKind,
    pub summary: VisualFieldSummary,
}

#[derive(Debug, Clone, PartialEq)]
pub struct VisualFieldCatalog {
    pub row_count: usize,
    pub fields: Vec<VisualFieldDescriptor>,
}
```

Construction API:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct VisualFieldCatalogConfig {
    pub max_category_values: usize,
}

impl Default for VisualFieldCatalogConfig {
    fn default() -> Self {
        Self { max_category_values: 4_096 }
    }
}

pub fn build_visual_field_catalog(
    source: &LoadedSourceTable,
    config: VisualFieldCatalogConfig,
) -> VisualFieldCatalog;
```

Rules:

- Empty/whitespace-only values are missing.
- Integer/float schema columns parse as `f64`; parse failures increment
  `invalid_count` and never silently become zero.
- Categorical values preserve exact source strings after trimming outer
  whitespace only.
- Sort categories by descending count, then ascending value for ties.
- `distinct_count` is the true count. Retain at most
  `max_category_values`; `truncated` discloses omission.
- A zero `max_category_values` returns no values but still reports distinct and
  missing counts.

Add profile hints:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DatasetProfileFilterKind {
    NumericRange,
    Categorical,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct DatasetProfileFilterHint {
    pub column_name: &'static str,
    pub kind: DatasetProfileFilterKind,
    pub priority: u8,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct ScatterDatasetProfileHints {
    pub show_equality_guide: bool,
    pub supports_mean_difference: bool,
    pub filter_columns: &'static [DatasetProfileFilterHint],
}
```

Add `scatter_hints: ScatterDatasetProfileHints` to `DatasetProfile`. This is an
in-memory Rust contract, not serde; update every profile literal explicitly.

Lichess priorities:

1. `winner`
2. `category`
3. `time_control`
4. `termination`
5. `event`
6. `weekday`
7. `eco`
8. `opening`

Every hint is optional at runtime. A helper returns only hints whose column and
kind exist in the loaded catalog:

```rust
pub fn available_profile_filter_hints<'a>(
    profile: &'a DatasetProfile,
    catalog: &'a VisualFieldCatalog,
) -> Vec<DatasetProfileFilterHint>;
```

#### Migration Notes

- Update the single current profile literal and tests; no serialized migration.
- Existing validation still checks required columns only.
- Keep `LoadedSourceTable` unchanged; derive catalog data from it.
- Synthetic datasets may have no field catalog until a real source table exists.

#### Misinterpretations To Prevent

- Wrong interpretation: make every suggested Lichess field required.
  Correct rule: hints are optional and filtered against actual schema.
- Wrong interpretation: infer winner/opening semantics from arbitrary names.
  Correct rule: only the human-reviewed profile provides semantic priority.
- Wrong interpretation: truncate without disclosure.
  Correct rule: always report `distinct_count` and `truncated`.
- Wrong interpretation: add serde for future evidence.
  Correct rule: T015 owns render-side serialization DTOs.

#### Invariants

- Catalog row count equals retained source row count.
- Column indices preserve source schema order.
- Numeric parse failures are counted explicitly.
- Category order is deterministic.
- Profile validation behavior is unchanged.
- Missing optional hints never reject the dataset.
- `rawscope-data` gains no UI/render/serde dependency.

## Final Notes

- Recommended implementation order: catalog math, deterministic tests, profile
  hint types, Lichess constants, availability helper.
- Unresolved questions: human review may reorder Lichess optional fields.
- Risks: high-cardinality memory use and numeric schema inference drift.
- Human review: opening/eco ordering and whether `site` is useful enough to show.
- Completion: implemented on `codex/t005-field-catalog-profile-hints`; retained
  source rows now produce deterministic numeric, categorical, and empty field
  descriptors without changing loader contracts.
- Architectural decisions: used data-owned in-memory types with no serde,
  preserved true category cardinality before bounded retention, and kept all
  Lichess optional semantics in the human-reviewed profile.
- Validation: five named behavior tests, all 30 `rawscope-data` tests,
  `cargo fmt --all --check`, and `cargo check --workspace` passed.
- Not run: the external 200,000-game catalog was not materialized; T016 owns
  flagship dataset workflow review.
- Remaining risk: category construction must observe every distinct value to
  report truthful cardinality, so T008 should retain the catalog rather than
  rebuilding it during interaction.
