### T013 - Add GPU Relief Field Presentation

#### Objective

Add a richer top-down relief presentation that makes density structure feel
dimensional through multiscale normals, bounded horizon shading, and contours
without changing bin values or breaking one-to-one screen/data hit-testing.

#### Scope

- Extend `ScatterDensityPresentation` with `ReliefField`.
- Add `crates/rawscope-render/src/scatter_relief.rs` for configuration,
  validation, labels, and CPU-reference helper math where practical.
- Extend the scatter render shader or add a focused relief fragment shader with
  multiscale gradient normals, directional lighting, bounded ambient/horizon
  shading, and contour contribution.
- Keep UV/data mapping top-down and identical to Cells/Topographic modes.
- Add bounded height-strength and light-azimuth controls plus curated defaults.
- Expose exact density transform, palette, normalization, and relief parameters
  in the inspector.
- Keep brush, inspection, point reveal, and axes aligned to the same T001 plot.
- Ensure the mode degrades safely at tiny grids and plot sizes.

#### Out Of Scope

- No perspective/oblique camera, free orbit, 3D mesh, depth-buffer scene,
  parallax that changes hit-testing, ray casting, or decorative animation.
- No physically based renderer, environment map, texture asset, or generic
  lighting framework.
- No signed difference-field relief in this task unless its zero-centered
  semantics are independently tested; this task makes Relief unavailable while
  `ScatterDensityMode::FilteredDifference` is active.
- No evidence serialization; T015 records final relief config.

#### Blocked By

T002 and T007.

#### Why It Is Blocked

Relief must be clipped/aligned to solved plot/axes and consume resident density
resources without reintroducing pointer-time readback.

#### Implementation Details

Add render-owned config:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ReliefFieldConfig {
    pub height_strength: f32,
    pub normal_radius_bins: u32,
    pub light_azimuth_degrees: f32,
    pub light_elevation_degrees: f32,
    pub ambient_strength: f32,
    pub shadow_strength: f32,
    pub contour_strength: f32,
}

impl Default for ReliefFieldConfig {
    fn default() -> Self {
        Self {
            height_strength: 1.0,
            normal_radius_bins: 2,
            light_azimuth_degrees: 315.0,
            light_elevation_degrees: 48.0,
            ambient_strength: 0.42,
            shadow_strength: 0.28,
            contour_strength: 0.32,
        }
    }
}

pub fn validate_relief_field_config(
    config: ReliefFieldConfig,
) -> Result<ReliefFieldConfig, ReliefFieldConfigError>;
```

Validation bounds are named constants in `scatter_relief.rs`, not anonymous UI
numbers. Suggested first bounds:

- height strength `0.25..=2.5`;
- normal radius `1..=4` bins;
- azimuth normalized to `0..360`;
- elevation `20..=80` degrees;
- ambient/shadow/contour `0..=1`.

Only height strength and azimuth are exposed in the normal inspector. Other
values use curated defaults and live in an Advanced disclosure under Visual
Encoding. Reset returns exact defaults.

Shader requirements:

1. Use the same transformed scalar density as topographic color mapping.
2. Estimate fine and coarse gradients with bounded neighboring samples.
3. Combine them into a normalized screen-space normal.
4. Calculate one directional diffuse term plus ambient.
5. Approximate horizon shadow along the light direction with exactly eight
   compile-time-bounded samples; early-out where safe.
6. Add restrained contour darkening/brightening without changing scalar color
   legend semantics.
7. Fade lighting toward empty/very-low-density regions to avoid embossed noise.
8. Clamp all output and guard zero max count/grid dimensions.

Do not displace UVs or geometry. A pointer over screen fraction `(u, v)` still
refers to the same data bin as Cells. The legend continues to encode density;
lighting is explicitly labeled `Relief shading` rather than a second measure.

Add config to `ScatterDensityRendererConfig` through a builder:

```rust
pub fn with_relief(mut self, relief: ReliefFieldConfig) -> Self;
```

Render params must remain 16-byte aligned and covered by a size/layout test.

#### Migration Notes

- Topographic remains default until T016 human curation.
- Relief is selectable only in AbsoluteDensity. Switching to difference keeps
  the saved relief config/presentation but uses the dedicated signed field.
- Existing enum serialization in v3 must preserve exact old variant labels and
  behavior. Adding a variant must not change old outputs for old values.
- Existing Cells/Topographic shader branches remain numerically unchanged.
- T015 serializes relief config only for v4.

#### Misinterpretations To Prevent

- Wrong interpretation: build a free-camera 3D terrain.
  Correct rule: top-down screen-aligned relief with exact hit mapping.
- Wrong interpretation: alter density values to make hills dramatic.
  Correct rule: lighting shades the same transformed density scalar.
- Wrong interpretation: expose every shader coefficient.
  Correct rule: two normal controls, curated rest.
- Wrong interpretation: make relief the default immediately.
  Correct rule: T016 human review decides.

#### Invariants

- Cells/Topographic outputs remain unchanged.
- Relief uses identical bins, transform, palette, and normalization.
- Screen/data UV mapping is one-to-one and unchanged.
- Sample loop bounds are compile-time and small.
- Empty fields render stable background without NaN or light artifacts.
- Brush/probe/point overlays remain aligned.
- Relief cannot be active in FilteredDifference mode.

- Completion: implemented on `codex/t013-gpu-relief-field`; Absolute density now
  offers a data-aligned Relief surface with multiscale normals, directional
  light, eight bounded horizon samples, restrained contours, and live bounded
  tuning. Cells and Topographic retain their existing shader IDs and behavior.
- Files changed: render relief contract/config, presentation, renderer params,
  render resources, WGSL, and facade; workbench visual-encoding state/actions,
  render scheduling, UI wiring/tests, and the focused `ui_relief` owner; task
  index and this handoff.

  the workbench only coordinates validated state and controls. Relief consumes
  the existing resident density buffers, preserves source/display UV mapping,

  `cargo check --workspace`, and all nine ignored scatter GPU adapter tests
  passed. Native review rendered 200,000 Lichess rows on AMD Radeon RX 7800 XT
  with Vulkan and verified distinct relief output, aligned axes/guides, and
  live height tuning.

  was added or run; visual behavior was reviewed directly in the native app.
- Remaining risk: eight horizon samples add fixed fragment cost, and final
  default/palette curation remains intentionally assigned to T016.
