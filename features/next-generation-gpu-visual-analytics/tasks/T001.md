### T001 - Add Authoritative Plot Geometry And GPU Scissoring

#### Objective

Make one physical plot rectangle authoritative for density drawing, axes,
input, brushes, and overlays. Replace full-window normalization and fixed UI
guard guesses with a testable geometry contract while splitting plot behavior
out of oversized workbench owners.

#### Scope

- Create `crates/rawscope-render/src/plot_geometry.rs` with checked physical
  plot geometry and screen/data fraction helpers.
- Export the geometry contract through `crates/rawscope-render/src/lib.rs`.
- Create `apps/rawscope-workbench/src/ui_plot_surface.rs` to allocate the egui
  central plot and convert its logical rectangle to physical pixels.
- Create `apps/rawscope-workbench/src/app_plot_interaction.rs` and move scatter
  cursor-fraction, pan, zoom, and reset coordination out of `app.rs`.
- Store the latest valid plot rectangle in `WorkbenchApp`.
- Pass the plot rectangle to scatter/timeline density renderers and the brush
  overlay renderer; call WGPU `set_viewport` and `set_scissor_rect` before draw.
- Translate cursor positions into plot-local fractions for pan, zoom, brush,
  and hover routing. Ignore starts outside the plot, but always finalize an
  already-active gesture on release.
- Keep the swapchain clear full-window so UI chrome has a stable background.

#### Out Of Scope

- No axis tick redesign; T002 owns ticks, grid lines, and reference guides.
- No visual restyling; T003 owns chrome and identity.
- No new interaction modes; T004 owns Pan/Brush/Inspect state.
- No GPU resource-lifetime rewrite; T007 owns resident buffers/readback policy.
- No perspective, camera, point-reveal, filter, or evidence changes.

#### Blocked By

None.

#### Why It Is Blocked

This is the coordinate-system foundation and can start immediately. Every later
visual and interaction task depends on its physical plot contract.

#### Implementation Details

Create the render-owned pixel geometry without egui or winit dependencies:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PlotRectPx {
    pub x: u32,
    pub y: u32,
    pub width: u32,
    pub height: u32,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct PlotPointPx {
    pub x: f32,
    pub y: f32,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum PlotGeometryError {
    ZeroWidth,
    ZeroHeight,
    OutsideSurface,
}
```

Required methods:

```rust
impl PlotRectPx {
    pub fn try_new(
        x: u32,
        y: u32,
        width: u32,
        height: u32,
        surface_width: u32,
        surface_height: u32,
    ) -> Result<Self, PlotGeometryError>;

    pub fn contains(self, point: PlotPointPx) -> bool;
    pub fn fraction_at(self, point: PlotPointPx) -> Option<(f32, f32)>;
    pub fn local_point(self, point: PlotPointPx) -> Option<BrushScreenPoint>;
    pub fn screen_size(self) -> BrushScreenSize;
}
```

Fractions are `0.0..=1.0`, with y increasing downward. Right/bottom edges must
map deterministically and never produce a fraction above one.

Create app-only layout output:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub(crate) struct PlotSurfaceLayout {
    pub(crate) logical_rect: egui::Rect,
    pub(crate) physical_rect: rawscope_render::PlotRectPx,
}

pub(crate) struct WorkbenchUiOutput {
    pub(crate) actions: UiActions,
    pub(crate) plot_surface: Option<PlotSurfaceLayout>,
}
```

`show_workbench_ui()` must allocate an unframed central region after top,
right, and bottom panels. Convert logical points using the current
`pixels_per_point`, clamp to the surface extent, and return `None` for a zero
area. `WorkbenchApp::render()` stores the layout before applying actions.

Change renderer methods to accept the physical rectangle:

```rust
pub fn render(
    &self,
    encoder: &mut wgpu::CommandEncoder,
    target_view: &wgpu::TextureView,
    plot_rect: PlotRectPx,
);
```

Inside each density/overlay render pass:

```rust
render_pass.set_viewport(
    plot_rect.x as f32,
    plot_rect.y as f32,
    plot_rect.width as f32,
    plot_rect.height as f32,
    0.0,
    1.0,
);
render_pass.set_scissor_rect(
    plot_rect.x,
    plot_rect.y,
    plot_rect.width,
    plot_rect.height,
);
```

Brush screen coordinates become plot-local. Finalized selections remain data
anchored. Reprojection must add plot origin only at the WGPU/egui overlay
boundary; do not store absolute window coordinates in finalized selection.

Move scatter plot-input methods from `app.rs` into
`app_plot_interaction.rs`. Use plot width/height for pan deltas, preserving the
current accepted signs exactly:

```rust
let data_delta_x = -delta_x_fraction * viewport.x_range().span();
let data_delta_y = -delta_y_fraction * viewport.y_range().span();
```

Timeline interaction should adopt the same plot-local x normalization without
changing lane semantics.

#### Before / After

**Before:**

```rust
let window_size = window.inner_size();
let delta_x_fraction = delta_x / window_size.width as f32;
scatter_density_renderer.render(encoder, target_view);
```

**After:**

```rust
let plot_rect = self.plot_surface?.physical_rect;
let delta_x_fraction = delta_x / plot_rect.width as f32;
scatter_density_renderer.render(encoder, target_view, plot_rect);
```

#### Migration Notes

- Renderer `render` signatures change inside the workspace; update every call
  in the same task.
- No serialized artifact or public crate version migration is required.
- Existing brush selections must remain valid across resize and panel collapse.
- Remove fixed axis guard constants only after T002 consumes plot layout; until
  then, adapt the current overlay to the returned logical rectangle.

#### Misinterpretations To Prevent

- Wrong interpretation: draw density into an egui image texture.
  Correct rule: keep native WGPU rendering and use viewport/scissor on the
  swapchain render pass.
- Wrong interpretation: maintain separate rectangles for axes and input.
  Correct rule: one plot allocation produces both logical and physical views.
- Wrong interpretation: clamp active drags when the cursor leaves the plot.
  Correct rule: starts must be inside; active gestures continue and finalize.
- Wrong interpretation: reverse pan signs while normalizing.
  Correct rule: preserve the user-approved x/y behavior.

#### Invariants

- Plot width and height are non-zero before rendering or input conversion.
- Every density pixel and brush overlay is clipped to the same plot rectangle.
- A point at the logical plot center maps to approximately `(0.5, 0.5)`.
- UI panel width changes immediately update render, axes, and interaction.
- Finalized brush ranges remain data anchored after resize.
- `app.rs` becomes smaller; new plot methods do not remain duplicated there.
