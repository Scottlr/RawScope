### T014 - Add Refined Visual Transitions And Reduced Motion

#### Objective

Make settled filter, projection, and visual-mode changes feel coherent through
short GPU-side interpolation while keeping pan/zoom immediate and providing a
strict reduced-motion path.

#### Scope

- Create `crates/rawscope-render/src/visual_transition.rs` with bounded config
  and pure progress/easing functions.
- Retain previous/current density resources long enough to blend settled state
  changes without recomputing old data.
- Add transition parameters to relevant scatter render paths.
- Create `apps/rawscope-workbench/src/app_visual_transition.rs` for transition
  lifecycle and frame requests.
- Add a reduced-motion preference to workbench settings/state. Default false
  and expose a concise toggle in settings. A later task may initialize it from
  a platform preference only when a stable API is already available.
- Transition filter, projection, Absolute/Difference, and
  Topographic/Relief/Cells settled changes where semantically valid.
- Do not animate pointer-time pan/brush feedback or selection truth.

#### Out Of Scope

- No decorative idle animation, pulsing, particle effects, camera motion,
  spring physics, animation timeline editor, or continuous repaint when idle.
- No interpolation between semantically incompatible signed/sequential palettes
  unless both fields are separately blended with explicit mode crossfade.
- No evidence serialization of progress or wall-clock timestamps.

#### Why It Is Blocked

Transition ownership must cover the final density, point-reveal, difference,
relief, and interactive preview/exact lifecycle rather than being rewritten for

#### Implementation Details

Add render config:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct VisualTransitionConfig {
    pub duration_ms: u32,
    pub reduced_motion: bool,
}

impl Default for VisualTransitionConfig {
    fn default() -> Self {
        Self { duration_ms: 180, reduced_motion: false }
    }
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TransitionKind {
    DensityRefresh,
    ProjectionChange,
    PresentationChange,
    DifferenceModeChange,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct TransitionProgress(pub f32);
```

Functions:

```rust
pub fn validate_transition_config(
    config: VisualTransitionConfig,
) -> Result<VisualTransitionConfig, VisualTransitionConfigError>;

pub fn transition_progress(
    elapsed_ms: u64,
    config: VisualTransitionConfig,
) -> TransitionProgress;

pub fn ease_out_cubic(progress: TransitionProgress) -> f32;
```

Bound duration to `0..=500` ms. Reduced motion or zero duration returns progress
one immediately. Progress is finite and clamped.

App state:

```rust
pub(crate) enum WorkbenchTransitionState {
    Idle,
    Running {
        kind: TransitionKind,
        started_at: std::time::Instant,
        from_revision: u64,
        to_revision: u64,
    },
}
```

When a settled state change begins, retain old and new render resources or
count buffers. The shader crossfades transformed scalar/color outputs. For
Absolute to Difference, render each semantic field independently then blend
final color; never interpolate raw count and signed delta values as if they
shared units. For point reveal, reuse its analytical LOD blend and multiply by
transition alpha only.

During active pan/brush:

- cancel/complete any decorative transition;
- show latest interactive density immediately;
- keep brush/probe overlays immediate;
- start a new short density refresh only after settled update if enabled.

Request redraw only while a transition is running. Drop previous resources and
return to Idle at progress one. Dataset replacement cancels and drops both
safely.

Reduced-motion UI lives in a small settings menu; it is not another persistent
right-rail control. The setting applies immediately and completes any running
transition.

#### Before / After

**Before:**

```text
Filter/mode changes replace the density field in one frame.
```

**After:**

```text
Settled changes crossfade over <=180 ms; pan/brush and reduced motion remain immediate.
```

#### Migration Notes

- Existing behavior is exactly the reduced-motion/zero-duration path.
- No evidence or report migration.
- Avoid storing `Instant` in serializable/UI projection types.
- Preserve idle event-loop behavior; no continuous redraw after completion.

#### Misinterpretations To Prevent

- Wrong interpretation: animate every pointer move.
  Correct rule: interaction remains immediate; only settled changes transition.
- Wrong interpretation: interpolate incompatible numeric fields.
  Correct rule: crossfade final colors for semantic mode changes.
- Wrong interpretation: run a permanent animation loop.
  Correct rule: request frames only while running.
- Wrong interpretation: ignore reduced motion because this is a desktop tool.
  Correct rule: immediate bypass is mandatory.

#### Invariants

- Reduced motion produces immediate final output.
- Transition progress is finite, monotonic, and ends at one.
- Old resources remain valid until the final blended frame, then release.
- Interaction/selection/filter truth uses current state, never interpolated state.
- Idle app requests no animation frames.
- Evidence never contains progress or previous revision.

#### Acceptance Criteria

- [x] Settled density/mode changes transition within bounded duration.
- [x] Pan/brush feedback is immediate and cancels stale transitions.
- [x] Reduced motion bypasses every transition.
- [x] Absolute/Difference transitions blend colors, not incompatible values.
- [x] Previous GPU resources release after completion/dataset replacement.
- [x] Idle state does not continuously repaint.
- [x] Focused tests, formatting, and workspace check pass.

## Final Notes

- Recommended implementation order: pure timing, app lifecycle, density
  refresh blend, presentation blend, difference blend, point overlay, setting.
- Unresolved questions: automatic OS reduced-motion detection is deferred.
- Risks: resource lifetime leaks and unnecessary idle redraw.
- Human review: duration, interruption behavior, and reduced-motion parity.
- Completion: implemented on `codex/t014-visual-transitions`; settled density,
  projection, presentation, relief, and semantic mode changes now use a bounded
  180 ms GPU transition. Pan/brush cancels motion immediately, and Settings has
  an immediate reduced-motion bypass.
- Files changed: render timing contract/facade, scatter density resource layout,
  shader and renderer, difference and point render composition, shared pipeline
  plumbing; workbench transition lifecycle, render scheduling/composition,
  interaction and mode triggers, settings projection/actions/UI; task index and
  this handoff.
- Architectural decisions: render owns bounded progress/easing and GPU color
  composition. Workbench owns `Instant`, revisions, cancellation, reduced-motion
  preference, and redraw lifecycle. Same-semantic transitions sample the two
  existing resident count buffers; Absolute/Difference draws each final color
  field independently and blends only those colors. Timeline remains unchanged.
- Validation: 56 render unit tests plus integrations, 92 workbench tests, all
  nine ignored scatter GPU adapter tests, `cargo fmt --all --check`, and
  `cargo check --workspace` passed. Native review on AMD Radeon RX 7800 XT with
  Vulkan and 200,000 Lichess rows verified filter settling, semantic mode
  composition, palette fidelity, the settings toggle, and immediate bypass.
- Not run: no screenshot/window/startup test, video test, benchmark, automatic
  OS preference detection, or public timing claim was added or run.
- Remaining risk: the 180 ms duration is curated by feel rather than a formal
  usability study. The double-buffer allocation remains resident for later
  compute updates, while the completed revision is no longer sampled.
