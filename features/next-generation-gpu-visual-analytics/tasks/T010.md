### T010 - Add Automatic Point Reveal Level Of Detail

#### Objective

Let sparse regions resolve into real row glyphs as the analyst zooms, while
keeping dense views aggregated. Draw a deterministic bounded subset when the
visible cohort exceeds the point budget and disclose that sampling truthfully.

#### Scope

- Create `crates/rawscope-render/src/scatter_point_reveal.rs` for LOD policy,
  deterministic visible-point selection, stats, and render configuration.
- Create `crates/rawscope-render/src/scatter_point_renderer.rs` plus a focused
  WGSL shader for instanced screen-space disc glyphs.
- Reuse T007 resident point data where practical without coupling private
  buffers unsafely.
- Respect T008 filter mask and T001 plot viewport/scissor.
- Use T009 inspection/nearest-row data for click/hover emphasis.
- Add Auto/Off point-reveal controls under visual encoding; Auto is default.
- Fade glyph opacity based on visible rows per plot pixel and preserve density
  underneath until the transition completes.
- Display exact eligible count, rendered count, and sampled status in the
  inspector/encoding summary.

#### Out Of Scope

- No all-rows marker mode for dense views, force-on escape hatch, arbitrary
  glyph shapes, per-row labels, size mapping, or category legend system.
- No CPU one-widget-per-point rendering.
- No evidence v4; T015 records reveal config/stats.
- No transition timing beyond a static LOD blend; T014 owns refined motion.

#### Blocked By

T008 and T009.

#### Why It Is Blocked

Point membership must use the active mask and truthful inspection mapping
before glyphs can be selected or clicked.

#### Implementation Details

Add render-owned policy:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum PointRevealMode {
    Off,
    #[default]
    Auto,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct PointRevealConfig {
    pub mode: PointRevealMode,
    pub max_rendered_points: usize,
    pub fully_visible_rows_per_pixel: f32,
    pub hidden_rows_per_pixel: f32,
    pub radius_px: f32,
}

impl Default for PointRevealConfig {
    fn default() -> Self {
        Self {
            mode: PointRevealMode::Auto,
            max_rendered_points: 50_000,
            fully_visible_rows_per_pixel: 0.03,
            hidden_rows_per_pixel: 0.25,
            radius_px: 2.0,
        }
    }
}

#[derive(Debug, Clone, PartialEq)]
pub struct PointRevealSelection {
    pub point_indices: Vec<u32>,
    pub eligible_count: usize,
    pub blend: f32,
    pub sampled: bool,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct PointRevealStats {
    pub eligible_count: usize,
    pub rendered_count: usize,
    pub sampled: bool,
    pub blend: f32,
}
```

Builder:

```rust
pub fn select_points_for_reveal(
    points: &[ScatterPointRecord],
    mask: &FilterMask,
    x_range: F32Range,
    y_range: F32Range,
    plot_width_px: u32,
    plot_height_px: u32,
    config: PointRevealConfig,
) -> Result<PointRevealSelection, PointRevealError>;
```

Count eligible masked points in the viewport. Rows-per-pixel is
`eligible_count / (plot_width * plot_height)`. Blend is one below the fully
visible threshold, zero at/above hidden threshold, and linearly interpolated
between. Off always returns blend zero and no selected indices.

If eligible count exceeds budget, choose the lowest `(priority, row_id)` pairs,
where `priority` is SplitMix64 applied to `row_id.0` with the standard fixed
constants below. Sort selected point indices back into ascending row-id order
before upload. Do not choose `take(max)` because viewport order can create
spatial bias. Sample selection is recomputed only after settled
viewport/filter revisions.

```rust
fn point_reveal_priority(row_id: RowId) -> u64 {
    let mut value = row_id.0.wrapping_add(0x9E37_79B9_7F4A_7C15);
    value = (value ^ (value >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
    value = (value ^ (value >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
    value ^ (value >> 31)
}
```

GPU renderer:

- Upload selected point indices or compact reveal vertices after settled
  selection.
- Render one instanced quad per glyph; fragment shader discards outside a disc.
- Radius is screen-space and clamped to a bounded range.
- Use a restrained light glyph with outline/alpha that remains visible on all
  density palettes.
- A hovered/pinned row receives a separate accent state; do not recolor all
  points by arbitrary categories.
- Clip through T001 plot viewport/scissor.

Add visual controls:

- segmented/toggle `Points: Auto | Off`;
- rendered/eligible summary;
- sampled badge only when true;
- no raw threshold sliders in the main inspector.

#### Migration Notes

- Keep `ScatterDensityPresentation` focused on density surfaces; point reveal
  is an overlay mode, not a replacement enum variant.
- Existing density/brush/evidence behavior remains when mode is Off or blend 0.
- No serialized change until T015.
- Record any default threshold changes after native Lichess review.

#### Misinterpretations To Prevent

- Wrong interpretation: always draw 200,000 markers because GPU can.
  Correct rule: bounded LOD policy and density-first default.
- Wrong interpretation: call a deterministic sample all visible points.
  Correct rule: disclose eligible and rendered counts plus `sampled`.
- Wrong interpretation: render points through egui widgets.
  Correct rule: one instanced WGPU pipeline.
- Wrong interpretation: use point reveal as a second category chart.
  Correct rule: neutral row glyphs plus hover/pin accent only.

#### Invariants

- Rendered points are included by mask and inside visible ranges.
- Rendered count never exceeds configured budget.
- Sampling is stable for identical cohort/viewport/config.
- Point opacity falls as rows per pixel grows.
- Density remains visible until point blend reaches full.
- Point positions use the same plot/data transform as density and inspection.

#### Acceptance Criteria

- [ ] Auto reveal activates/deactivates at deterministic density thresholds.
- [ ] Large visible cohorts are sampled reproducibly and disclosed.
- [ ] Filtered-out/out-of-view rows never render.
- [ ] GPU glyphs align with inspection bins and axes.
- [ ] Hover/pin emphasizes the correct revealed row when present.
- [ ] Off reproduces density-only output/state.
- [ ] Focused tests, formatting, and workspace check pass.
