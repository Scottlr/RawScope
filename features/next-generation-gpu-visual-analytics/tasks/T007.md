### T007 - Add Resident GPU Density Resources

#### Objective

Make scatter density GPU resources dataset-resident. Upload points and create
pipelines once per dataset, reuse count/maximum buffers across view changes,
compute normalization maxima on GPU, and preserve explicit full-readback paths
for exact CPU/GPU agreement and settled analytical summaries.

#### Scope

- Split reusable scatter GPU resources out of
  `gpu_scatter_density.rs`/`scatter_density_renderer.rs` into focused modules.
- Keep point, count, maximum, parameter, pipeline, and bind-group resources
  resident across viewport and density-encoding updates.
- Add GPU-side maximum-bin reduction during density compute.
- Allow renderer updates to request no readback, maximum-only readback, or full
  count-grid readback explicitly.
- Retain the existing public correctness functions and ignored GPU tests.
- Preserve the current 256x256 exact grid and Cells reference behavior.
- Expose enough source/destination resource state for T017 to reproject and
  refine density without recreating dataset resources.

#### Out Of Scope

- No workbench gesture scheduler, frame cadence, density reprojection, or
  deferred marginal lifecycle; T017 owns those behaviors.
- No filter mask buffer; T008 adds it to these resources.
- No point reveal, dual comparison buffers, relief, or transitions.
- No background thread, async runtime, continuous busy loop, performance claim,
  or benchmark-only task.
- No timeline resource rewrite unless a shared helper is obviously safe; do not
  block scatter behavior on timeline parity.

#### Blocked By

T001.

#### Why It Is Blocked

The resident renderer needs the authoritative plot dimensions and viewport
contract before its update API and output resources are finalized.

#### Implementation Details

Create the focused render-owned module
`crates/rawscope-render/src/scatter_density_gpu_state.rs`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DensityReadbackPolicy {
    None,
    MaxOnly,
    FullCounts,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ScatterDensityUpdate {
    pub config: ScatterDensityRendererConfig,
    pub readback: DensityReadbackPolicy,
}

pub struct ScatterDensityGpuState {
    point_buffer: wgpu::Buffer,
    point_count: u32,
    count_buffers: [wgpu::Buffer; 2],
    max_count_buffer: wgpu::Buffer,
    compute_params_buffer: wgpu::Buffer,
    compute_bind_group_layout: wgpu::BindGroupLayout,
    compute_pipeline: wgpu::ComputePipeline,
    compute_bind_groups: Vec<wgpu::BindGroup>,
    active_count_buffer: usize,
    grid_width: u32,
    grid_height: u32,
    dataset_revision: u64,
}
```

The two count buffers allow a completed field to stay renderable while a new
field is computed. T017 owns when buffers swap; this task owns their validity,
capacity, and binding lifetime. T008 adds mask buffer/revision fields later.

Expose this behavior:

```rust
impl ScatterDensityGpuState {
    pub fn new(
        device: &wgpu::Device,
        queue: &wgpu::Queue,
        points: &[ScatterPointRecord],
        config: ScatterDensityRendererConfig,
        dataset_revision: u64,
    ) -> Result<Self, GpuScatterDensityError>;

    pub fn update(
        &mut self,
        device: &wgpu::Device,
        queue: &wgpu::Queue,
        update: ScatterDensityUpdate,
    ) -> Result<ScatterDensityRenderStats, GpuScatterDensityError>;
}
```

Point upload occurs in `new` or explicit dataset replacement only. Viewport and
encoding updates write uniform buffers and clear/reuse output buffers. Recreate
grid resources only when dimensions or capacity change.

Extend compute WGSL with one atomic maximum:

```wgsl
let previous = atomicAdd(&counts[bin_index], 1u);
atomicMax(&max_count[0], previous + 1u);
```

Use compute bindings `0=points`, `1=params`, `2=counts`, and
`3=max_count`. T008 reserves binding 4 for the row mask. Update the shared
helper only if timeline callers retain their existing three-binding layout;
otherwise create a scatter-specific layout rather than adding dummy timeline
buffers.

Clear the destination count and maximum buffers before dispatch. The render
shader reads the GPU maximum through a read-only storage binding or another
GPU-only path. Do not map the full count grid merely to set a CPU uniform.

Keep `ScatterDensityRenderStats.max_bin_count` as the last known readback value
for existing UI/evidence callers. Add runtime-only freshness disclosure and
update every constructor/test literal in this task:

```rust
pub struct ScatterDensityRenderStats {
    // Existing fields remain.
    pub max_bin_count_is_current: bool,
}
```

`DensityReadbackPolicy::None` leaves the last CPU value explicitly stale while
the GPU render path uses the current device-side maximum. `MaxOnly` copies one
maximum value. `FullCounts` maps the exact grid and is reserved for correctness
tests or settled analytical cache construction.

The public correctness function `gpu_scatter_density*()` may construct a
temporary resident state and request `FullCounts`; its behavior and tests
remain unchanged.

#### Migration Notes

- Preserve `gpu_scatter_density()` and the existing CPU/GPU correctness
  contract.
- Renderer construction may absorb resident state; update direct render-crate
  constructors and tests in one slice.
- Avoid changing serialized evidence. Stats freshness is runtime-only.
- T017 consumes the double-buffered update API and adds interaction scheduling;
  do not add a second renderer resource owner there.
- T008 extends the bind group with a mask. Leave a clear binding slot or
  constructor path, but do not add an unused fake mask now.

#### Misinterpretations To Prevent

- Wrong interpretation: cache only the render pipeline while reuploading
  points and recreating output buffers on every view change.
  Correct rule: point/count/max resources and pipelines are dataset-resident.
- Wrong interpretation: remove readback correctness paths because normal
  rendering no longer needs them.
  Correct rule: preserve explicit full-readback paths for tests and settled
  analytical caches.
- Wrong interpretation: add event coalescing to this renderer task.
  Correct rule: expose resource-safe updates here; T017 owns event/frame policy.
- Wrong interpretation: add a benchmark-only harness and call it product work.
  Correct rule: the reusable resource lifetime must be used by the real
  renderer.

#### Invariants

- Dataset replacement uploads one point buffer per replacement revision.
- Viewport movement reuses point/pipeline/grid resources when dimensions match.
- A no-readback update performs no full-grid synchronous mapping.
- The currently displayed count buffer remains valid while its replacement is
  computed.
- GPU density counts and maximum remain equal to the CPU reference.
- No workbench interaction or evidence state is owned by this module.
