### T011 - Add Mean Difference Scatter Projection

#### Objective

Add a second truthful coordinate view for paired numeric fields: mean value on
x and signed difference on y. For Lichess this exposes overall player strength
versus white-minus-black rating imbalance while preserving every row id.

#### Scope

- Create `crates/rawscope-data/src/scatter_projection.rs` with projection enum,
  transformation, ranges, labels, and recoverable errors.
- Support `RawXY` and `MeanDifference` only.
- Rebuild projected visual points from the same loaded source binding without
  losing row ids or source rows.
- Add projection state/coordination in a focused workbench module.
- Add a compact projection option to visual controls when T005 profile/catalog
  says both fields are numeric.
- Recompute viewport, density, filters, marginals, inspection, point reveal,
  and selection state consistently on projection change.
- Use T002 equality guide in RawXY when requested; use y=0 guide in
  MeanDifference.

#### Out Of Scope

- No PCA, regression residuals, arbitrary formulas, expression editor,
  log-coordinate projection, or more chart types.
- No changes to source filters; predicates remain on original columns.
- No automatic projection based solely on column names.
- No v4 serialization; T015 records the chosen projection.

#### Blocked By

T002, T005, and T008.

#### Why It Is Blocked

Projection needs refined axis/guide behavior, profile/catalog eligibility, and
filter-consistent density integration.

#### Implementation Details

Add data-owned projection contracts:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum ScatterProjection {
    #[default]
    RawXY,
    MeanDifference,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ScatterProjectionLabels {
    pub x_label: String,
    pub y_label: String,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ProjectedScatterData {
    pub projection: ScatterProjection,
    pub labels: ScatterProjectionLabels,
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub points: Vec<ScatterPointRecord>,
}
```

Function:

```rust
pub fn project_scatter_points(
    points: &[ScatterPointRecord],
    x_column: &str,
    y_column: &str,
    projection: ScatterProjection,
) -> Result<ProjectedScatterData, ScatterProjectionError>;
```

Math for each finite point `(x, y)`:

```text
RawXY:          u = x,           v = y
MeanDifference: u = (x + y) / 2, v = x - y
```

Use overflow-resistant intermediate `f64` for mean/difference and convert to
finite f32 with a contextual error if out of range. Preserve `row_id` and
`kind` unchanged and preserve point order.

Labels:

```text
RawXY:          x_column, y_column
MeanDifference: mean(x_column, y_column), x_column - y_column
```

Ranges use the same expanded-bounds helper as loaded scatter data; do not use
hard-coded rating bounds.

Workbench state stores both immutable raw points and current projected points
without cloning on every frame. On projection change:

1. build/project once;
2. reset viewport to projected full ranges;
3. clear brush and pinned inspection;
4. retain source filter predicates/mask because row ids are unchanged;
5. schedule final density/marginal/inspection/point-reveal rebuild;
6. update axes/guides.

Add `Projection: Raw | Mean/Difference` segmented control only when both bound
fields are numeric. T005 Lichess profile orders Mean/Difference as the suggested
secondary mode, never the automatic default.

#### Before / After

**Before:**

```text
x = white_rating, y = black_rating
```

**After alternative:**

```text
x = mean(white_rating, black_rating)
y = white_rating - black_rating
guide = y = 0
```

#### Migration Notes

- RawXY is default and reproduces existing points/ranges.
- Filters remain source-column predicates and keep their revision.
- Selections/pins clear because their data-space ranges belong to the old
  projection.
- No evidence shape changes until T015.

#### Misinterpretations To Prevent

- Wrong interpretation: calculate a statistical regression residual.
  Correct rule: exact paired mean and signed x-minus-y difference only.
- Wrong interpretation: mutate source rows or field bindings.
  Correct rule: derive visual coordinates and preserve source identity.
- Wrong interpretation: apply filters to projected labels.
  Correct rule: filters retain original source columns.
- Wrong interpretation: default every dataset to MeanDifference.
  Correct rule: profile-supported secondary option; RawXY remains default.

#### Invariants

- Row id, point order, source row, and filter-mask index are unchanged.
- Mean/difference math is finite and deterministic.
- RawXY output matches input coordinates.
- Projection switch resets viewport and clears data-space selections/pins.
- Equality guide appears only in raw paired view; zero guide only in difference.
- Density/inspection/point reveal all consume the same projected points.
