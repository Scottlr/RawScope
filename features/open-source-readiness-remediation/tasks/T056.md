### T056 — Add Protected Publishing And Rollback

#### Objective

Enable only the explicitly approved Rust/Python/native publication matrix behind
protected human approval, least-scope credentials, ordered ecosystem mutation,
and a concrete partial-failure/yank/rollback runbook.

#### Scope

- Primary audit finding: RS-010 (publication/rollback completion).
- Change `publish = false` only for human-approved public packages; leave internal
  crates/app private and record the resulting API commitment.
- Add protected release-environment approval after T035/T055 verification.
- Use approved trusted publisher/OIDC or least-scope credentials isolated to
  ecosystem-specific publish jobs.
- Define immutable tag/version checks, publication order, no duplicate retries,
  release notes/changelog/schema/support statement, and post-publish verification.
- Define/approve response when one ecosystem succeeds and another fails: stop,
  notify, yank/withdraw where permitted, corrective version, artifact retention.

#### Out of Scope

- Do not execute a real release while implementing this workflow.
- Do not use `cargo publish --dry-run`; T035 package inspection is the gate.
- Do not publish every crate by default, overwrite versions/tags, add auto-update,
  or claim global atomicity across registries.
- Do not configure credentials/environments without explicit authority.

#### Blocked By

T004, T035, T055.

#### Why It Is Blocked

Governance, inspected artifacts, and verified supply-chain metadata must be final
before any publication-capable job exists.

#### Related Code

- T001 private publication matrix, T004 release policy/roles/changelog.
- T035 artifact manifest/checksums and T055 verified metadata.
- Final Cargo/Python manifests and supported platform/schema docs.

#### Implementation Touchpoints

- Read first: human-approved package/platform matrix, registry official publisher/
  yanking rules, protected environment/credentials, version/tag/changelog.
- Edit first: publication intent manifests after approval, protected workflow jobs,
  runbook/release notes template.
- Symbols to search: `publish = false`, package versions, registry tokens/OIDC,
  environment reviewers, tags, yank/withdraw.
- Required structural changes: build/inspect/metadata artifacts flow unchanged into
  one approval gate then separate ordered publish jobs.
- Do not edit: product behavior/artifact bytes/benchmark claims.
- Verify in order: workflow control with no credentials/publication, manifest/
  approval/job dependency review, injected partial failure control, human review.
- Stop and ask: before any publish flag, secret/environment, tag/version, registry
  upload, release creation, or recovery mutation.

#### Implementation Details

Workflow checks the approved tag points at the inspected commit and artifact
manifest verifies. Protected approval unlocks only publish jobs. Each job consumes
prebuilt artifacts; it does not rebuild. Publication order is documented based on
dependency graph (Rust libraries before dependent package if approved; Python/
native release order explicit) and stops on failure. Retries verify whether a
version already exists before acting and never overwrite.

Runbook names owner/contact, exact evidence to capture, when to yank/withdraw,
corrective release/version policy, and public communication. Rollback cannot erase
downloaded artifacts; wording is precise.

#### Before / After

Before: there is no protected publish/partial-failure path.

After: publication cannot occur without approved immutable artifacts, metadata,
matrix, and human authorization; failures have an owned response.

#### Migration Notes

- Enabling a crate is a public API support decision; T052 docs must match.
- Actual first release is a separate explicitly authorized operation.

#### Misinterpretations To Prevent

- Wrong: workflow implementation authorizes a release. Correct: no real publish.
- Wrong: make all crates public. Correct: approved matrix only.
- Wrong: call yank a rollback. Correct: downloaded artifacts remain; corrective
  guidance/version is required.

#### Invariants

- No build/PR job has publish credentials.
- Human approval gates every registry/release mutation.
- Published bytes equal inspected/attested manifest hashes.
- Versions/tags immutable and partial failure stops sequence.
- Recovery ownership/actions documented before first release.

#### Acceptance Criteria

- [ ] Approved publication matrix is explicit; all others remain private.
- [ ] Protected least-privilege publish jobs consume exact verified artifacts.
- [ ] Control-path/injected-failure review proves no unauthorized mutation.
- [ ] Version/tag/release notes/post-verify/partial-failure runbook is complete.
- [ ] Actual publication remains unexecuted pending explicit authorization.

#### Testing Guidance

- Test workflow dependencies/guards with non-publishing fixtures and injected job
  failure; never real credentials/registry writes.
- No dry-run publish command.

#### Agent Handoff Context

This is final gate. If any approval/prerequisite is absent, leave packages private
and report exact blocker.

## Final Notes

- Recommended order: matrix approval, environment/control, jobs, runbook, review.
- Human review mandatory for every external mutation detail.
- Risk: multi-registry releases are not atomic; ordering/recovery must be honest.
