### T040 — Make Current Report Bundle Writes Transactional

#### Objective

Fix current partial bundle publication and collision TOCTOU immediately with a
tested no-clobber staged transaction in the existing workbench owner.

#### Scope

- Primary audit findings: RS-101 and RS-102.
- Stage every current artifact in an exclusively created hidden sibling directory.
- Flush/sync according to supported-platform policy, write manifest last, and
  publish with a tested atomic no-replace directory operation.
- Retry bounded fresh names only on `AlreadyExists`; remove all `exists()` suffix
  prechecks.
- Add RAII cleanup restricted to the transaction's verified child path.
- Preserve current bundle schema/version/path bytes; T021 introduces schema v2.

#### Out of Scope

- Do not change manifest path semantics/schema version; T021 owns it.
- Do not move implementation to evidence yet or add background jobs.
- Do not overwrite/merge existing bundles or use unsafe platform code.
- Do not add a generic filesystem abstraction beyond the injected operations
  required for failure testing.

#### Blocked By

None.

#### Why It Is Blocked

The current filesystem bug is independent of evidence model migration and should

#### Implementation Touchpoints

- Read first: all report paths/write order/cleanup and supported-platform rename

- Edit first: focused `app_report_bundle_transaction.rs`, then delegate current

- Required structural changes: private `CurrentBundleTransaction` with begin,

- Do not edit: evidence fields/formatters, export event scheduling, or schema docs.
- Verify in order: stage-failure matrix, concurrent collision test, all report

- Stop and ask: if no approved cross-platform no-replace directory primitive is
  available or required durability differs by platform/filesystem.

#### Implementation Details

Use an owned transaction with `committed: bool` and validated report root/temp
child. Commit is:

1. verify every expected artifact recorded;
2. write/flush manifest last in temp;
3. sync files/directory as policy requires;
4. invoke audited no-replace atomic publication;
5. on collision, discard/retry with a newly exclusively created name;
6. mark committed only after success.

Do not emulate no-replace with `exists()` plus rename. If std cannot guarantee the
approved platform semantics, use one narrow audited dependency and document it.
Drop cleanup never follows arbitrary manifest paths or escapes report root.

#### Before / After

Before: errors leave partial final bundles and concurrent writers can choose the
same supposedly collision-safe name.

After: readers see no final bundle until the complete current schema-v1 directory
is published without clobbering.

#### Misinterpretations To Prevent

- Wrong: write manifest last directly in final directory. Correct: final directory
  is invisible until atomic commit.
- Wrong: precheck a suffix. Correct: no-replace operation decides collision.
- Wrong: cleanup a computed parent/root. Correct: only the verified owned temp child.

#### Invariants

- Final bundle is complete or absent.
- Existing final bundles are never overwritten.
- Every error cleans only owned temporary state.
- Current schema/path bytes remain unchanged.

- [x] Concurrent same-name writers cannot clobber.
- [x] `exists()` collision prechecks are gone.
- [x] Existing valid bundle artifact bytes/path semantics remain fixed.
