### T036 — Repair Current Axis Termination And Integer Ticks

#### Objective

Fix the confirmed axis infinite loop, unbounded tick growth, and large-u64 label
precision loss in the current render-owned axis implementation before any crate
extraction.

#### Scope

- Primary audit findings: RS-072 through RS-074.
- Replace value-advancing `while` tick generation with a bounded index-based
  algorithm that explicitly rejects/non-progressing adjacent floating values.
- Add one validated maximum tick count shared by current scatter/timeline axes.
- Generate/interpolate timeline ticks in integer/u128 space and format `u64`
  directly, using floating point only for screen fraction.
- Preserve current UI styling, gutters, labels, and public call behavior for valid
  ordinary ranges.

#### Out of Scope

- Do not create `rawscope-analysis`; T013 moves the corrected math later.
- Do not redesign palettes, plot geometry, zoom/pan, or axis aesthetics.
- Do not add a generic chart/axis library or macro-generated tick DSL.
- Do not change endpoint semantics without documenting the current bug/correction.

#### Implementation Details

Use a validated options contract:

```rust
pub struct AxisTickOptions {
    target_tick_count: NonZeroU16,
    max_tick_count: NonZeroU16,
}

pub fn numeric_axis_ticks(
    domain: F64Domain,
    options: AxisTickOptions,
) -> Result<Vec<AxisTick>, AxisError>;
```

Until T005/T013 types land, the current range type may be adapted internally, but
the algorithm must validate finite ordered endpoints and enforce
`target <= max`. Iterate `0..=bounded_interval_count`; compute candidates in f64,
reject `candidate <= previous` before adding, and deduplicate equal presentation
values. Never rely on repeated addition reaching the end.

Timeline tick values use quotient/remainder or u128 interpolation:

```text
value = min + ((span * tick_index) / interval_count)
```

with checked bounds. Store/format the resulting `u64` exactly; compute screen
fraction separately. Cap final vector length by the validated maximum.

#### Before / After

Before: adjacent large f32 values can produce a non-progressing infinite loop,
timeline ticks are unbounded, and labels narrow through floating point.

After: every valid/invalid request terminates within a named bound and integer
timeline values remain exact.

- Wrong: format `u64` after `as f64`. Correct: retain the integer value.
- Wrong: solve by removing ticks. Correct: preserve useful bounded axes.

- Ordinary current axes retain styling/order/meaning.
