### T007 — Correct Synthetic And CSV Boundary Semantics

#### Objective

Make deterministic generators and CSV ingestion honor their public counts,
ranges, limits, and unsigned numeric domains at every boundary size.

#### Scope

- Primary audit findings: RS-026 through RS-029.
- Generate exactly the requested synthetic event count for 0, 1, 2, 3, and all
  larger inputs; make partition ranges sum to the requested count.
- Validate synthetic time windows against the configured `U64Range` and return
  a typed configuration error instead of panicking.
- Use a checked positive row-limit contract across CSV APIs; define `None` as no
  limit and reject zero before reading any row.
- Infer/parse signed and unsigned integer domains without routing valid `u64`
  timestamps through `i64`.

#### Out of Scope

- Do not add new synthetic scenarios, randomness algorithms, or UI controls.
- Do not implement full streaming/chunk admission; T009 owns the pipeline.
- Do not change Parquet semantics; T008 owns adapter parity.
- Do not add raw-versus-normalized store retention; T044 owns that follow-up after
  the immediate parser fixes.
- Do not silently coerce malformed numeric values to missing.

#### Blocked By

T005.

#### Why It Is Blocked

The immediate fixes require only checked ranges/positive limits and should not wait
for DatasetStore migration.

#### Implementation Details

Partition counts with checked arithmetic into named values whose sum is
`row_count`; do not derive overlapping/negative ranges inside loops. For very
small inputs, allocate records deterministically to the earliest documented
pattern lanes and leave later partitions empty.

Synthetic config validation should have an explicit result:

```rust
impl SyntheticEventConfig {
    pub fn validate(&self) -> Result<ValidatedSyntheticEventConfig, SyntheticEventConfigError>;
}
```

All pattern windows must be within the configured inclusive/exclusive time
contract. Convert upper bounds with checked arithmetic and use the deterministic
RNG only after validation.

CSV row limiting must check the count before parsing/pushing the next record:

```rust
match limit {
    Some(limit) if rows_read == limit.get() as u64 => break,
    _ => { /* decode next row */ }
}
```

Inference should distinguish `I64`, `U64`, and `F64`, or parse a bound target
column using its declared target type. A value above `i64::MAX` that fits `u64`
must remain exact. T044 separately preserves raw cell spelling in DatasetStore.

#### Before / After

Before: tiny synthetic requests return the wrong number of events, custom time
ranges can panic, CSV zero limits read one row, valid unsigned timestamps fail,
and callers receive incorrect boundary behavior.

After: counts/ranges/limits are checked/deterministic and unsigned domains stay
exact in current ingestion.

#### Migration Notes

- Preserve deterministic output for existing valid default configurations except
  where the audited row-count bug necessarily changes tiny fixtures.
- Update CLI/session/Python conversion to the same `PositiveRowLimit`; T011/T012
  complete wire-language parity later.
- Do not expose inference enum details as a stable public wire schema.

#### Misinterpretations To Prevent

- Wrong: fix tiny counts by forcing a minimum of four rows. Correct: emit exactly
  the requested count, including zero.
- Wrong: treat zero as unlimited. Correct: `None` means unlimited; zero is invalid.
- Wrong: fold raw retention into this quick fix. Correct: T044 adapts corrected CSV
  decoding to the new store in a separate PR.

#### Invariants

- Generated event count equals requested count exactly.
- Generator config validation occurs before allocation/sampling.
- CSV reads no data row for an invalid zero limit.
- Valid `u64` values never pass through a narrowing signed representation.

#### Acceptance Criteria

- [ ] Regression cases for 0, 1, 2, and 3 synthetic events pass.
- [ ] Out-of-domain synthetic windows return typed errors without panic.
- [ ] CSV zero limit is rejected and positive limits are exact.
- [ ] A timestamp above `i64::MAX` imports when its target type permits `u64`.
- [ ] Focused data tests and workspace check pass.

#### Testing Guidance

- Assert behavior and errors, not internal iterator steps.
- No random sleeps, generated large files, or smoke executable.
