### T042 — Contain Pointer-Time Scatter And Timeline Work

#### Objective

Remove compute/readback/full CPU scans from current pointer handlers, coalesce
rapid viewport intents, and perform one latest exact settle using resident engines
and real jobs before moving behavior into the final render coordinator.

#### Scope

- Primary audit findings: RS-108 and RS-110.
- Make pan/zoom/move handlers update only constant-size viewport/scheduler state
  and request redraw.
- Reproject the last completed field during a gesture, admit at most one bounded
  preview per presented frame, and coalesce pending requests to latest.
- On release/settle, submit one exact scatter/timeline operation through T027 and
  T023 tickets; no event-thread full-grid wait or source rescan.
- Reuse T038 snapshot/current indexes for exact summaries/inspection/evidence state
  instead of independent full scans.
- Reject stale completion by dataset/filter/view/request generations and retain the
  previous completed field on failure.

#### Out of Scope

- Do not create the final controller module; T029 migrates behavior.
- Do not redesign selection/evidence or add visual modes.
- Do not run a continuous busy loop or detached GPU poll thread.
- Do not claim latency improvement without T057 measurement.

#### Blocked By

T023, T024, T025, T027, T038.

#### Why It Is Blocked

Containment needs nonblocking tickets, resident scatter/timeline resources, real
jobs, and one current authoritative selection snapshot.

#### Related Code

- `app_plot_interaction.rs`, `app_render_schedule.rs`, `app_scatter_density.rs`,
  `app_timeline.rs`, and exact-settle/inspection refresh paths.
- `scatter_density_reprojection.rs` and new timeline equivalent.
- T023 ticket lifecycle, T024/T025 resident engines, T027 user events.

#### Implementation Touchpoints

- Read first: every pointer/wheel/pan/release path and every call it triggers.
- Edit first: current `app_render_schedule.rs` state, pointer intent routing,
  scatter then timeline settle adapters.
- Symbols to search: `recompute_*` inside input handlers, `device.poll`, readback,
  marginal/inspection loops, `request_redraw`, and debounce/in-flight booleans.
- Required structural changes: honest current `InteractionSettleState` with desired,
  completed, preview/exact IDs, plus bounded retiring ticket ownership.
- Do not edit: final controller layout, evidence wire, data ingestion, or UI theme.
- Verify in order: deterministic coalescing/stale/failure tests, current workbench
  action tests, adapter correctness, format, workspace check.
- Stop and ask: if exact evidence is required continuously mid-gesture or a
  truthful timeline preview cannot be produced without uncovered-region smearing.

#### Implementation Details

Maintain desired/completed separately. Preview output is labelled refining and
cannot update analytical/evidence truth. At gesture release, obsolete preview
tickets become non-publishable but remain in a bounded retiring registry until
backend terminal state; exact work has priority and previews are skipped at cap.

Completion commits only when its full generation/request key equals desired. The
exact result packages field plus current snapshot/index-derived summaries and is
prepared completely before active replacement. Pending device progress uses
T023's explicit wake/deadline behavior.

#### Before / After

Before: exact scatter settling blocks/readscans and timeline recomputes on every
pointer event.

After: pointer work is constant-size/coalesced and only one latest exact completion
becomes truth without blocking the event thread.

#### Migration Notes

- T029 moves this state/behavior into `controllers/render_coordinator`; no semantic
  rewrite or second scheduler.
- Preserve pan/zoom directions and plot geometry.

#### Misinterpretations To Prevent

- Wrong: debounce but execute synchronously when timer fires. Correct: submit real
  jobs/tickets and accept completion events.
- Wrong: publish preview as exact evidence. Correct: exact completed only.
- Wrong: drop obsolete submitted ticket resources. Correct: bounded retirement.

#### Invariants

- Pointer handlers never scan/upload/read back/rebuild resources.
- Latest desired request wins; stale completion is side-effect free.
- Preview cannot become evidence/selection truth.
- Previous completed field remains until complete exact replacement.
- Live/retiring ticket count is bounded with exact priority.

#### Acceptance Criteria

- [ ] Input handlers perform constant-size intent/redraw work only.
- [ ] Rapid gestures coalesce and release submits one latest exact settle.
- [ ] Scatter/timeline exact paths have no event-thread blocking/full rescans.
- [ ] Stale/error/cancel preserves previous completed state.
- [ ] Ticket saturation skips previews rather than growing unbounded.
- [ ] Deterministic workbench and adapter correctness tests pass.

#### Testing Guidance

- Drive fake jobs/tickets out of order with barriers/channels, not sleeps.
- Assert operation counts, exact generation commits, and bounded registry size.
- Hardware tests only verify real no-readback/resident semantics.

#### Agent Handoff Context

T029 is a relocation/integration task. T057 measures the final path.

## Final Notes

- Recommended order: pointer intent, scatter preview/exact, timeline, stale/error,
  ticket admission.
- Human review: preview cadence/refining disclosure.
- Risk: submit calls themselves can be costly; measure separately in T057.
