### T014 — Add Immutable Cohort Generations

#### Objective

Move filtering into `rawscope-analysis` and make each active cohort an immutable,
validated dataset-generation snapshot with explicit valid/missing/invalid policy
and owner-minted revision.

#### Scope

- Primary audit findings: RS-024, RS-039, RS-040, and RS-071.
- Move `DatasetFilter`, `FilterSet`, mask evaluation, and filter errors from data
  into `rawscope-analysis::cohort`.
- Make filter fields private; expose builders/validated update operations and
  mint `CohortGeneration` only after semantic changes.
- Add explicit `MissingValuePolicy` and `InvalidValuePolicy`; make UI/evidence
  consume the resulting policy rather than infer from booleans/strings.
- Resolve filter predicates to T006 stable `ColumnId` and consume T005 checked
  identifiers at analysis boundaries; T011 separately owns session/display string
  normalization. Do not preserve string/boolean primitive policy fields here.
- Produce immutable row-aligned mask/index state tied to one `DatasetGeneration`.
- Make timeline lane/range validation use the same reject/skip policy in density,
  summaries, and selection, returning typed errors where invalid data is not
  allowed.

#### Out of Scope

- Do not add filter UI, query language, SQL, expression trees, or arbitrary OR
  groups.
- Do not construct final selections/evidence; T016 owns that snapshot.
- Do not upload masks to GPU or coordinate commits; T025/T030 consume cohorts.
- Do not keep a second mutable filter implementation in `rawscope-data`.

#### Blocked By

T006, T013.

#### Why It Is Blocked

Cohorts require an immutable typed store generation and normative range/bin
semantics before mask identity and invalid-value policy can be trustworthy.

#### Related Code

- `crates/rawscope-data/src/dataset_filter.rs` and tests.
- `crates/rawscope-render/src/mask_alignment.rs`, density/summary masked functions.
- Workbench `app_scatter_filter.rs`, `ui_filters/`, and filter revision state.
- Timeline density/summary/brush paths that currently treat invalid lanes/ranges
  differently.

#### Implementation Touchpoints

- Read first: every filter struct literal/mutation, revision comparison, mask
  alignment check, missing/invalid conversion, and timeline invalid-row path.
- Edit first: `rawscope-analysis/src/cohort/{filter,policy,snapshot}.rs`, then data
  removal/compatibility re-export and pure consumers.
- Symbols to search: `FilterSet`, `FilterRevision`, `FilterMask`,
  `evaluate_filters`, `include_missing`, `is_none`, and invalid lane skips.
- Required structural changes: one `CohortBuilder`/validated filter set owner and
  one immutable `CohortSnapshot`; no public mutable vectors.
- Do not edit: UI layout, shaders, evidence wire structs, or job scheduling.
- Verify in order: analysis cohort tests, migrated data/filter tests, masked CPU
  density/summary tests, format, workspace check.
- Stop and ask: if product semantics require OR composition, invalid-as-missing,
  or silent invalid timeline-row skipping.

#### Implementation Details

Use closed policies and immutable output:

```rust
pub enum MissingValuePolicy { Exclude, Include }
pub enum InvalidValuePolicy { RejectDataset, ExcludeWithDisclosure }

pub struct CohortSnapshot {
    dataset_generation: DatasetGeneration,
    cohort_generation: CohortGeneration,
    mask: Arc<[u64]>,
    included_row_count: u64,
    excluded_missing_count: u64,
    excluded_invalid_count: u64,
}
```

Choose a bitset representation with checked length matching store row count.
Expose membership/iteration, not mutable storage. `CohortBuilder::evaluate`
validates predicates against stable `ColumnId`/schema, applies documented AND
semantics, and mints the next generation only when filter content/policy changes.

Timeline summaries either reject invalid lane/range rows under
`RejectDataset` or exclude/count them under `ExcludeWithDisclosure`; density,
selection, and evidence consume the same snapshot/counts.

#### Before / After

Before: callers mutate filter fields/revisions, invalid numerics collapse into
missing, and timeline consumers count/skip invalid events inconsistently.

After: one owner produces immutable cohort generations with explicit policy and
row alignment for all downstream consumers.

#### Migration Notes

- Preserve current AND semantics for valid predicates.
- Temporary data-crate re-exports may ease migration but must not retain
  implementation or allow mutable fields.
- Workbench state should store the validated filter request plus returned
  snapshot, not separate caller-supplied revision numbers.

#### Misinterpretations To Prevent

- Wrong: rename the current public `FilterSet`. Correct: private fields and
  owner-minted generations must prevent bypass.
- Wrong: treat parse failure as missing. Correct: invalid is a separate counted
  state with explicit policy.
- Wrong: recompute a slightly different mask in each consumer. Correct: share the
  immutable snapshot.

#### Invariants

- Mask length and row order match one dataset generation exactly.
- Cohort generations cannot be supplied by callers.
- Missing/invalid counts and membership derive from one evaluation.
- All predicates compose with documented AND semantics.
- Analysis remains UI/GPU/Serde-free.

#### Acceptance Criteria

- [ ] Filter implementation and ownership live in `rawscope-analysis::cohort`.
- [ ] Filter/policy fields are private and validated.
- [ ] Immutable snapshots carry dataset/cohort generation and aligned membership.
- [ ] Missing versus invalid policy/counts are explicit and tested.
- [ ] Timeline density/summary/selection consume the same invalid-row policy.
- [ ] Focused cohort/masked behavior tests and workspace check pass.

#### Testing Guidance

- Add table-driven mixed valid/missing/invalid cases, multiple predicates, no-op
  update generation behavior, mask length mismatch, and invalid timeline lanes.
- Prove all consumers see the same membership/counts; avoid implementation-detail
  bit layout assertions except local bitset tests.
- No UI/window smoke tests.

#### Agent Handoff Context

T015 builds reusable indexes against this snapshot; T016 makes it authoritative
for selections; T025/T030 commit the same generation to GPU/UI atomically.

## Final Notes

- Recommended order: policies/filter validation, snapshot evaluation, timeline
  invalid semantics, consumer migration, remove data implementation.
- Human review: default invalid-value policy and whether exclusions are visible
  in persistent UI/evidence.
- Risk: carrying both old `FilterRevision` and new generation creates divergence;
  remove caller-controlled revision fields in this task.
