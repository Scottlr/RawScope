### T017 — Migrate Inspection And Drilldown To Checked Snapshots

#### Objective

Move inspection and source drilldown into `rawscope-analysis`, derive them from
validated selection/index state, and remove zero-width, divide-by-zero, eager
per-bin allocation, and ambiguous source-availability behavior.

#### Scope

- Primary audit findings: RS-075 through RS-077 and RS-082.
- Move scatter/difference inspection and selection drilldown semantic logic from
  render into focused analysis modules.
- Represent inspection cell extents with bin index plus precise domain metadata,
  not a fabricated strictly positive f32 range.
- Allocate row samples lazily only for occupied bins and keep deterministic
  bounded samples without eager `bins × sample_capacity` allocation.
- Make difference inspection fallible or accept only validated non-zero totals;
  no public helper may divide by zero.
- Distinguish `sampled_due_to_limit`, `source_rows_unavailable`, and invariant
  failure in one masked/unmasked drilldown contract over `SelectionSnapshot`.

#### Out of Scope

- Do not own hover overlays, colors, tooltips, or render geometry.
- Do not add evidence fields yet; T018-T020 adapt the checked results.
- Do not perform source rescans per pointer move.
- Do not replace exact selected IDs with samples.

#### Blocked By

T013, T016.

#### Why It Is Blocked

Checked inspection needs normative bin domains and the authoritative selection/
cohort snapshot. Reusable T015 indexes may accelerate it later but are not a
correctness prerequisite.

#### Related Code

- `crates/rawscope-render/src/scatter_inspection.rs` (over 500 lines),
  `difference_inspection.rs`, and `selection_drilldown.rs`.
- `scatter_inspection_overlay.rs` — presentation consumer that remains in render.
- Existing inspection, drilldown, difference, and workbench tooltip tests.
- Source retention/availability contracts from T006/T009.

#### Implementation Touchpoints

- Read first: range construction at bin edges, sample allocation loops,
  denominator assumptions, masked/unmasked duplicate builders, and UI disclosure.
- Edit first: `analysis/src/inspection/{scatter,difference}.rs` and
  `analysis/src/drilldown.rs`, then render adapters/overlays.
- Symbols to search: `F32Range::new`, `Vec::with_capacity` inside bin creation,
  division by totals, `source_rows_available`, and masked/unmasked functions.
- Required structural changes: one checked inspection builder and one drilldown
  builder accepting snapshot/index/source access; keep render overlay separate.
- Do not edit: WGSL, event scheduling, evidence schema, or UI styling.
- Verify in order: analysis inspection/drilldown tests, migrated render/workbench
  behavior tests, format, workspace check.
- Stop and ask: if source values unavailable by retention policy should block all
  selection evidence rather than produce explicit unavailable disclosure.

#### Implementation Details

Use a precise, non-panicking extent:

```rust
pub struct InspectionBinExtent {
    x_bin: BinIndex,
    y_bin: BinIndex,
    x_domain: F64Domain,
    y_domain: F64Domain,
    grid: GridSize,
}
```

Accessors compute bounds in f64 and may return equal f32 presentation values
without invalidating the analytical bin. The overlay projects bin indices through
the active plot geometry; evidence can retain precise/domain metadata.

Store sample state only for occupied bins, such as an ordered map/vector keyed by
bin index. Because row IDs arrive monotonically from the snapshot, deterministic
first-N/reservoir policy can be implemented without preallocating every bin.

Unify drilldown disclosure:

```rust
pub struct DrilldownCompleteness {
    selected_count: u64,
    attempted_count: u64,
    returned_count: u64,
    sampled_due_to_limit: bool,
    unavailable: Vec<SourceUnavailability>,
}
```

Sampling and unavailability may both be present; counts must reconcile and the
limitations compose rather than overwrite each other. Missing a row that policy
says is retained is `DrilldownError::StoreInvariant`, not silently dropped.
Difference inspection validates non-zero totals and finite normalization before
any division.

#### Before / After

Before: adjacent f32 bin bounds can panic, sample capacity scales with all bins,
public difference inspection can divide by zero, and missing source rows look
like ordinary sampling.

After: inspection is precise/fallible/bounded, presentation consumes it, and
drilldown tells users exactly why rows are absent or limited.

#### Migration Notes

- Preserve current deterministic sample order where it is documented.
- Temporary render re-exports may delegate to analysis, but semantic types should
  move and render-only overlays stay behind render's facade.
- Evidence adapters must map completeness explicitly in later tasks.

#### Misinterpretations To Prevent

- Wrong: widen a zero f32 interval with epsilon and call it exact. Correct: keep
  bin index/f64 domain truth and expand only presentation if needed.
- Wrong: allocate an empty sample vector for every bin. Correct: allocate only
  occupied sampled bins.
- Wrong: silently omit unavailable rows. Correct: error on invariant breach or
  disclose retention unavailability.

#### Invariants

- Inspection construction never panics on valid checked domains/grids.
- Sampling memory is bounded by occupied bins and configured total/sample caps.
- Difference denominators are validated before calculation.
- Drilldown rows are members of the authoritative snapshot.
- Source unavailability and sampling limits are distinguishable and may coexist.

#### Acceptance Criteria

- [ ] Semantic inspection/drilldown owners live in `rawscope-analysis`.
- [ ] Adjacent large-value/zero-f32-width bins do not panic or fabricate domains.
- [ ] Empty bins allocate no per-bin sample capacity.
- [ ] Zero-total difference inspection returns a typed error.
- [ ] Drilldown completeness distinguishes limit, unavailable, and invariant error.
- [ ] Focused analysis/render/workbench tests and workspace check pass.

#### Testing Guidance

- Add adjacent-float, huge grid with sparse occupancy, zero totals, source-retention
  unavailable, missing retained row, and masked snapshot cases.
- Assert allocation bounds through exposed sample counts/capacity policy rather
  than flaky process-memory measurements.
- Keep hover/UI tests at action/projection boundaries, not screenshots.

## Final Notes

- Recommended order: checked extent, sparse sampling, difference validation,
  unified drilldown, render adapter migration.
- Human review: sample policy and whether unavailable source rows permit aggregate-
  only evidence.
- Risk: keeping old masked/unmasked entry points can reintroduce duplicate logic;
  make them thin wrappers or remove before publication.
