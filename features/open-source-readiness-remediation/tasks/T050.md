### T050 — Split Scatter Timeline And Selection Controllers

#### Objective

Move already-correct scatter, timeline, and selection behavior from action-
fragmented `impl WorkbenchApp` modules into three vertical private controllers with
typed commands/results, without also redesigning active-root/UI state.

#### Scope

- Primary audit findings: RS-106 and RS-137 (domain-controller portion).
- Add `controllers/scatter.rs`, `timeline.rs`, and `selection.rs`; reuse T028
  dataset and T029 render coordinator.
- Give each controller private state/job handles and a narrow immutable view.
- Route cross-feature changes through typed commands/results with full generation
  tuples; preserve T038/T041/T042 semantics.
- Delete migrated `WorkbenchApp` fields/methods and action-fragmented modules in
  the same slice; no dual owner.
- Keep app/main/mod facades thin.

#### Out of Scope

- Do not create aggregate active-generation store or UI cache; T030 owns them.
- Do not add/export controller (T049), algorithms, features, or visual polish.
- Do not rename/move modules without privatizing state/commands.
- Do not use a generic message bus/ECS/mutex registry.

#### Blocked By

T028, T029, T041, T042, T043.

#### Why It Is Blocked

Current behavior must already be nonblocking/atomic and dataset/render ownership
stable so the task is an ownership move, not a hidden rewrite.

#### Related Code

- All scatter/timeline/selection `app_*` modules and fields in `app.rs`.
- T038 snapshot, T041 prepared changes, T042/T029 scheduling.
- Workbench action/UI projection tests.

#### Implementation Touchpoints

- Read first: field/mutation/call graph for the three domains and current dirty
  worktree diff.
- Edit first: scatter controller and callers/tests, then timeline, then selection;
  thin `controllers/mod.rs` last.
- Symbols to search: `impl WorkbenchApp`, scatter/timeline/selection fields,
  direct sibling writes, and action handlers.
- Required structural changes: domain commands/results/views; explicit app routing
  only for cross-controller coordination.
- Do not edit: dataset/export owners, evidence/data/render algorithms, UI styling.
- Verify in order: each controller tests after its migration, cross-command tests,
  workbench tests, format, workspace check.
- Stop and ask: if external embedding relies on public app fields or a state field
  has no clear single owner.

#### Implementation Details

Example shape:

```rust
pub(crate) struct ScatterController { /* private state/jobs */ }
pub(crate) enum ScatterCommand { SetCohort(Arc<CohortSnapshot>), SetProjection(...), ... }
pub(crate) enum ScatterResult { Prepared(...), SelectionRequested(...), Failed(...) }
pub(crate) struct ScatterView<'a> { /* borrowed small projection */ }
```

Timeline/selection follow their domain, not one generic trait. Commands that need
multiple controllers are routed by app and result in prepared state from T041/
T029. Worker completions enter the owning controller only after ID/generation
match. Delete old fields/methods immediately after each owner migrates.

#### Before / After

Before: one god object is mutated through action-named sibling modules.

After: three domain owners expose typed behavior/views and app routes them.

#### Migration Notes

- Preserve user-visible behavior/current uncommitted inspection work.
- T030 creates the aggregate active state/UI cache after these owners exist.

#### Misinterpretations To Prevent

- Wrong: move files unchanged under `controllers/`. Correct: private cohesive state
  and commands/results define ownership.
- Wrong: create one controller trait/message Any. Correct: concrete domains.
- Wrong: leave old app fields as mirrors. Correct: one owner only.

#### Invariants

- Every migrated mutable field/job has one controller owner.
- Cross-controller messages are typed/generation-tagged.
- No worker mutates controllers directly.
- Facades route only and current behavior remains.

#### Acceptance Criteria

- [ ] Scatter/timeline/selection controllers exist with private state/views.
- [ ] Old app fields/direct methods/duplicate owners are removed.
- [ ] T038/T041/T042 behavior tests pass under controllers.
- [ ] Cross-controller routing is typed, not generic/global.
- [ ] Files/facades meet organization policy and workspace checks pass.

#### Testing Guidance

- Move existing tests to owner and add only command/result/generation regressions.
- No window/screenshot tests or file-layout assertions.
- Preserve dirty interaction behavior tests.

#### Agent Handoff Context

T030 adds one aggregate active generation and cached UI projection over these
controllers; it should not reopen controller ownership.

## Final Notes

- Recommended order: scatter, timeline, selection, cross-routing, old app cleanup.
- Human review: controller boundary of render coordination versus view state.
- Risk: state mirrored for UI can become a second owner; expose borrowed views only.
