### T049 — Add The Async Export Controller

#### Objective

Move evidence formatting and transactional bundle IO off the event thread through
one private export controller that owns job lifecycle and commits only matching
terminal results.

#### Scope

- Primary audit finding: RS-104.
- Add `apps/rawscope-workbench/src/controllers/export.rs` with private idle/running/
  succeeded/failed/cancelling state.
- Capture a validated immutable evidence document/context/bundle request on owner
  thread and submit all formatting/IO through T027.
- Route progress/terminal completion via typed user events and match job ID plus
  selection/evidence generation before UI/status commit.
- Use T021 transaction; cancellation/stale completion cannot publish partial state.
- Preserve source errors/recovery and sensitive-provenance choice.

#### Out of Scope

- Do not split scatter/timeline/selection controllers; T050 owns them.
- Do not change evidence bytes/schema/bundle semantics.
- Do not add multiple concurrent exports unless explicitly approved; queue policy
  remains bounded.
- Do not mutate `WorkbenchApp` from a worker.

#### Blocked By

T021, T027, T048.

#### Why It Is Blocked

The job runtime, final evidence API, and transactional bundle library must exist
before export controller ownership is stable.

#### Related Code

- Current `app_export*`, report bundle wrappers/status UI, T027 events/errors.
- Evidence document/writers/bundle transaction.
- Existing workbench export/report tests and benchmark.

#### Implementation Touchpoints

- Read first: every export action/status/path and current synchronous formatting/
  writing on event thread.
- Edit first: `controllers/export.rs`, job input/result, event routing, then delete
  old direct paths.
- Symbols to search: export actions, `write_report_bundle`, evidence formatting,
  `ExportStatus`, path/provenance, and swallowed errors.
- Required structural changes: one owned `ExportJobInput` with immutable data and
  one `ExportCompletion`; controller stores no raw mutable app reference.
- Do not edit: other controller layouts, evidence internals, UI styling.
- Verify in order: controller job/stale/failure/cancel tests, report integration,
  workbench tests/bench compile, format, workspace check.
- Stop and ask: queue/supersession behavior for a second user export or shutdown
  while an atomic commit is in progress.

#### Implementation Details

```rust
pub enum ExportControllerState {
    Idle,
    Running { job: JobHandle, selection: SelectionId, generation: EvidenceGeneration },
    Succeeded { bundle: CommittedBundleSummary },
    Failed { error: WorkbenchOperationError, retry: ExportRequest },
    Cancelling { job_id: WorkbenchJobId },
}
```

Capture validates snapshot/context and sensitive policy before submission. Worker
formats/writes. Terminal result is durable even if event proxy closes; shutdown
drains/cancels per T027. UI commits success/failure only for current matching job/
generation. Bundle commit already atomic; cancellation after commit reports the
committed bundle rather than pretending rollback.

#### Before / After

Before: export formatting/filesystem work blocks winit and errors may be erased.

After: one controller owns bounded asynchronous export and persistent result/error.

#### Migration Notes

- T030 includes controller view in cached UI/active app facade; export does not
  become part of analytical active generation.
- Existing command names may remain as action adapters.

#### Misinterpretations To Prevent

- Wrong: preformat all bytes on event thread then job only writes. Correct: worker
  handles validation-safe formatting and IO from immutable input.
- Wrong: stale completion updates current status. Correct: match IDs/generation.
- Wrong: cancel after atomic commit deletes final bundle. Correct: report commit.

#### Invariants

- Event thread performs no evidence formatting/file IO.
- Accepted job yields one durable terminal controller outcome.
- Stale results cannot overwrite current export state.
- Partial bundles never appear.
- Errors preserve source/recovery context.

#### Acceptance Criteria

- [ ] Private export controller owns all export job/status state.
- [ ] Formatting/bundle IO run entirely on bounded worker.
- [ ] Matching/stale/cancel/proxy-closed/shutdown behavior is deterministic.
- [ ] Old synchronous export paths are removed.
- [ ] Focused controller/report/workbench checks pass.

#### Testing Guidance

- Use fake job executor and T021 filesystem failures; no sleeps/live window.
- Assert event-thread formatter/IO seam is not called.
- Keep artifact bytes tested in evidence, not duplicated here.

#### Agent Handoff Context

T030 projects this controller state; T035 uses the library writer, not the UI
controller.

## Final Notes

- Recommended order: input/state, worker job, event commit, old path removal,
  failure/shutdown tests.
- Human review: concurrent export/supersession policy.
- Risk: large immutable input capture can still clone source data; pass Arc/snapshot
  handles with explicit lifetime/budget.
