### T019 — Create The Canonical Evidence Domain

#### Objective

Create a private `rawscope-evidence` crate that owns one validated evidence
domain assembled from analysis truth, while deliberately leaving legacy wire
adapters, readers, callers, formatting, and filesystem bundles for later tasks.

#### Scope

- Primary audit finding: RS-100.
- Add `crates/rawscope-evidence` with a thin facade and domain-first modules for
  dataset identity, query/cohort identity, selection, samples, comparisons,
  sources, and visual context.
- Depend only on the narrow owners needed for those contracts: `rawscope-core`,
  `rawscope-data`, `rawscope-analysis`, and `rawscope-session-contracts`.
- Inherit approved workspace package/legal metadata, set `publish = false`, and
  express internal dependencies with both compatible `version` and `path`.
- Construct and validate canonical evidence from an immutable
  `SelectionSnapshot` plus typed context; make invalid combinations
  unrepresentable or return a source-preserving validation error.
- Add focused construction/validation tests without defining a public wire shape.

#### Out of Scope

- Do not move scatter v1-v5 adapters/readers; T046 owns that bounded migration.
- Do not move timeline v1-v3 adapters/readers; T047 owns it.
- Do not add scatter v6, timeline v4, Markdown formatting, provenance policy, or
  schema documentation; T020 owns those contracts.
- Do not move bundle IO/readers (T021) or workbench/render callers (T048).
- Do not derive a serialized schema from the canonical struct layout.

#### Blocked By

T010, T011, T013, T018.

#### Why It Is Blocked

The canonical model must consume stable precision, session, analysis, selection,
and current serializer-validation contracts rather than recreate them.

#### Related Code

- Current evidence domain/validation components under
  `crates/rawscope-render/src/`.
- `SelectionSnapshot`, dataset/source identities, comparison/aggregate context,
  and session evidence-key contracts.
- Render evidence construction tests that distinguish semantic construction from
  wire formatting.

#### Implementation Touchpoints

- Read first: every evidence constructor/validator and the fields repeated across
  scatter/timeline versions; identify semantic data versus wire-only layout.
- Edit first: crate manifest/facade, then vertical model modules and one validation
  entry point; add no `models.rs`, `types.rs`, or generic helper bucket.
- Symbols to search: evidence document/context/sample/comparison/source structs,
  serializer-side validation, `SelectionSnapshot`, and copied DTO fields.
- Do not edit: render adapters, schema constants, Markdown writers, bundle paths,
  workbench export code, shaders, or historical golden fixtures.
- Verify in order: canonical construction/invalid-combination tests, package
  tests, format, and workspace check.
- Stop and ask: if a field has no authoritative current owner or canonical
  construction would require fabricating legacy-only information.

#### Implementation Details

The canonical domain is private-layout, validated state:

```rust
pub struct EvidenceDocument {
    dataset: EvidenceDataset,
    query: EvidenceQuery,
    cohort: EvidenceCohort,
    selection: EvidenceSelection,
    sources: EvidenceSources,
    visual_context: EvidenceVisualContext,
}

impl EvidenceDocument {
    pub fn from_selection(
        snapshot: &SelectionSnapshot,
        context: EvidenceContext<'_>,
    ) -> Result<Self, EvidenceValidationError>;
}
```

Fields remain private and expose query methods. Construction checks matching
dataset/cohort/projection/selection generations, selected-count consistency,
sample membership, finite presentation context, source availability, and bounded
collections. Wire tasks later map explicitly from query methods; this task does
not add Serde derives as a shortcut.

Keep errors local to evidence and preserve the source/domain context that made a
document invalid. Use ordinary structs/enums/functions, not a version macro DSL.

#### Before / After

Before: evidence semantics are copied into serializer-specific render DTOs.

After: one private validated domain exists as the stable input to independently
reviewable legacy-adapter and new-schema tasks.

#### Migration Notes

- Additive crate creation only; no current public caller changes in this task.
- Existing render constructors may be used as test oracles, but cannot become a
  second canonical owner.
- Keep the package private until the protected publication decision in T056.

#### Misinterpretations To Prevent

- Wrong: move every evidence file now. Correct: create only canonical semantics.
- Wrong: `Serialize` on `EvidenceDocument` defines the next schema. Correct:
  version adapters own every wire field and ordering.
- Wrong: copy render presentation settings wholesale. Correct: accept only typed
  visual context required to explain evidence.

#### Invariants

- `rawscope-evidence` has no WGPU, winit, egui, workbench, or filesystem owner.
- One validation path constructs new canonical evidence.
- Canonical layout is not a public wire compatibility promise.
- Every collection and generation relationship is validated and bounded.
- The new crate is private and uses truthful inherited metadata.

#### Acceptance Criteria

- [ ] `rawscope-evidence` exists with a thin facade and vertical model modules.
- [ ] Its manifest inherits workspace metadata, has `publish = false`, and uses
      `version + path` for internal workspace dependencies.
- [ ] Canonical construction consumes `SelectionSnapshot` and typed context.
- [ ] Invalid generations/counts/samples/sources return contextual errors.
- [ ] No legacy adapter, reader, serializer, bundle, or caller is migrated here.
- [ ] Focused evidence package tests, format, and workspace check pass.

#### Testing Guidance

- Use deterministic canonical fixtures for matching and mismatched generation,
  count, sample-membership, and bounded-collection behavior.
- Do not duplicate byte goldens; T046/T047 own those.
- No fake report app or serialization snapshot of private struct layout.

#### Agent Handoff Context

T046 and T047 independently migrate legacy adapters/readers. T020 adds explicit
new versions, and T048 removes render ownership after all adapters exist.

## Final Notes

- Recommended order: manifest/facade, domain components, constructor/validation,
  focused tests.
- Human review: which visual/source fields are semantic evidence.
- Risk: premature public fields or Serde derives would freeze the wrong API.
