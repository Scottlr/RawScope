### T012 — Align And Harden The Python Dataframe Bridge

#### Objective

Make Python construction, dataframe validation, bundle preparation, and native
launch follow the same bounded type/normalization/atomicity contracts as Rust.

#### Scope

- Primary audit findings: RS-123 through RS-130.
- Reject `bool` as a row limit, enforce the Rust `u64`/application maximum, and
  store normalized identifiers in frozen models.
- Validate scatter/timeline binding types with the exact Rust supported matrix.
- Replace module-name/string adapter selection with lazy imports plus concrete or
  documented protocol `isinstance` checks.
- Write persistent and temporary dataframe sessions into a complete temporary
  sibling generation, then atomically publish it.
- Use engine-native null/uniqueness aggregates or the streaming write pass for
  evidence-key validation; do not materialize whole columns in Python lists.
- Clean prepared temporary bundles when `subprocess.Popen` fails and require
  execute permission for explicit executables on relevant platforms.

#### Out of Scope

- Do not add new dataframe ecosystems, remote kernels, notebooks, or IPC servers.
- Do not change session schema version or accept types Rust rejects.
- Do not make approximate evidence-key uniqueness claims.
- Do not publish the Python package; T035 owns release enablement.

#### Blocked By

T007, T008, T011, T045.

#### Why It Is Blocked

Python must mirror the corrected CSV/Parquet type matrix, final source
normalization vectors, row-limit bounds, and session contract rather than freezing
current bugs.

#### Implementation Touchpoints

- Read first: every public Python entry point, dataframe-engine APIs for bounded
  null/unique aggregates, Rust supported-type tables, and cross-language fixtures.
- Edit first: models/validation, adapter type matrix/key checks, transaction
  object, then launcher cleanup and tests.
- Symbols to search: `isinstance(limit, int)`, `__module__`, `to_list`,
  `n_unique`, `write_parquet`, `os.replace`, `Popen`, and `NamedTemporaryFile`.
- Required structural changes: add a context-managed `PreparedSession` owner and
  a focused transaction module only if `bundle.py` cannot remain coherent; do
  not create `utils.py`.
- Do not edit: Rust implementations except shared language-neutral fixtures.
- Verify in order: Python unit suite with pandas/Polars/PyArrow, Rust session
  fixture tests, Python sdist/wheel build, format/lint commands if configured.
- Stop and ask: if an engine cannot provide exact bounded key uniqueness, if
  persistent update rollback semantics differ from directory replacement, or if
  Windows executable permission policy needs platform-specific approval.

#### Implementation Details

Row-limit validation must explicitly reject booleans before integral checks:

```python
if isinstance(limit, bool) or not isinstance(limit, numbers.Integral):
    raise TypeError("row limit must be an integer, not bool")
```

Then require `1 <= limit <= MAX_SESSION_ROW_LIMIT` and serialize a normal Python
`int` that fits the Rust `u64` contract.

Create one supported binding matrix keyed by session format/view role and test it
from language-neutral fixtures. Python adapters map engine dtypes to that matrix;
they must reject boolean/categorical/text fields where numeric axes/timestamps are
required, matching Rust exactly.

Use transaction ownership:

```python
class PreparedSession:
    path: Path
    temporary: bool
    committed: bool

    def commit(self, final_path: Path) -> Path: ...
    def cleanup(self) -> None: ...
    def __enter__(self): ...
    def __exit__(self, exc_type, exc, tb): ...
```

Write Parquet and manifest under a uniquely/exclusively created sibling directory,
flush/fsync as appropriate, write manifest last, then atomically rename the
directory. On `Popen` failure, cleanup uncommitted temporary state before re-raise.

Evidence-key validation uses engine-native null count and exact unique count when
safe, or validates keys during the one streaming Parquet write. A budget failure
must be explicit; do not fall back to `list(column)`.

#### Before / After

Before: `True` becomes row limit 1, whitespace/type rules drift from Rust, bundle
updates can expose mismatched data/manifest, failed launch leaks files, and key
validation materializes whole columns.

After: Python emits only Rust-valid bounded sessions, atomically publishes complete
generations, and owns cleanup across success/failure.

#### Migration Notes

- Valid existing public Python calls retain names and output schema.
- Inputs that Rust could never load now fail earlier with matching error roles.
- Persistent bundle replacement must preserve the previous valid generation on
  every failure before commit.

#### Misinterpretations To Prevent

- Wrong: `isinstance(True, int)` means valid. Correct: reject bool explicitly.
- Wrong: update the manifest atomically after overwriting Parquet. Correct: stage
  the complete generation and swap it as one unit.
- Wrong: detect pandas by module-name strings. Correct: lazy import and concrete/
  documented protocol checks.

#### Invariants

- Rust and Python accept/reject the same fixture vectors.
- A published bundle is always complete old or complete new.
- Failed process creation cannot leak temporary prepared sessions.
- Exact evidence-key claims never come from approximate/materialized shortcuts.
- Optional dataframe libraries are imported only when used.

#### Acceptance Criteria

- [ ] Boolean/zero/oversized row limits fail with clear errors.
- [ ] Binding-type and normalization vectors pass identically in Rust/Python.
- [ ] Dataframe bundle publication is transactional and failure-tested.
- [ ] Popen failure cleans temporary state and explicit executable checks are
      platform-correct.
- [ ] Key validation avoids full Python column materialization.
- [ ] All existing Python tests plus new parity/atomicity cases pass.

#### Testing Guidance

- Extend existing tests per dataframe engine with accepted/rejected dtype tables,
  boolean limits, whitespace normalization, duplicate/null keys, and injected
  write/rename/Popen failure.
- Assert old-or-new directory contents after each injected failure.
- No live GUI launch or fake dataframe application is required.

#### Agent Handoff Context

This task makes Python a faithful producer of session/data contracts rather than
a permissive alternate API. T021 applies analogous transactions to evidence;
T028 consumes prepared sessions asynchronously.

## Final Notes

- Recommended order: shared fixtures/models, type validation, key validation,
  transaction owner, launcher cleanup, multi-engine tests.
- Human review: supported Python versions/engines and persistent bundle overwrite
  semantics.
- Risk: filesystem directory replacement differs by platform; preserve the old
  generation and surface unsupported atomic replacement explicitly.
