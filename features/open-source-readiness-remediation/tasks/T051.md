### T051 — Add Property And Fuzz Coverage

#### Objective

Add bounded property tests and focused semantic fuzz targets for RawScope's parser,
range/bin, store, and wire boundaries without mixing in cross-controller atomicity
or GPU integration scope.

#### Scope

- Primary audit finding: RS-131.
- Add property tests for checked ranges/dimensions/binning, rectangular chunks,
  filter/selection membership, and bundle-relative paths.
- Add a `fuzz/` package (`publish = false`) with bounded targets for session v1
  JSON, CSV ingest dispatch, and Parquet schema/value dispatch.
- Assert semantic invariants plus no panic; cap bytes/rows/columns/strings before
  allocation.
- Add small reviewable seed corpora and scheduled/manual CI commands.

#### Out of Scope

- Do not add failure-atomicity/filtered golden/GPU parity tests; T032 owns them.
- Do not fuzz third-party parsers unboundedly or require live GPU/UI/services.
- Do not add tests for every private helper or meaningless no-crash-only targets.
- Do not create a fake app or diagnostic utility.

#### Blocked By

T010, T011, T013, T019, T032.

#### Why It Is Blocked

Property/fuzz targets should exercise final checked owners and coexist with the
deterministic cross-boundary regression suite rather than cement temporary APIs.

#### Related Code

- Core/data/analysis/session/evidence public validation entry points and tests.
- T032 deterministic golden/failure matrices.
- T003 CI and cargo-deny/dev dependency policy.

#### Implementation Touchpoints

- Read first: existing boundary cases/fixtures and input allocation limits.
- Edit first: owner-crate property tests, then `fuzz/Cargo.toml` and three targets/
  corpora, then scheduled/manual workflow integration.
- Symbols to search: panicking constructors, checked multiplication, parser byte
  limits, row/column counts, path traversal, and existing proptest/fuzz config.
- Required structural changes: tests under owning `tests/`; shared fixtures only
  under that owner's `tests/common/`; fuzz package excluded/marked private.
- Do not edit: production behavior unless a discovered bug is split back to its
  owner task.
- Verify in order: targeted property tests, workspace tests, bounded fuzz campaigns
  with recorded seeds/duration, format, workspace check.
- Stop and ask: if dev dependencies violate policy or CI runtime/corpus retention
  exceeds approved budget.

#### Implementation Details

Properties must assert meaning, such as ordered inputs map monotonically to valid
bins, failed chunk append commits nothing, selection IDs are sorted/unique/subset,
and relative paths never escape the bundle.

Targets:

```text
fuzz/fuzz_targets/session_manifest_v1.rs
fuzz/fuzz_targets/csv_ingest_bounded.rs
fuzz/fuzz_targets/parquet_dispatch_bounded.rs
```

Session target bounds bytes before parse and validates normalized/fixed-width
contracts. CSV target bounds records/fields and validates rectangular/raw state.
Parquet target fuzzes RawScope's structured bounded Arrow type/value dispatch (not
necessarily the full third-party file decoder) and asserts support/rejection parity.

#### Before / After

Before: boundary-heavy code relies mainly on hand-picked examples.

After: generated bounded inputs continuously exercise semantic invariants and
regression seeds remain reproducible.

#### Migration Notes

- Fuzz tools are dev-only/private and do not enter product packages.
- Keep normal CI property tests deterministic; fuzz campaigns scheduled/manual.

#### Misinterpretations To Prevent

- Wrong: no panic is sufficient. Correct: assert store/bin/schema semantics.
- Wrong: generate attacker dimensions then allocate. Correct: cap before call.
- Wrong: duplicate T032 failure matrices. Correct: separate generated boundaries.

#### Invariants

- Inputs are bounded before allocation.
- Seeds/corpora are small, deterministic, non-sensitive.
- Normal tests remain hardware/service independent.
- Fuzz package cannot publish.

#### Acceptance Criteria

- [ ] Meaningful properties cover core/bin/store/selection/path invariants.
- [ ] Three semantic bounded fuzz targets/corpora exist.
- [ ] CI/manual commands and runtime policy are documented.
- [ ] Findings reproduce from seed and route to owning task.
- [ ] Targeted/workspace checks pass.

#### Testing Guidance

- This task is tests; names describe behavior and failures show minimized input.
- Record campaign command/duration/seed without claiming exhaustiveness.
- No smoke/window tests.

#### Agent Handoff Context

T035 requires this as a release gate; keep it focused on generated boundaries.
