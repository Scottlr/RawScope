### T010 — Define Precision-Safe Projection And GPU Quantization

#### Objective

Preserve source and CPU analytical numeric truth through projection, avoid
unnecessary full copies, and make finite f32 GPU packing an explicit validated
quantization boundary disclosed to evidence and tests.

#### Scope

- Primary audit findings: RS-034, RS-043, and RS-060.
- Retain numeric source columns as typed `i64`, `u64`, or `f64` analytical values
  rather than eagerly narrowing to `f32`.
- Represent projection output in CPU-precise coordinates with stable `RowId`s and
  a reusable generation-owned buffer/cache.
- Return a borrowed/shared raw projection when no transform is required instead
  of copying the entire point vector.
- Make GPU visual records privately constructed and finite-only; return typed
  errors for NaN/infinity/out-of-range conversion.
- Record quantization domain/scale/error disclosure for render/evidence consumers.

#### Out of Scope

- Do not redesign binning/axes; T013 owns normative analysis math.
- Do not change shaders beyond defensive finite checks required for parity.
- Do not claim exact f64 GPU rendering or zero-copy.
- Do not add arbitrary precision, decimal, or a generic numeric trait hierarchy.

#### Blocked By

T005, T006, T013.

#### Why It Is Blocked

Projection needs checked domains, a generation-owned typed store, and the final
analysis owner. It does not require chunked ingestion and therefore must not wait
on T009's larger throughput/memory refactor.

- `crates/rawscope-data/src/scatter_projection.rs` — current projection and raw

- CSV/Parquet numeric conversion paths.

#### Implementation Touchpoints

- Read first: all `ScatterPointRecord`/`TimelineEventRecord` constructors and

  and large-u64/f64 tests.
- Edit first: data numeric/projection contracts, checked visual packers, then
  downstream accessors and defensive shaders/parity fixtures.
- Symbols to search: `as f32`, `.clone()` in raw projection, `is_finite`,
  `ScatterPointRecord {`, `TimelineEventRecord {`, and range normalization.
- Required structural changes: `rawscope-analysis::projection` owns
  `ProjectedScatterGeneration`; render-owned packing owns `GpuQuantization` and
  packed GPU records. Do not add a universal numeric abstraction.
- Do not edit: evidence wire field shapes or workbench scheduling; pass disclosure
  metadata through existing runtime context for T020 to serialize later.
- Verify in order: projection/packing boundary tests, CPU density tests, pure
  CPU/WGSL parity vectors, relevant data/render tests, format, workspace check.
- Stop and ask: if an existing artifact promises exact f32 values rather than

  bound without changing the visual contract.

#### Implementation Details

Use a closed data-owned source numeric representation and an analysis-owned
projection representation:

```rust
pub enum NumericValue {
    I64(i64),
    U64(u64),
    F64(f64),
}

pub struct ProjectedScatterPoint {
    row_id: RowId,
    x: f64,
    y: f64,
}
```

Projection output is owned by a dataset/projection generation and can be shared
through `Arc<[ProjectedScatterPoint]>`. For an identity projection already in
that canonical buffer, return a clone of the `Arc`, not a cloned `Vec`.

GPU packing is explicit and render-owned:

```rust
pub struct GpuQuantization {
    x_domain: F64Domain,
    y_domain: F64Domain,
    max_abs_error_x: f64,
    max_abs_error_y: f64,
}

pub fn pack_scatter_points(
    points: &[ProjectedScatterPoint],
    quantization: &GpuQuantization,
) -> Result<Vec<PackedScatterPoint>, VisualPackingError>;
```

Reject non-finite projected values before packing. Normalize in f64, check the
f32 result, and retain row identity/mapping. Shaders should still defensively
skip non-finite bit patterns so malformed GPU buffers cannot diverge silently
from the CPU reference.

Evidence/report consumers must be able to state source numeric type and that GPU
coordinates were normalized/quantized; exact source samples come from the store,
not reconstructed f32 points.

#### Before / After

Before: numeric ingestion narrows silently, raw projection clones full point
vectors, and public non-finite f32 records can produce CPU/GPU disagreement.

After: CPU analysis remains precise, identity projection shares storage, GPU
conversion is fallible and measured, and source evidence never depends on packed
coordinates.

#### Migration Notes

- Public f32 record struct literals become checked constructors or internal
  packed types; migrate tests through builders.
- CPU reference output should move to f64-aware inputs before GPU parity is
  asserted within a documented tolerance.
- Preserve source field formats/values in evidence compatibility adapters.

#### Misinterpretations To Prevent

- Wrong: change fields from f32 to f64 and still cast silently in the packer.
  Correct: quantization is a named validated boundary with error metadata.
- Wrong: claim zero-copy because an `Arc` is reused. Correct: use copy-minimising
  language and disclose GPU upload/packing.
- Wrong: clamp NaN/infinity into a visible bin. Correct: reject or explicitly
  classify invalid values consistently.

#### Invariants

- Source integer/f64 values remain exact through data/analysis storage.
- Only finite validated coordinates reach GPU packing.
- Row identity survives projection and packing.
- Identity/raw projection does not allocate proportional to row count.
- GPU/CPU comparison uses a documented numerical tolerance/domain.

#### Acceptance Criteria

- [ ] Typed numeric columns are not eagerly narrowed to f32.
- [ ] Projection output is generation-owned and identity projection shares it.
- [ ] GPU packing rejects non-finite/out-of-domain input with contextual errors.
- [ ] Quantization/error metadata is available to render/evidence consumers.
- [ ] Boundary/parity tests cover extreme u64, adjacent f64, NaN, and infinity.
- [ ] Focused data/render tests and workspace check pass.

#### Testing Guidance

- Add table-driven numeric-boundary cases and a test that proves identity
  projection shares the same allocation (`Arc::ptr_eq` at the public seam).
- Test source sample precision separately from GPU tolerance.
- Adapter-backed GPU execution remains in the existing ignored suite; pure pack/
  formula tests run normally.

#### Agent Handoff Context

T013 uses precise projections for normative binning; T019/T020 serialize source
truth plus quantization disclosure; T025 shares packed buffers by generation.

## Final Notes

- Recommended order: typed source numeric model, precise projection, sharing,
  checked packer, defensive shader/parity vectors.
- Human review: acceptable GPU error disclosure and supported extreme domains.
- Risk: memory can grow if precise and packed buffers are both retained without
  T009/T028 resource accounting.
