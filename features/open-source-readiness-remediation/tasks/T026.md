### T026 — Bound Relief And Transition Resource Costs

#### Objective

Replace relief's fragment-time sample amplification with bounded precomputed field
resources and ensure visual transitions retain/use prior data only when complete
grid/config/resource generations are compatible.

#### Scope

- Primary audit finding: RS-062; completes RS-061 transition compatibility.
- Add compute passes that prefilter density into bounded height/normal textures for
  relief presentation rather than repeatedly sampling wide neighborhoods/horizons
  per fragment.
- Define validated relief quality tiers with named radius/step/texture limits and
  explicit default/fallback behavior.
- Extend transition state to carry complete previous/current grid dimensions,
  presentation parameters, field/resource generations, and device generation.
- Permit crossfade only for compatible resources; otherwise perform an immediate
  swap or rebuild a compatible previous representation without lying.
- Release prior resources when transition completes/cancels or reduced-motion is
  active.

#### Out of Scope

- Do not change density counts, selection/evidence truth, palette meaning, or
  introduce 3D perspective.
- Do not make relief the default based on unmeasured appearance/performance.
- Do not add benchmark claims; T033 measures real workbench cost.
- Do not expose shader implementation knobs directly in UI.

#### Blocked By

T025.

#### Why It Is Blocked

Relief/transition resources must refer to validated immutable field generations
and shared dataset resources rather than the current incomplete prior-grid state.

#### Implementation Touchpoints

- Read first: fragment sample loops, quality/config constants, transition resource
  lifetimes, grid-change behavior, reduced motion, and T025 generation handles.
- Edit first: relief compute resource/pipeline module and shader, then transition
  compatibility state and workbench config projection.
- Symbols to search: normal radius, horizon steps, texture samples, previous grid,
  transition progress, reduced motion, and bind group/resource replacement.
- Required structural changes: scatter-owned `ReliefFieldResources` and
  `TransitionCompatibility`; constants/config stay near relief/transition owner.
- Do not edit: analysis density/binning, data, evidence, or job scheduler.
- Verify in order: pure quality/compatibility tests, adapter-backed relief/transition
  semantics, reduced-motion resource tests, format, workspace check. Performance
  thresholds wait for T033.
- Stop and ask: if the precompute path requires unsupported texture/storage
  features on the approved WGPU floor or if product design requires a quality tier
  outside the reviewed budget.

#### Implementation Details

Use a bounded precompute pipeline:

1. Convert/count field to a normalized height texture without CPU readback.
2. Apply a fixed/bounded separable filter or mip hierarchy for the selected tier.
3. Compute/store normals/auxiliary horizon data once per completed field generation.
4. Fragment shader samples a constant small set of textures per pixel.

Validated config names units:

```rust
pub struct ReliefQualityConfig {
    normal_radius_bins: NonZeroU16,
    blur_pass_count: u8,
    max_horizon_steps: u8,
}
```

Use domain-owned min/max constants and device resource-plan checks. Do not use a
macro to produce tiers.

Transition compatibility checks grid size, field format, density mode,
quantization/presentation contract, device generation, and resource validity.
If incompatible, `TransitionDecision::ImmediateSwap` is truthful. Reduced motion
always swaps immediately and releases prior resources.

#### Before / After

Before: relief can perform extreme fragment sample work and transitions can
interpret a previous buffer with current grid metadata.

After: relief presentation uses bounded precomputed resources and transitions
never sample incompatible generations.

#### Migration Notes

- Preserve existing relief visual parameters where they map to validated tiers;
  reject or migrate unsupported arbitrary values explicitly.
- Existing evidence records semantic relief config, not transient texture/pipeline
  internals.
- Keep Cells/topographic exact reference paths unchanged.

#### Misinterpretations To Prevent

- Wrong: just lower the fragment loop constants. Correct: move repeated field work
  to bounded per-generation compute resources.
- Wrong: stretch old grid data into new dimensions during transition. Correct:
  transition only when complete configs/resources are compatible.
- Wrong: call faster based on code shape. Correct: T033 measures named hardware.

#### Invariants

- Relief fragment work is constant-bounded per pixel by quality tier.
- Precomputed resources belong to one field/device generation.
- Incompatible/reduced-motion transitions never retain/sample prior field.
- Density counts and pointer/data alignment remain unchanged.
- Resource cleanup is explicit on completion/cancellation/device loss.

#### Acceptance Criteria

- [ ] Relief uses precomputed height/normal resources with bounded fragment samples.
- [ ] Quality config is private, validated, unit-named, and device-limit checked.
- [ ] Transition compatibility includes full grid/presentation/resource generations.
- [ ] Incompatible and reduced-motion changes swap immediately/cleanly.
- [ ] Cells/reference density semantics remain unchanged.
- [ ] Focused pure/adapter tests and workspace check pass.

#### Testing Guidance

- Test quality limits, resource regeneration, compatible/incompatible grid/mode/
  device transitions, cancellation, and reduced motion.
- Adapter tests should compare stable semantic output/finite pixels, not screenshot
  aesthetics.
- T033 owns frame/sample-count benchmarks and default-mode decision evidence.

#### Agent Handoff Context

T029 coordinates these generations during gestures; T033 determines whether the
bounded path meets performance budgets. Do not make relief default in this task.

## Final Notes

- Recommended order: validated tiers, precompute pipeline, fragment simplification,
  transition compatibility, resource cleanup, tests.
- Human review: quality tier limits and final visual quality.
- Risk: extra textures/passes trade fragment cost for VRAM/compute; T028/T033 must
  account and measure the full product path.
