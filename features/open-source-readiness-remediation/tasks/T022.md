### T022 — Validate GPU ABI And Resource Limits

#### Objective

Make RawScope's low-level upload/allocation boundary provable: validate every
host/WGSL layout, mapped length, allocation byte count, binding, and dispatch
against checked device limits.

#### Scope

- Primary audit findings: RS-048 and RS-058.
- Centralize each `#[repr(C)] + Pod + Zeroable` host/WGSL contract beside its
  owning scatter/timeline/overlay pipeline and assert size/alignment/offsets.
- Set `min_binding_size` for uniform/storage layouts and validate mapped/readback
  lengths before typed decoding.
- Add checked GPU resource plans for bin counts, byte sizes, buffer limits,
  storage bindings, dispatch/workgroup dimensions, and adapter device limits.

#### Out of Scope

- Do not move renderer/domain logic into `rawscope-gpu`.
- Do not add async readback lifecycle; T023 owns it.
- Do not add adapter policy/error scopes/device recovery; T058 owns that separate
  PR after resource errors are typed.
- Do not use Rust `unsafe`, code-generation macros, or a macro DSL to mirror WGSL.
- Do not silently clamp requested grids/resources to device limits.

#### Blocked By

T005.

#### Why It Is Blocked

GPU planning consumes checked sizes/domains and must return typed errors rather
than relying on assert/panic or unchecked integer multiplication.

#### Related Code

- `crates/rawscope-render/src/gpu_*_pack.rs`, renderer param structs, and nine
  WGSL shaders.
- `crates/rawscope-render/src/gpu_density_pipeline.rs` buffer/layout/readback
  helpers.
- `crates/rawscope-gpu/src/{compute,context,error}.rs` limit consumers.
- Existing ignored GPU tests and the report's low-level invariant audit.

#### Implementation Touchpoints

- Read first: every `Pod/Zeroable` type and matching WGSL struct/binding plus all
  buffer/dispatch size calculations/device limits.
- Edit first: focused ABI/resource-plan types/tests in the owning vertical module,
  then route resource construction through them.
- Symbols to search: `repr(C)`, `Pod`, `Zeroable`, `bytes_of`, `cast_slice`,
  `min_binding_size: None`, `create_buffer`, `dispatch_workgroups`,
  mapped byte decode, and device limit reads.
- Required structural changes: `rawscope-gpu::limits` plus render-owned `*_abi.rs`
  per pipeline where needed. No global ABI dumping file.
- Do not edit: workbench controller logic, evidence, data/analysis semantics, or
  shader business formulas except field layout agreement.
- Verify in order: compile-time/host ABI tests, resource-plan limit tests, existing
  ignored semantic GPU tests on an available adapter, format, workspace check.
- Stop and ask: if an ABI cannot be proven without changing the wire layout, if
  requested limits exceed the minimum supported profile.

#### Implementation Details

Each host ABI module declares the Rust type, expected WGSL offsets, total size,
and binding minimum size:

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy, Pod, Zeroable)]
struct TimelineDensityParams { /* fields + explicit padding */ }

const TIMELINE_PARAMS_SIZE_BYTES: u64 = size_of::<TimelineDensityParams>() as u64;
const TIMELINE_PARAMS_MIN_BINDING_SIZE: NonZeroU64 = /* checked constant */;
```

Use `size_of`, `align_of`, and stable `offset_of!` assertions for every field;
semantic GPU tests populate distinctive values so swapped fields fail visibly.
Parsing WGSL at build time or adding a macro is not required.

Resource creation begins from a validated plan:

```rust
pub struct GpuResourcePlan { /* checked counts/bytes/dispatch */ }

impl GpuResourcePlan {
    pub fn for_density(grid: GridSize, records: u64, limits: &wgpu::Limits)
        -> Result<Self, GpuLimitError>;
}
```

Errors name requested/allowed value and units. If workgroups require tiling,
the plan computes legal tiles explicitly.

#### Before / After

Before: host/WGSL agreement is manual and sizes can overflow/device-limit fail.

After: typed plans prove layouts/resources before creation and expose contextual
limit/layout errors for T058/T023 consumers.

#### Migration Notes

- Keep existing public renderer behavior while routing construction through plans.
- Do not expose raw `wgpu::Limits` throughout domain APIs; translate to focused
  capability/error contracts.
- T058 adds adapter/recovery; T023/T024/T025 consume validated plans.

#### Misinterpretations To Prevent

- Wrong: `Pod` proves WGSL compatibility. Correct: assert host offsets/sizes and
  run semantic field-mapping tests.
- Wrong: clamp an oversized grid. Correct: return a typed limit error unless a
  documented tiling path preserves semantics.
- Wrong: fold recovery/fallback into ABI changes. Correct: T058 is independently
  reviewable.

#### Invariants

- Every uploaded ABI type has offset/size/min-binding proof.
- Every allocation/dispatch uses checked counts and device limits.
- No mapped byte slice is cast before explicit length/alignment agreement.
- `rawscope-gpu` remains free of analysis/evidence/UI workflow logic.

#### Acceptance Criteria

- [ ] All host/WGSL ABI structs have complete layout assertions and semantic
      mapping coverage.
- [ ] Buffer/dispatch plans reject arithmetic/device-limit violations contextually.
- [ ] Pure tests, existing adapter-backed GPU tests when available, and workspace
      check pass.

#### Testing Guidance

- Add table-driven resource plans at exact/over limits and distinctive ABI field
  vectors; GPU semantics stay in existing ignored integration suites.
- Record why hardware tests are skipped; no smoke window.

#### Agent Handoff Context

T058 adds recovery; T023/T024/T025 create tickets/resources only from validated
plans. Keep low-level mechanics narrow.

## Final Notes

- Recommended order: inventory/layout proofs, resource plans, consumer migration.
- Human review: supported WGPU capability/limit floor.
- Risk: a size test without semantic distinct-field mapping can miss host/WGSL
  swaps.
