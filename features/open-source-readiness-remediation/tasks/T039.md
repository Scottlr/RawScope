### T039 — Secure Current Evidence Formatting And Provenance

#### Objective

Close current Markdown injection and absolute-path leakage before evidence crate/
wire migration, while explicitly documenting the narrow security compatibility
exception for structurally hostile legacy Markdown values.

#### Scope

- Primary audit findings: RS-093 and RS-094.
- Add current render-owned context-specific Markdown escaping for table cells,
  inline code, list text, headings, and link labels/targets.
- Default current writers to a portable dataset display label/basename instead of
  an absolute local path in existing provenance string fields.
- Add an explicit sensitive-provenance opt-in at the workbench export request;
  never infer it from debug/development mode.
- Keep JSON and known-safe Markdown golden bytes stable; add exact unsafe-before/
  safe-after fixtures and semantic assertions.

#### Out of Scope

- Do not add new provenance/fingerprint fields or schema versions; T020 defines
  scatter v6/timeline v4.
- Do not move files into `rawscope-evidence`; later tasks migrate corrected code.
- Do not change selection/evidence validation or bundle transaction mechanics.
- Do not retain an unsafe default writer solely for byte compatibility.

#### Blocked By

None.

#### Why It Is Blocked

This is a local High security/privacy correction in current writers and should
not wait for canonical evidence extraction.

#### Related Code

- Current scatter/timeline Markdown export modules and v3-v5 shared sections.
- Dataset identity/source path construction and workbench export request/status.
- Existing evidence JSON/Markdown golden tests.

#### Implementation Touchpoints

- Read first: every Markdown interpolation context and absolute path source.
- Edit first: focused `markdown_escape.rs` beside current export modules, then all
  writer call sites and export provenance policy.
- Symbols to search: `format!`, pipes/newlines/backticks/brackets/link/image
  syntax, `path.display`, `canonicalize`, and Markdown headings.
- Required structural changes: typed escape functions by context and
  `CurrentProvenancePolicy { portable_only | include_absolute_sensitive }`.
- Do not edit: schema constants/field names, report IO, data loaders, or UI layout.
- Verify in order: adversarial escaping/provenance tests, legacy safe goldens,
  evidence/workbench tests, format, workspace check.
- Stop and ask: if any external consumer depends on raw unsafe Markdown bytes or
  if absolute provenance must remain default for a contractual reason.

#### Implementation Details

Do not use one global replacement. Provide context APIs:

```rust
fn escape_table_cell(value: &str) -> Cow<'_, str>;
fn escape_inline_code(value: &str) -> Cow<'_, str>;
fn escape_list_text(value: &str) -> Cow<'_, str>;
fn escape_link_label(value: &str) -> Cow<'_, str>;
fn encode_link_target(value: &str) -> Cow<'_, str>;
```

Handle CR/LF, pipe, backtick runs, brackets/parentheses, link/image prefixes,
control characters, and HTML-like text according to context. Plain safe ASCII
returns borrowed/byte-identical output.

Existing source-path string fields receive a portable label by default. Sensitive
opt-in uses the current absolute path only after explicit export-request choice and
marks the UI status as sensitive; it does not add a wire field.

#### Before / After

Before: source values can alter Markdown structure and exports leak local absolute
paths by default.

After: current artifacts are structurally safe and portable by default, with a
documented deliberate byte change only where escaping is necessary.

#### Migration Notes

- Legacy readers remain semantic; do not add an unsafe compatibility writer.

#### Misinterpretations To Prevent

- Wrong: replace only `|`. Correct: escape per context including newlines/code/
  links/images.
- Wrong: delete provenance. Correct: retain portable label; sensitive absolute is
  explicit opt-in.
- Wrong: bump existing schema secretly. Correct: no new fields here.

#### Invariants

- Default artifacts contain no absolute local path.
- Safe legacy fixtures remain byte-identical.
- Sensitive provenance requires explicit per-export authorization.
