### T034 — Finalize Crate And Module Boundaries

#### Objective

Complete the source-ownership migration by removing residual dual owners,
temporary re-exports, and mixed-responsibility oversized modules so final crate
facades are thin and the implemented dependency DAG matches the planned domains.

#### Scope

- Primary audit finding: RS-135; closes the code-ownership portion of RS-136 after
  T048 and controller/module migrations.
- Inventory production Rust files around/over the repository's approximate
  400-line review threshold and classify each by coherent versus mixed ownership.
- Split mixed files by vertical responsibility/change pattern; document a concise
  justification and owner/follow-up for any coherent oversized file that remains.
- Remove temporary `rawscope-session`, render-analysis, render-evidence, and old
  workbench compatibility re-exports after all workspace callers migrate.
- Delete obsolete duplicate implementations, old action-fragmented modules, and
  abandoned migration facades in the same PR as their final call-site updates.
- Confirm package dependencies/public exports implement the final allowed DAG and
  keep `lib.rs`, `main.rs`, and `mod.rs` as routing facades.

#### Out of Scope

- Do not rewrite architecture/README/API docs; T052 owns the narrative/rustdoc pass.
- Do not archive feature plans (T053) or add examples (T054).
- Do not split coherent code solely to satisfy a line count.
- Do not redesign stable public behavior or wire bytes for aesthetic boundaries.
- Do not introduce generic `utils`, `helpers`, `common`, `misc`, giant model/type
  buckets, or speculative traits/macros.

#### Blocked By

T011, T015, T024, T025, T030, T031, T048, T050.

#### Why It Is Blocked

Boundary cleanup must follow final session/analysis/GPU/evidence/controller owners
and feature direction; otherwise it would preserve temporary paths or cause churn.

#### Related Code

- Root/package `Cargo.toml`, all crate `lib.rs`, app `main.rs`, and module facades.
- Files identified by the report's size/responsibility audit.
- Temporary re-exports/deprecations created by T011/T013-T019/T046-T050.
- Final controller and active-state modules in workbench.

#### Implementation Touchpoints

- Read first: final `cargo metadata`, public facade/import graph, production file
  size/responsibility inventory, and all temporary/deprecated markers.
- Edit first: one owner migration/removal at a time, keeping every intermediate
  commit with a coherent DAG; thin facades only after consumers move.
- Symbols to search: `pub mod`, `pub use`, `deprecated`, temporary/compatibility,
  duplicate type/function names, large `impl WorkbenchApp`, and files over policy.
- Required structural changes: vertical domain modules close to owners; move tests
  with their behavior and larger behavior suites under `tests/`.
- Do not edit: schema fixtures, benchmark outputs, release workflows, documentation
  beyond minimal link/module-name adjustments required by code moves.
- Verify in order: focused moved-owner tests after each slice, feature combinations
  from T031, format, workspace/all-target check, final package tests.
- Stop and ask: before removing a documented external public path or when an
  oversized file has no defensible single owner/split seam.

#### Implementation Details

The final dependency direction is verified against actual manifests:

```text
core -> none
session-contracts -> core + serde
data -> core + source adapters
analysis -> core + data
evidence -> core + data + analysis + session-contracts + serde
gpu -> wgpu and approved platform surface dependencies
render -> core + analysis + gpu + wgpu
session -> session-contracts + bounded IO/resolution
workbench -> composition owners + egui/winit
```

Adjust only for an explicit reviewed exception. A crate may re-export a type only
as its intentional public facade, not as a permanent alias for another semantic
owner. For each oversized file, record responsibility and change reasons in the
task/PR; split schema/conversion, state/UI projection, scheduler/executor, or
model/formatter when they change independently.

Use normal Rust moves and explicit imports. Preserve behavior tests/goldens; no
macro-generated facade or compatibility registry.

#### Before / After

Before: migrations leave temporary public paths, oversized mixed owners, and
obsolete implementations that obscure the intended architecture.

After: each semantic concept has one source owner, facades route deliberately,
and the manifest/module graph is navigable and enforceable.

#### Migration Notes

- Remove temporary re-exports only after repository consumers migrate; if external
  compatibility is promised, stop for a deprecation/version decision.
- Preserve file history with normal moves where practical.
- T052 documents the implemented final graph; do not write aspirational docs first.

#### Misinterpretations To Prevent

- Wrong: split every 401-line file. Correct: split mixed responsibility or justify.
- Wrong: keep old modules as forwarding aliases indefinitely. Correct: one owner.
- Wrong: hide dependency direction behind features. Correct: fix ownership first.

#### Invariants

- Every semantic implementation has one owning crate/module.
- `rawscope-core` remains dependency-free.
- Facades contain routing/re-exports, not implementation dumps.
- Final manifest dependencies follow the reviewed DAG or documented exception.
- No temporary migration path survives silently into release assembly.

#### Acceptance Criteria

- [ ] Final crate dependency graph matches allowed ownership or names reviewed
      exceptions explicitly.
- [ ] Every oversized production file is coherently justified or split by owner.
- [ ] Temporary re-exports, duplicate implementations, and obsolete app modules
      are removed after caller migration.
- [ ] Facades are thin and exports deliberate; no prohibited generic buckets exist.
- [ ] Focused moved-owner tests, T031 feature checks, format, and workspace/all-
      target checks pass.

#### Testing Guidance

- Move/retain meaningful behavior tests; do not add tests for file layout itself.
- Compile the public surfaces/features actually changed and run their focused tests.
- No diagnostic module graph utility or smoke app; inspect existing Cargo metadata.

#### Agent Handoff Context

T052 writes current architecture/API docs from this implemented graph. T054 uses
the stable public surface, and T035 assembles it.

## Final Notes

- Recommended order: dependency/facade inventory, duplicate owner removal,
  responsibility splits, temporary path removal, final graph checks.
- Human review: external public path removals and coherent oversized exceptions.
- Risk: deleting a forwarding path too early breaks consumers; migrate imports and
  remove the path in one bounded slice.
