### T035 — Assemble And Inspect Release Artifacts

#### Objective

Turn an approved immutable version/commit into actual source, native, Rust, and
Python package artifacts, inspect their contents, and emit checksums plus a release
manifest without generating supply-chain attestations or publishing anything.

#### Scope

- Release assembly task; publication finding RS-010 remains owned by T056.
- Add pinned least-privilege workflow jobs that validate the T003 gates and build
  the human-approved source/native/Rust/Python artifact matrix from a clean
  isolated checkout.
- Assemble actual Cargo packages, Python sdist/wheels, supported native archives,
  and source archive as approved; do not substitute registry dry-run output.
- Inspect every package/archive against explicit include/exclude rules for licence,
  readme, schemas, examples, generated files, binaries, local data, secrets, and
  absolute/developer-specific paths.
- Produce cryptographic checksums and a versioned release manifest binding artifact
  name, kind, platform/features, version, commit, size, and checksum.
- Compare repeat builds where the approved platform/tooling can be deterministic;
  record explained nondeterminism rather than claiming reproducibility falsely.
- Store build outputs as workflow artifacts for T055; no registry/release mutation.

#### Out of Scope

- Do not generate SBOM, provenance/attestations, or signatures; T055 owns them.
- Do not enable/publish crates, upload releases, touch registries, or implement
  rollback; T056 owns protected mutation.
- Do not trigger a real public release as implementation validation.
- Do not add installers/auto-updaters or unsupported platform artifacts.
- Do not change product behavior, compatibility adapters, or benchmarks to force
  packaging success.

#### Blocked By

T001, T002, T003, T004, T031, T032, T034, T051, T052, T053, T054.

#### Why It Is Blocked

Assembly must consume final legal/policy/CI, feature/public surfaces, regressions,
documentation/archive/example contents, and package metadata.

#### Related Code

- Workspace/Python manifests, licence/readme/schema/example files, and package
  include/exclude configuration.
- T003 workflows/support matrix and T004 release/version/changelog policy.
- T031 feature matrix and T034 final crate graph.
- Existing build scripts/tools and GitHub artifact retention policy.

#### Implementation Touchpoints

- Read first: final package graph, approved artifact matrix/platforms/features,
  package contents, version/changelog/schema alignment, and secret/local-data risks.
- Edit first: release-manifest schema and inspection allow-lists, then pinned
  validate/build/inspect workflow phases and artifact handoff.
- Symbols/keys to search: `publish = false`, versions, package include/exclude,
  source paths, schema constants, changelog `Unreleased`, workflow permissions,
  and artifact names.
- Required structural changes: one release manifest and narrow maintained assembly/
  inspection commands only where workflow YAML cannot express reliable logic.
- Do not edit: publication credentials/environments, SBOM/signing, product code,
  benchmark results, or historical plan contents.
- Verify in order: full prerequisite gates, clean actual package/archive builds,
  content inspection/checksum verification, repeat-build comparison where
  supported, protected workflow artifact retention.
- Stop and ask: before choosing the public artifact matrix, adding a supported
  platform, or if a package unexpectedly contains/omits sensitive/required files.

#### Implementation Details

Workflow phases are separate and credential-free:

1. `validate`: confirm immutable commit/version/changelog/schema alignment and all
   T003 required gates.
2. `build`: create actual approved artifacts in isolated supported-platform jobs.
3. `inspect`: unpack/list with path containment, validate allow-list/deny-list and
   binary/package metadata, and reject secrets/local paths/data.
4. `manifest`: hash inspected bytes and emit one deterministic release manifest.
5. `retain`: upload build products/manifests/checksums only to the workflow artifact
   store for T055 review.

Pin actions/tools immutably and grant only source read plus workflow-artifact write
permissions. Build jobs receive no crates.io, PyPI, signing, or release credentials.
Use normalized timestamps/order/metadata where supported. Repeat-build comparison
compares final bytes/hashes and records platform-specific differences.

All current packages stay `publish = false`; actual Cargo package assembly does
not authorize publication intent. If a proposed artifact cannot be assembled
while private, stop for the T056 approval boundary rather than flipping metadata.

#### Before / After

Before: the repository lacks a reviewed path from commit to inspectable release
artifacts and cannot prove their contents.

After: a protected credential-free workflow creates real inspectable artifacts,
checks contents, and binds them to a manifest/checksum for later attestation.

#### Migration Notes

- Start with the explicitly approved smallest artifact matrix; absence is safer
  than claiming unsupported packages/platforms.
- Artifact naming/version/features are inputs to T055/T056 and cannot change there
  without regenerating manifest/checksums.
- Never mutate or reuse an existing released tag/version.

#### Misinterpretations To Prevent

- Wrong: `cargo publish --dry-run` is the artifact pipeline. Correct: assemble and
  inspect actual package/archive bytes in a clean environment.
- Wrong: successful assembly permits publishing. Correct: T056 requires separate
  human-approved protected mutation.
- Wrong: checksums are provenance. Correct: T055 binds provenance/SBOM/signatures.

#### Invariants

- Assembly source is an approved immutable commit/version.
- Build/inspect jobs have no publication or signing credentials.
- Every retained artifact passes content/path inspection and has a manifest hash.
- Artifact platform/feature/schema claims match tested inputs.
- No registry, release, or package metadata mutation occurs.

#### Acceptance Criteria

- [ ] Credential-free pinned workflow builds the approved actual artifact matrix.
- [ ] Content inspection includes required legal/docs/schema/examples and rejects
      secrets, local data, unsafe paths, and unexpected generated files.
- [ ] Checksums/release manifest bind exact artifact bytes to commit/version/config.
- [ ] Repeat-build comparison is performed where supported and nondeterminism is
      explicitly recorded elsewhere.
- [ ] Workflow retains artifacts for T055 and performs no public mutation.
- [ ] Full prerequisite gates and assembly/inspection checks pass.

#### Testing Guidance

- Validate inspection/manifest logic with focused missing/extra/path-traversal/
  checksum-mismatch fixtures where it protects release integrity.
- Use actual clean assembly, not dry-run publication and not a fake demo package.
- A real registry/release operation is explicitly outside this task.

#### Agent Handoff Context

T055 consumes these exact immutable bytes to produce SBOM/provenance/signatures.
T056 alone may enable and publish an approved matrix.

## Final Notes

- Recommended order: artifact matrix, manifest/inspection policy, validate/build,
  inspect/hash, repeat comparison, retained artifact handoff.
- Human review: artifact/platform matrix, versions, retention, and exceptions.
- Risk: cross-platform bit reproducibility may be limited; never hide differences
  or weaken content inspection to obtain matching hashes.
