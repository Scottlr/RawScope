### T015 — Add Reusable Profile Missingness And Diff Indexes

#### Objective

Build generation-owned analytical indexes once from typed store/cohort state so
profiles, missingness, dataset diff, summaries, and deterministic leaders no
longer rescan row strings or collapse columns by name.

#### Scope

- Primary audit findings: RS-025 and RS-078 through RS-080.
- Move visual field profiling, missingness, dataset diff, and associated summary
  contracts into focused `rawscope-analysis` modules.
- Reuse store-owned missing/invalid bitmaps and bounded category indexes instead
  of cache-unfriendly row-by-column rescans.
- Represent zero-column datasets explicitly as empty analytical results or reject
  them at the store boundary; never invent column 0.
- Diff schemas/data by stable `ColumnId`/ordinal plus name and surface ambiguity;
  do not map duplicate names into one entry.
- Define and test deterministic tie policy for top categories/lanes.
- Tag indexes/results with dataset and cohort generation.

#### Out of Scope

- Do not build arbitrary group-by/query execution.
- Do not add GPU missingness/diff rendering or UI layout.
- Do not construct selections/evidence; T016-T020 consume these indexes.
- Do not reintroduce unbounded category maps to make counts exact.

#### Blocked By

T006, T009, T013, T014.

#### Why It Is Blocked

Indexes need the final typed/chunked store, bounded ingestion indexes, normative
bins, and immutable cohort generations.

#### Implementation Details

Use immutable generation-bound owners:

```rust
pub struct DatasetAnalysisIndex {
    dataset_generation: DatasetGeneration,
    columns: Arc<[ColumnAnalysisIndex]>,
}

pub struct CohortAnalysisIndex {
    dataset_generation: DatasetGeneration,
    cohort_generation: CohortGeneration,
    missingness: MissingnessIndex,
    summaries: SummaryIndex,
}
```

Missingness aggregates column bitmaps by requested row/bin ranges; it does not
iterate every cell for every refresh. Invalid counts remain separate. Diff pairs
columns by stable schema position/ID and reports `Added`, `Removed`, `Compatible`,
`TypeChanged`, or explicit ambiguity—names are presentation metadata.

Tie policy is explicit, for example descending count then ascending stable
category/lane rank. If bounded profiles yield estimated counts, leader output
must carry accuracy/error metadata rather than pretend exact ordering where
error bounds overlap.

#### Before / After

Before: missingness invents a column for empty tables and rescans cache-unfriendly
cells, diff collapses duplicate names, and top-value ties depend on iteration.

After: reusable generation-tagged indexes answer bounded analytical questions
with stable column identity, explicit empty/accuracy behavior, and deterministic
ties.

#### Migration Notes

- Keep render compatibility re-exports temporarily; actual implementations move.
- Preserve existing output ordering where it matches the documented new tie
  policy; document intentional changes.
- UI should consume immutable result projections and accuracy labels, not raw
  index internals.

#### Misinterpretations To Prevent

- Wrong: cache the old O(rows × columns) result per viewport. Correct: ingest/
  store-owned bitmaps and indexes make aggregation reusable.
- Wrong: use column name as identity. Correct: stable ID/ordinal owns identity.
- Wrong: choose a top value from approximate counts without disclosure. Correct:
  carry accuracy/error information.

#### Invariants

- Index generations match their dataset/cohort inputs.
- Zero-column behavior is explicit and cannot fabricate a column.
- Missing and invalid counts remain distinct.
- Diff never collapses columns solely by duplicate display name.
- Tie/order policy is deterministic across runs.

#### Acceptance Criteria

- [ ] Profile/missingness/diff implementations live in `rawscope-analysis`.
- [ ] Missingness consumes reusable bitmaps/indexes and handles empty schema.
- [ ] Diff uses stable column identity and surfaces type/ambiguity changes.
- [ ] Category/lane leader policy and accuracy labels are deterministic.
- [ ] Results carry dataset/cohort generations.
- [ ] Migrated analytical/workbench tests and workspace check pass.

#### Testing Guidance

- Benchmarks of scan reduction belong to T033, not acceptance here.
