### T009 — Implement Chunked Ingestion And Bounded Source Indexes

#### Objective

Replace eager, repeated full-dataset preparation with a single staged ingestion
plan that validates once, appends bounded chunks, builds reusable source indexes,
and accounts retained memory before committing a dataset generation.

#### Scope

- Primary audit findings: RS-031, RS-038, RS-041, and RS-044.
- Add an `IngestionPlan` that opens/reads schema once, validates profile bindings,
  then consumes the same source into `DatasetStoreBuilder`.
- Stream CSV record batches and Parquet Arrow batches without first retaining a
  full `Vec<RecordBatch>` plus duplicate row/point forms.
- Add explicit chunk-size, retained-column, raw-value, and RAM budgets with
  checked admission before store mutation.
- Build evidence-key uniqueness and categorical/profile indexes incrementally
  under documented exact/estimated/budget-exceeded semantics.
- Expose ingestion progress and contextual errors through a callback/iterator
  contract that T028 can run on a worker; do not introduce threads here.

#### Out of Scope

- Do not add async runtime, background tasks, or workbench progress UI.
- Do not upload GPU resources during decoding.
- Do not build a query engine, memory-mapped database, spill manager, or remote
  connector.
- Do not claim all ingestion is zero-copy or unbounded in scale.

#### Blocked By

T006, T007, T008, T044, T045.

#### Why It Is Blocked

Streaming must preserve immediate parser fixes plus the final raw/normalized and
cross-adapter store semantics; otherwise it would stream into an obsolete or
format-divergent representation.

#### Implementation Details

Use a synchronous, cancellation-aware plan that can later run on a worker:

```rust
pub struct IngestionPlan { /* source, validated schema/profile, policies */ }

impl IngestionPlan {
    pub fn prepare(request: IngestionRequest) -> Result<Self, IngestionError>;
    pub fn execute(
        self,
        cancel: &impl CancellationCheck,
        on_progress: impl FnMut(IngestionProgress),
    ) -> Result<DatasetStore, IngestionError>;
}
```

`prepare` opens the source and validates the schema/profile once. If a format
cannot safely continue from the same handle, reopening must be explicit and
measured, not disguised as validation. `execute` appends one checked chunk at a
time and checks cancellation between bounded units.

Use typed units such as `ChunkRowCount`, `MemoryBudgetBytes`, and
`MaxRetainedSourceBytes`. Store accounting covers typed arrays, raw values,
bitmaps, indexes, and capacity overhead with a documented conservative method.

Evidence-key validation must be exact. Use a bounded table-owned index of stable
hash plus collision verification/source reference; if the budget cannot prove
uniqueness, return `EvidenceKeyIndexError::BudgetExceeded` rather than claim the
column is unique.

Categorical profiling may use a deterministic bounded heavy-hitter algorithm.
Its result distinguishes `Exact` from `Estimated { error_bound }` and
`DistinctCount::AtLeast`; UI/evidence must not label estimates as exact.

#### Before / After

Before: profile validation can read twice, Parquet batches and row strings are
duplicated eagerly, key validation copies a full column, and category maps grow
unbounded before truncation.

After: one plan emits bounded chunks into one store, indexes are reusable and
truthfully exact/estimated, and admission/cancellation can occur between chunks.

#### Migration Notes

- Keep old `load_*` entry points as thin calls into `IngestionPlan` until all
  workbench/session callers migrate; do not preserve the old internal storage.
- Maintain deterministic row order and IDs across chunk boundaries.
- T028 owns background execution and UI progress; this API remains runtime-neutral.

#### Misinterpretations To Prevent

- Wrong: stream parsing but collect all chunks before building the store.
  Correct: append/admit each chunk and release adapter temporaries.
- Wrong: truncate a full category map after building it. Correct: memory is
  bounded during counting.
- Wrong: approximate evidence-key uniqueness. Correct: fail if exact uniqueness
  cannot be established within policy.

#### Invariants

- Source schema/profile validation occurs once per plan.
- Temporary adapter memory is bounded by chunk policy.
- Row IDs remain contiguous/deterministic across chunks.
- Store/index budgets are checked before commit and failures leave no partial
  public dataset generation.
- Progress/cancellation callbacks do not own source/store state.

#### Acceptance Criteria

- [ ] CSV and Parquet execute through one staged plan and checked store builder.
- [ ] Parquet no longer retains all batches before conversion.
- [ ] Profile validation reuses the staged schema/source plan.
- [ ] Evidence-key and categorical indexes obey explicit budgets/accuracy labels.
- [ ] Memory accounting includes retained raw values and indexes.
- [ ] Focused one-pass/budget/cancellation tests and workspace check pass.

#### Testing Guidance

- Add deterministic multi-chunk fixtures proving row-ID continuity, one schema
  validation, cancellation before commit, and old-or-error store state.
- Add adversarial high-cardinality and duplicate-key inputs with small budgets.
- Do not use huge files or timing assertions; T033 owns measured performance.

#### Agent Handoff Context

This is the storage/memory pivot. T010 consumes precise typed columns; T015
reuses indexes; T028 moves the synchronous plan to bounded jobs. Avoid coupling
the plan to winit/Tokio or the current workbench state object.

## Final Notes

- Recommended order: staged plan, chunk adapters, store admission, exact key
  index, bounded category index, compatibility loaders.
- Human review: default chunk/raw/index budgets and approximate category policy.
- Risk: conservative accounting may reject inputs previously accepted; errors
  must explain which budget/retention choice caused rejection.
