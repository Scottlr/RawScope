### T053 — Archive Historical Feature Plans

#### Objective

Move completed/superseded feature bundles outside the active contributor path,
preserve their original records exactly, and provide a clear active/archive index
with repaired references.

#### Scope

- Primary audit finding: RS-139.
- Add `features/README.md` listing active, completed, superseded, and archived
  bundles with maintained truth links.
- Move approved historical completed bundles under `features/archive/` using
  history-preserving moves.
- Repair repository links/prompts and annotate supersession only in the index.
- Correct any inaccurate completion checkbox only in a separate explicit erratum,
  never by rewriting original task history.

#### Out of Scope

- Do not rewrite historical task text/status to match current code.
- Do not delete feature plans or use them as maintained architecture docs.
- Do not move this active remediation bundle before completion.
- Do not change production code.

#### Blocked By

T052.

#### Why It Is Blocked

Maintained architecture/roadmap truth must exist before historical plans leave the
primary path.

#### Related Code

- Existing `features/*/tasks.md`, task details, implementation plans, docs prompts,
  and `docs/AGENTS.md` current-next-task links.

#### Implementation Touchpoints

- Read first: every feature status/link and current contributor entry point.
- Edit first: `features/README.md`, then human-approved moves and link repairs.
- Symbols to search: `features/`, current next task, old bundle names, task links.
- Required structural changes: `features/archive/<original-name>/` preserving tree.
- Do not edit: historical file contents except path-relative links strictly needed
  by move; record such changes as mechanical.
- Verify in order: `git diff --summary`, link/reference review, status/history
  preservation, docs check.
- Stop and ask: before moving each bundle or marking active/superseded/completed.

#### Implementation Details

Index records original path/name, status, archive path, completion date if known,
and maintained successor docs/tests. Use `git mv`; do not copy/delete and lose
history. If relative links inside moved files require edits, preserve prose/status.

#### Before / After

Before: historical plans conflict with active contributor direction.

After: history remains discoverable but maintained docs/tasks are unambiguous.

#### Migration Notes

- Update `docs/AGENTS.md` next-task path only to an actually active bundle.
- Keep external links redirectable via index where possible.

#### Misinterpretations To Prevent

- Wrong: “archive” means delete/rewrite. Correct: history-preserving move/index.
- Wrong: fix regressions by unchecking old task. Correct: current audit/tasks/tests
  record regression.
- Wrong: archive still-active plan. Correct: human status approval.

#### Invariants

- Original records/status/prose remain intact.
- Every move has index entry and repaired inbound links.
- Active contributor path names maintained truth only.

#### Acceptance Criteria

- [ ] Human-approved active/archive index exists.
- [ ] Historical bundles move with history and intact records.
- [ ] All repository references resolve to active/archive locations.
- [ ] No production/test behavior changes.

#### Testing Guidance
