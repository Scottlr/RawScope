### T008 — Correct Parquet Type Dispatch And Errors

#### Objective

Make Parquet schema/value support consistent and errors actionable immediately,
without waiting for DatasetStore or cross-adapter normalization migration.

#### Scope

- Primary audit findings: RS-032, RS-033, and RS-036.
- Reject Arrow `Float16` consistently at schema validation and load boundaries
  until a complete checked conversion/evidence-format contract is implemented.
- Model unsupported Arrow types as `Unsupported(DataType)` metadata and fail
  bound loads instead of formatting a type name as a source value.
- Add Parquet-aware error locations/variants so failures never claim CSV row
  semantics and preserve Arrow/Parquet sources.

#### Out of Scope

- Do not add Float16 support partially or narrow it silently to f32.
- Do not stream Parquet batches yet; T009 owns staged chunk ingestion.
- Do not unify lanes/source identity/logging; T045 owns parity after store landing.
- Do not redesign evidence schemas; T018-T020 own compatibility/migration.
- Do not add remote object stores or Arrow/DataFusion query execution.

#### Blocked By

T005.

#### Why It Is Blocked

The accepted-but-unloadable/fabricated-value defects are local to current Parquet
dispatch and should land before store migration.

#### Implementation Touchpoints

- Read first: every Arrow `DataType` match, conversion/value formatting, dataset-

- Edit first: Parquet type dispatch/error model, then focused fixtures.
- Symbols to search: `Float16`, `Unsupported`, `format!("{data_type:?}")`,

- Required structural changes: adapter-specific errors may wrap a common
  `ParquetLocation { path, batch_index, row_index, column }` or a current common

- Do not edit: render/evidence wire files or Python implementation except shared

- Verify in order: targeted Parquet fixture/error tests, rawscope-data tests,
  format, workspace check.
- Stop and ask: if Float16 is an immediate supported-format requirement; that
  requires a separate full precision/evidence design rather than removing the
  rejection.

#### Implementation Details

Schema classification must preserve the original Arrow type:

```rust
pub enum LoadedColumnKind {
    Boolean,
    SignedInteger,
    UnsignedInteger,
    Float,
    Utf8,
    Timestamp,
    Unsupported(arrow_schema::DataType),
}
```

If exposing Arrow types would leak a heavy dependency through a public facade,
keep this adapter-internal and expose a dependency-light owned description/error.
Do not claim support for a type that conversion cannot load.

Errors name `ParquetBatchRow`/schema/value roles accurately with path/batch/row/
column context and preserve underlying Arrow/Parquet errors as `#[source]`.

#### Before / After

Before: Float16 validates then fails, unsupported values become fake type-label
text, and Parquet errors mention CSV row semantics.

After: support/rejection is consistent from schema through current load and
Parquet errors identify actionable source location.

#### Migration Notes

- Rejecting previously accepted-but-unloadable Float16 is a correctness fix;
  document it as unsupported rather than a regression.
- T045 later migrates corrected conversion into shared source metadata/normalization.

#### Misinterpretations To Prevent

- Wrong: stringify unsupported values. Correct: surface unsupported type and
  stop the bound load.
- Wrong: implement only schema acceptance for Float16. Correct: reject it at all
  boundaries until conversion, precision, Python, and evidence are complete.
- Wrong: broaden this quick fix into lane/metadata/store refactoring. Correct: T045
  owns that separate PR.

#### Invariants

- Schema validation and value loading have the same supported-type matrix.
- Errors name the actual format/location and preserve sources.
