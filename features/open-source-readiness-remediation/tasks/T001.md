### T001 — Complete Legal And Package Metadata

#### Objective

Remove the repository's legal and mechanical packaging blockers without
publishing anything. Establish explicit package intent, include the dual-licence
texts in Rust and Python artifacts, and make every package self-describing.

#### Scope

- Primary audit findings: RS-001, RS-002, RS-007, and RS-015.
- Add canonical `LICENSE-MIT` and `LICENSE-APACHE` files after the copyright
  attribution is approved by the maintainer.
- Add repository/homepage/readme metadata at workspace level and package-specific
  descriptions, keywords, categories, and publication intent.
- Add `version = "0.1.0"` beside every internal `path` dependency that could
  ever be packaged.
- Set `publish = false` on every current package as the safe baseline; T035 is
  the only task allowed to enable an approved public crate set.
- Complete PEP 621 metadata and ensure both licence files and the Python README
  are included in sdist/wheel artifacts.

#### Out of Scope

- Do not publish crates, wheels, binaries, tags, or releases.
- Do not choose an MSRV, update dependencies, or create CI; T002/T003 own those.
- Do not invent a legal entity, author list, security contact, or copyright
  holder.
- Do not stabilize or redesign public Rust APIs in this task.

#### Blocked By

None.

#### Why It Is Blocked

This task can begin immediately. The only external decision is the exact
copyright attribution; package privacy can be established before any later
public-crate decision.

#### Related Code

- `Cargo.toml` — `[workspace.package]` and shared dependency versions.
- `crates/*/Cargo.toml` and `apps/rawscope-workbench/Cargo.toml` — package
  descriptions, `publish`, and internal path dependencies.
- `sdk/python/pyproject.toml` — incomplete PEP 621 metadata and licence policy.
- `README.md` and `sdk/python/README.md` — public licence/source links.
- Missing root `LICENSE-MIT`, `LICENSE-APACHE`, and publication-intent document.

#### Implementation Touchpoints

- Read first: every manifest, Cargo's package inclusion rules for the locked
  toolchain, both READMEs, and the repository ownership information supplied by
  the maintainer.
- Edit first: `LICENSE-MIT`, `LICENSE-APACHE`, then root/package manifests.
- Symbols/keys to search: `[workspace.package]`, `path =`, `[project]`,
  `[tool.setuptools]`, `license`, `publish`, `repository`, and `readme`.
- Required structural changes: add `docs/PUBLISHING.md` with an explicit table
  of packages and current `private` status; keep it policy-only until T035.
- Do not edit: Rust/Python source, `Cargo.lock`, workflows, schemas, or tests.
- Verify in order: `cargo metadata --format-version 1`; create a clean isolated
  worktree/copy containing the intended commit plus this task's scoped changes
  (never reset or package unrelated user edits); run `cargo package -p` for each
  library there; build Python sdist/wheel; inspect all archive contents for
  licences/readmes.
- Stop and ask: before filling the MIT copyright line, changing any package to
  publishable, or naming authors/maintainers not already approved publicly.

#### Implementation Details

Use workspace inheritance for fields that are genuinely shared:

```toml
[workspace.package]
version = "0.1.0"
edition = "2021"
license = "MIT OR Apache-2.0"
repository = "<approved repository URL>"
homepage = "<approved project URL>"
readme = "README.md"
```

Each package must define a truthful `description` and explicit
`publish = false`. Internal dependencies use both path and compatible version:

```toml
rawscope-core = { version = "0.1.0", path = "../rawscope-core" }
```

Do not add a crates.io `license-file` that contradicts the SPDX dual licence.
The Python project should use current PEP 639-compatible licence-file metadata
for the selected setuptools floor and add project URLs, classifiers, and
readme. Configure the build so both root licence files are present in sdist and
wheel metadata; verify the actual archives rather than assuming setuptools
includes parent files.

`docs/PUBLISHING.md` must record:

- every package name;
- current `private` state;
- intended consumer (internal library, native app, Python bridge);
- prerequisite task IDs before publication can be reconsidered;
- the rule that T035 requires explicit human approval to flip `publish`.

#### Before / After

Before: the workspace declares a dual licence with no licence texts, packages
have sparse metadata, path dependencies have no versions, and publication intent
is implicit.

After: source and built artifacts carry approved licence texts and metadata,
internal dependency versions are package-compatible, and accidental publication
is impossible because all packages are explicitly private.

#### Migration Notes

- No API or artifact schema changes are permitted.
- Adding path dependency versions must match `workspace.package.version` exactly.
- If Cargo cannot include a workspace-root README from a member package, add a
  small crate-owned README that links to the root documentation; do not copy a
  stale full README into every crate.

#### Misinterpretations To Prevent

- Wrong: packaging success authorizes publication. Correct: all packages stay
  private until T035 and explicit maintainer approval.
- Wrong: fabricate `RawScope contributors` as a legal holder. Correct: stop for
  the approved attribution.
- Wrong: add version-only crates.io dependencies and remove local paths.
  Correct: keep `version + path` for local workspace development.

#### Invariants

- The SPDX expression and shipped licence texts agree.
- Every current package has explicit publication intent.
- Every packaged Rust/Python artifact contains the required licence material.
- No code, lockfile, schema, or dependency version changes occur.
