### T018 — Make Current Evidence Contracts Serializer-Validated

#### Objective

Repair evidence integrity in place before crate extraction: make v4/v5 contracts
opaque and comprehensively validated, require validated sources for promotion,
and ensure every serializer rejects impossible or incomplete artifacts.

#### Scope

- Primary audit findings: RS-086 through RS-091 and RS-099.
- Privatize mutable evidence fields and expose checked builders/accessors for
  query, cohort, comparison, samples, inspection, and session context.
- Add one reusable `validate()` path per supported current contract and require it
  from constructors, v4-to-v5 promotion, JSON, and Markdown serializers.
- Enforce difference magnitude bounds/tolerance and exact bidirectional agreement
  between density mode and every difference-bearing field.
- Make schema version serializer truth rather than caller-mutable in-memory data.
- Treat missing retained source rows as an invariant error or explicit unavailable
  contract; never silently drop them.
- Preserve legacy output bytes for all valid existing golden fixtures.

#### Out of Scope

- Do not extract `rawscope-evidence` yet; T019 owns the crate move/readers.
- Do not remove v1-v5/timeline versions or rename valid wire fields.
- Do not add path redaction/Markdown escaping beyond validation; T020 owns safety.
- Do not derive serialization directly on canonical analysis snapshots.

#### Blocked By

#### Implementation Details

Introduce opaque validated values rather than boolean validation flags:

```rust
pub struct ValidatedScatterEvidenceV4(ScatterEvidenceV4Data);

impl ScatterEvidenceV4Builder {
    pub fn build(self) -> Result<ValidatedScatterEvidenceV4, EvidenceValidationError>;
}

impl ValidatedScatterEvidenceV4 {
    pub fn validate(&self) -> Result<(), EvidenceValidationError>;
}
```

If internal mutation is impossible, `validate()` still protects deserialized or
compatibility inputs until T019 readers own construction. Serializer signatures
accept the validated wrapper or call validation and return a typed combined
validation/serialization error—never `expect`.

Schema version is emitted from the adapter constant. Remove public mutable
`schema_version` from validated state; legacy wire adapters may deserialize and
reject mismatches explicitly.

V5 promotion accepts `ValidatedScatterEvidenceV4`, verifies its source contract,
then validates session/pinned-inspection additions. Difference mode requires all
required difference configs and forbids them in absolute mode, independent of
whether inspection is pinned. Magnitude must be finite and within `0.0..=1.0`
using the same tolerance/definition as analysis.

#### Before / After

Before: public mutation bypasses constructors, V5 trusts invalid V4, mode/config
validation is asymmetric, serializers emit unchecked state, and rows may vanish.

After: only validated evidence reaches bytes, version/mode/sample/source
invariants are centralized, and valid artifacts remain byte-compatible.

#### Migration Notes

- Migrate workbench builders through `SelectionSnapshot`; do not reconstruct
  public DTO literals.
- Keep current public serializer names where possible but return typed errors.
- Source compatibility may break before release; artifact compatibility for valid
  data must not.

#### Misinterpretations To Prevent

- Wrong: validate only in constructors. Correct: serializer/read boundaries also
  enforce validation.
- Wrong: leave public fields for tests. Correct: tests use builders and malformed
  wire fixtures.
- Wrong: silently omit missing source rows. Correct: invariant error or explicit
  unavailable state approved by contract.

#### Invariants

- No supported serializer emits an unvalidated artifact.
- V5 cannot be built from invalid/unvalidated V4.
- Difference mode/config presence agrees in both directions.
- Schema version is adapter-owned constant truth.
- Valid legacy fixture bytes remain unchanged.

#### Acceptance Criteria

- [ ] V4/v5 invariant-bearing fields are private with checked construction.
- [ ] Comprehensive validation is shared by build/promotion/serialization.
- [ ] Difference bounds and symmetric mode/config rules are enforced.
- [ ] Missing retained source rows cannot be silently dropped.
- [ ] Schema versions cannot be caller-mutated.
- [ ] All valid golden artifacts remain byte-identical and invalid cases fail.

#### Testing Guidance

  range magnitude, absolute mode with difference fields, difference mode missing
  fields, invalid V4 promotion, schema mismatch, and missing source row.
- Keep byte-level golden assertions for valid legacy artifacts.
- Avoid broad snapshots unrelated to compatibility.
