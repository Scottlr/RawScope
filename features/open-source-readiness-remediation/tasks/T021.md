#### Objective

Move the already-correct transactional bundle mechanism into
`rawscope-evidence`, add an explicit bundle manifest schema v2 whose paths are
validated bundle-relative, and strictly read every documented legacy v1 path
form without guessing.

#### Scope

- Move T040's no-clobber staged `BundleTransaction` into the evidence crate and

#### Implementation Details

V2 uses explicit wire state:

```rust
pub const REPORT_BUNDLE_SCHEMA_VERSION_V2: u32 = 2;

pub struct BundleArtifactV2 {
    pub kind: EvidenceArtifactKind,
    pub schema_version: u32,
    pub relative_path: BundleRelativePath,
    pub length_bytes: u64,
    pub checksum: ContentChecksumV1,
}
```

`BundleRelativePath` rejects absolute/prefixed paths, parent traversal, empty
components, ambiguous separators, and normalization changes. The v2 reader joins
only validated relative paths beneath the chosen bundle root, validates manifest
first, then length/checksum and artifact kind/version before typed decode.

Manifest-v1 compatibility is a closed matrix, not a fallback heuristic:

- historical v1-v3 artifact entries using serialized full child paths follow the
  documented legacy full-child branch and are rebased only by the proven filename
  relationship when a moved-bundle fixture permits it;
- historical v4/v5 filename entries follow the filename branch beneath bundle
  root;
- scatter and timeline artifact kinds/versions each have exact fixtures;
- unknown combinations, traversal, mismatched kind/version, and ambiguous path
  forms fail with contextual compatibility errors.

Move T040's transaction implementation behavior-identically: exclusive hidden
staging, manifest last, supported durability sync, atomic no-replace publication,
and verified-child RAII cleanup.

#### Before / After

Before: transaction behavior is application-owned and manifest-v1 path meaning
changes implicitly by evidence version.

After: evidence owns one transactional bundle library, explicit v2 relative paths,
and strict documented v1 compatibility dispatch.

#### Migration Notes

- New writers emit manifest v2 only; v1 is read-only compatibility.
- Preserve T040 collision/cleanup behavior and public workbench command semantics.
- Never normalize a legacy absolute path by simply trusting or canonicalizing it.

#### Misinterpretations To Prevent

- Wrong: if a v1 path exists, accept it. Correct: dispatch by documented artifact
  kind/version and validate containment.
- Wrong: store an export-root-relative path in v2. Correct: store bundle-relative.
- Wrong: write into final directory and put manifest last. Correct: publish a
  complete staged directory atomically.

#### Invariants

- A visible committed bundle is complete and manifest-valid.
- Existing final bundles are never clobbered.
- Every v2 path is normalized, validated, and bundle-relative.
- Legacy path handling is exact-version dispatch, never existence-based guessing.
- Reader errors retain manifest/artifact/path/source context.
