### T055 — Add Release SBOM Provenance And Signing

#### Objective

Generate reviewed hash-bound SBOM/provenance and optional approved signatures for
the exact T035 artifacts, without registry/release publication or credential
exposure in ordinary build jobs.

#### Scope

- Supply-chain implementation portion of RS-010.
- Add pinned tooling/actions that consume immutable T035 artifacts/checksums and
  emit an approved SBOM format plus provenance/attestations bound to commit,
  workflow, platform/features, and artifact hashes.
- Add optional signing only after identity/key mechanism approval; isolate secrets
  in a protected environment/job.
- Extend release manifest with SBOM/provenance/signature references and verification
  commands.
- Verify generated metadata against artifacts before handoff to T056.

#### Out of Scope

- Do not publish crates/wheels/releases; T056 owns mutation.
- Do not invent/sign with a maintainer identity or configure secrets without
  explicit authority.
- Do not generate SBOM from a different build/lockfile than packaged artifacts.
- Do not add runtime telemetry/security scanners unrelated to release artifacts.

#### Blocked By

T002, T003, T035.

#### Why It Is Blocked

Policy/toolchain and complete inspected artifacts must exist before supply-chain
metadata can bind to the correct inputs.

#### Related Code

- T035 release manifest/checksums/artifact workflow.
- T002 cargo-deny/dependency policy and T003 pinned workflow conventions.
- T004 release/signing policy.

#### Implementation Touchpoints

- Read first: official approved tool/action docs, supported formats, keyless/OIDC
  availability, release permissions, and artifact manifest.
- Edit first: supply-chain workflow job/config, manifest schema, verification docs.
- Symbols to search: artifact hashes, commit SHA, lockfile, workflow permissions,
  attest/sign/SBOM, environment secrets.
- Required structural changes: build jobs remain credential-free; signing job
  consumes already-built immutable artifacts only.
- Do not edit: product code/package contents/versions.
- Verify in order: SBOM schema/content/hash association, provenance verification,
  signature verification if enabled, workflow permissions, failure control.
- Stop and ask: before selecting signing identity, enabling OIDC/attestation,
  creating protected environment, or accessing any secret.

#### Implementation Details

Each release manifest artifact entry gains checksum plus SBOM/provenance/signature
identifiers. Metadata generator input is downloaded by checksum and cannot rebuild/
substitute artifacts. Pin tool/action versions/SHAs and record versions.

SBOM includes Rust/Python/native dependencies/features/platform and licence/source
metadata as available. Provenance binds repository/ref/commit/workflow/run/builder/
materials and output digests. Signing is optional until approved; unsigned is
reported truthfully, not a failed fake signature.

#### Before / After

Before: artifacts have checksums but no component/provenance/signing evidence.

After: verifiers can bind each inspected artifact to its build/material metadata.

#### Migration Notes

- T056 publishes only artifacts whose manifest metadata verifies.
- Changing build inputs requires regenerating all metadata, never patching hashes.

#### Misinterpretations To Prevent

- Wrong: generate SBOM from source generally. Correct: bind exact artifact build.
- Wrong: expose signing credentials to build/PR jobs. Correct: protected isolated
  post-build job.
- Wrong: call unsigned signed. Correct: optional state explicit.

#### Invariants

- Metadata hashes match immutable T035 artifacts/commit.
- Build jobs have no signing/publication credentials.
- Tools/actions pinned and permissions minimal.
- Verification commands work from released files only.

#### Acceptance Criteria

- [ ] Every approved artifact has verified SBOM/provenance references.
- [ ] Optional signatures verify or are explicitly absent pending approval.
- [ ] Release manifest binds commit/materials/artifact hashes.
- [ ] Protected permissions/secrets are correctly isolated.
- [ ] Failure prevents T056 publication handoff.

#### Testing Guidance

- Verify generated metadata/signatures on non-published artifacts.
- Inject missing/mismatched checksum and assert job failure.
- No registry credentials or dry-run publication.

#### Agent Handoff Context

T056 is the only publishing task and must consume this verified manifest.

## Final Notes

- Recommended order: SBOM, provenance, optional signing, manifest verification.
- Human review: formats/tools/identity/environment.
- Risk: metadata generated before final packaging can bind wrong bytes; consume
  immutable T035 outputs only.
