### T013 — Create Normative Analysis Binning

#### Objective

Create `rawscope-analysis` as the dependency-light owner of normative density
binning and checked summary math, and move T036's already-correct axis contract
without combining another behavior fix.

#### Scope

- Primary audit findings: RS-070 and RS-081; structural owner for the T036 axis
  correction.
- Add workspace crate `crates/rawscope-analysis` depending on `rawscope-core` and
  `rawscope-data`, but not WGPU, Serde, UI, or evidence formatting.
- Inherit approved workspace legal/package metadata, set `publish = false`, and
  use `version + path` for internal dependencies per T001.
- Move CPU density/binning semantics from render into
  `analysis::density::binning` and make it the documented normative oracle.
- Move/delegate T036's bounded scatter/timeline axis implementation and tests into
  `analysis::axis` without changing its proven output.
- Replace panicking zero/unbounded public summary options with validated bounded
  config and typed errors.
- Publish WGSL parity vectors derived from the same boundary cases, without code
  generation macros.

#### Out of Scope

- Do not move cohorts, missingness, diff, selection, or evidence yet.
- Do not add GPU execution or shader ownership to analysis.
- Do not build a generic plotting/axis library.
- Do not claim CPU/GPU parity until adapter tests in later tasks pass.

#### Blocked By

T005, T036.

#### Why It Is Blocked

Normative math must consume checked core types and the tactical axis correction
rather than reimplementing the bug during extraction.

#### Related Code

- `crates/rawscope-render/src/density_reference.rs` — CPU scatter/timeline binning.
- `crates/rawscope-render/src/view_axes.rs` — current looping/tick formatting.
- `crates/rawscope-render/src/view_summaries.rs` and aggregate/missingness configs.
- `crates/rawscope-render/src/shaders/{scatter,timeline}_density.wgsl`.
- Existing density, axes, timeline viewport, and GPU parity tests.

#### Implementation Touchpoints

- Read first: every CPU/WGSL bin formula, out-of-range rule, axis option/caller,
  current tests at boundaries, and report findings RS-053-RS-075 for consumers.
- Edit first: new private crate manifest/facade, `density/binning.rs`, checked
  summary config, then move T036 axis modules and compatibility re-exports.
- Symbols to search: `scatter_density`, `timeline_density`, `axis_ticks`,
  `while value`, `as f32`, `grid_width`, `tick_count`, and range multiplication.
- Required structural changes: thin `lib.rs`; vertical density/axis modules;
  shared declarative test vectors, not a macro DSL.
- Do not edit: workbench UI rendering or WGSL formulas beyond consuming agreed
  constants/vectors in a follow-through change.
- Verify in order: pure analysis boundary tests, existing density/axes tests via
  compatibility paths, format, workspace check.
- Stop and ask: if existing public out-of-range inclusion semantics are intended
  to differ between density and summary, or if a requested tick count exceeds
  the approved maximum.

#### Implementation Details

Expose explicit results:

```rust
pub enum BinPlacement {
    BeforeDomain,
    InDomain(BinIndex),
    AfterDomain,
}

pub fn bin_f64(
    value: f64,
    domain: F64Domain,
    bins: NonZeroU32,
) -> Result<BinPlacement, BinningError>;

pub fn bin_u64(
    value: u64,
    domain: U64Range,
    bins: NonZeroU32,
) -> Result<BinPlacement, BinningError>;
```

Document inclusivity: the lower bound maps to bin 0; the upper endpoint follows
the range's explicit inclusive/exclusive contract; before/after never converts a
huge offset to a smaller integer. Timeline multiplication uses u128 or a proven
quotient/remainder decomposition, mirrored in WGSL-compatible vectors.

Preserve T036's validated axis options:

```rust
pub struct AxisOptions {
    max_tick_count: NonZeroU16,
    target_tick_count: NonZeroU16,
}
```

Move its bounded implementation/vectors unchanged. Summary configs use the same
checked `GridSize`/bin limits and return errors rather than assert/panic.

#### Before / After

Before: T036 axes are correct but semantic binning/summary formulas remain
duplicated/render-owned and public summary helpers panic on config.

After: one analysis crate owns bounded numerical truth and render/GPU code has a
single oracle plus edge vectors.

#### Migration Notes

- Preserve temporary `rawscope-render` re-exports to migrate workbench/tests in
  stages; mark the analysis crate as the owner in rustdoc.
- Do not change visual tick styling; only positions/values/contracts move.
- Any intended CPU/GPU tolerance must be named by formula/domain, never global.

#### Misinterpretations To Prevent

- Wrong: centralize copied formulas in render. Correct: analysis owns semantic
  math; render consumes results.
- Wrong: rewrite T036 axis math during the move. Correct: move/delegate the tested
  implementation and vectors byte/behavior-identically.

#### Invariants

- Every public bin/tick operation remains within validated bounds.
- CPU bin placement is the normative semantic contract.
- Before/after-domain values are classified consistently across consumers.
- Analysis has no GPU/UI/Serde/evidence dependency.
- Compatibility re-exports do not duplicate implementation.
