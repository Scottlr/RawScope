### T006 — Add A Typed Rectangular DatasetStore

#### Objective

Introduce one generation-owned, typed, rectangular dataset store that separates
raw source evidence from normalized analytical values and prevents callers from
constructing inconsistent rows, columns, IDs, or validity state.

#### Scope

- Primary audit findings: RS-021, RS-022, RS-037, RS-042, and RS-047. The
  three-state cell model is the storage prerequisite for RS-040; T014 owns filter
  semantics.
- Add `rawscope-data::store` as the owner of schema, chunks, typed cells,
  generation, stable IDs, and memory accounting contracts.
- Reject duplicate column names at schema construction and assign stable
  `ColumnId`s by validated schema order.
- Make `DatasetEvidenceKey` constructible only by validating a stable `ColumnId`
  against one `DatasetStore` generation; expose read-only column/index accessors
  so the descriptor cannot be rebound or lie about its table.
- Model valid, missing, and invalid cells distinctly; retain raw source values
  separately from normalized values used by analysis.
- Replace publicly mutable `LoadedSourceTable`/`LoadedColumnarDataset` contracts
  with read-only compatibility views over `DatasetStore` during migration.
- Validate contiguous `RowId`s and rectangular chunk shapes once on append.

#### Out of Scope

- Do not implement streaming adapters or profiling algorithms; T009 owns them.
- Do not move filters, projections, missingness, diff, or evidence into the store.
- Do not add WGPU, Serde, UI, filesystem export, or a generic dataframe API.
- Do not retain every source column by default without an explicit policy/budget.

#### Blocked By

T005.

#### Why It Is Blocked

The store needs checked row/column IDs, dimensions, and owner-issued generation
tokens from core before it can make its invariants private.

#### Implementation Details

Use explicit source and cell state contracts:

```rust
pub enum SourceValue {
    Utf8(Arc<str>),
    Bool(bool),
    I64(i64),
    U64(u64),
    F64(f64),
    TimestampMicros(i64),
}

pub enum CellState<T> {
    Value(T),
    Missing,
    Invalid(InvalidCell),
}

pub enum CellRef<'a> {
    Value(&'a SourceValue),
    Missing,
    Invalid(&'a InvalidCell),
    NotRetained(SourceUnavailableReason),
}
```

`InvalidCell` carries a bounded reason/category and source location, not a copy
of an unbounded payload. Raw values needed for evidence are stored through a
`RetainedSourceValue` contract chosen by ingestion policy; normalized analytical
columns use typed arrays plus missing/invalid bitmaps.

The primary API should have this shape:

```rust
pub struct DatasetStore { /* private generation-owned state */ }

impl DatasetStore {
    pub fn generation(&self) -> DatasetGeneration;
    pub fn schema(&self) -> &DatasetSchema;
    pub fn row_count(&self) -> u64;
    pub fn chunks(&self) -> impl ExactSizeIterator<Item = DatasetChunkRef<'_>>;
    pub fn source_value(&self, row: RowId, column: ColumnId)
        -> Result<CellRef<'_>, DatasetAccessError>;
}

pub struct DatasetStoreBuilder { /* private */ }

impl DatasetStoreBuilder {
    pub fn new(
        identity: DatasetIdentity,
        schema: DatasetSchema,
        budget: DatasetMemoryBudget,
    ) -> Result<Self, DatasetStoreError>;
    pub fn append_chunk(&mut self, chunk: DatasetChunk) -> Result<(), DatasetStoreError>;
    pub fn finish(self) -> Result<DatasetStore, DatasetStoreError>;
}
```

Append validates column count, equal column lengths, row-ID continuity, schema
kinds, and checked row/memory totals before mutation. Build the next chunk's
admission result first, then commit all columns together so failure cannot leave
a ragged store.

`DatasetEvidenceKey::validate(store, column_id)` returns a descriptor carrying the
store generation, stable column ID, and table-owned uniqueness-index handle. Its
fields are private; crossing to another dataset generation requires revalidation.

#### Before / After

Before: public vectors can be mutated into ragged tables, duplicate names are
ambiguous, invalid numerics collapse into missing values, and the columnar API
exposes metadata for arrays it does not retain.

After: adapters emit one checked store contract; row/column identity, validity,
raw evidence, normalized values, and chunk ownership are explicit and read-only.

#### Migration Notes

- Keep temporary deprecated read-only `Loaded*` views only where needed to
  migrate one downstream crate at a time; do not maintain two mutable stores.
- Preserve current row-order identity for existing artifacts.
- A source value unavailable under retention policy must return an explicit
  unavailable state, never an empty string or dropped row.

#### Misinterpretations To Prevent

- Wrong: rename current chunk metadata to `DatasetStore`. Correct: retain actual
  typed chunk data and expose real chunk iteration/lifetimes.
- Wrong: use `Option<T>` for both missing and invalid. Correct: three states are
  observable and policy-controlled.
- Wrong: add a dataframe query API. Correct: this is bounded storage/iteration,
  not a query engine.

#### Invariants

- Schema names are unique and map stably to `ColumnId`.
- Every committed chunk is rectangular and belongs to one dataset generation.
- `RowId` maps to exactly one stable row for the generation.
- Evidence-key descriptors are generation/table-bound and cannot be created from
  a name/index pair alone.
- Raw evidence values are never overwritten by normalization.
- Memory admission is checked before mutating the store.

#### Acceptance Criteria

- [ ] `rawscope-data::store` exists with a thin public facade.
- [ ] Duplicate columns, ragged chunks, type mismatch, and row overflow return
      contextual errors.
- [ ] Valid/missing/invalid cells and raw/normalized values are distinguishable.
- [ ] Evidence-key descriptors cannot be fabricated or reused across generations.
- [ ] `Loaded*` compatibility surfaces are read-only views or removed after
      migrated callers; no second mutable table remains.
- [ ] Store/local-import/evidence-key tests and workspace check pass.

#### Testing Guidance

- Add `crates/rawscope-data/tests/dataset_store.rs` with table-driven invalid
  schema/chunk cases, atomic failed append, stable row lookup, and budget failure.
- Prove that invalid and missing values remain different and raw spelling is
  preserved after normalization.
- No large fixture or smoke app; deterministic small chunks are sufficient.

#### Agent Handoff Context

T007/T008 adapt real source formats; T009 makes construction incremental;
T013-T017 consume immutable store generations. Keep storage concepts source-
truthful and avoid analytical conveniences in this crate.

## Final Notes

- Recommended order: schema/IDs, cell state, chunk validation, builder atomicity,
  compatibility views, call-site migration.
- Human review: retained-source policy and whether non-contiguous external keys
  are separate from internal `RowId`.
- Risk: a compatibility view that clones all rows would preserve the current
  memory bug; it must borrow or be temporary and explicitly costly.
