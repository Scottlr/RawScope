### T030 — Publish One Active Workbench Generation And Cached UI

#### Objective

Replace independently mutated app-visible dataset/render/selection state with one
validated immutable active generation swap, and derive revision-cached borrowed
UI projections plus persistent typed degraded state through a thin winit facade.

#### Scope

- Primary audit findings: RS-112 and RS-116; controller ownership findings are
  handled by T049/T050 and tactical atomicity by T041/T029.
- Define `ActiveWorkbenchGeneration` containing matching dataset, cohort,
  projection, settled render, selection/inspection, and identity generations.
- Prepare and validate a complete candidate from T028/T029/T050 controller
  results, then replace active state with one `Arc` swap on the event thread.
- Keep transition/job/export/controller operational state separate; it may refer
  to active IDs but cannot mutate the immutable aggregate.
- Add small `UiProjection` caches keyed by active generation plus controller view
  revisions; borrow/share large strings, vectors, profiles, and summaries instead
  of cloning them every frame.
- Preserve concise persistent degraded/error state with typed recovery action;
  successful unrelated work must not silently clear it.
- Reduce `WorkbenchApp` to winit lifecycle, event routing, candidate commit, and
  frame composition over controller views.

#### Out of Scope

- Do not split controllers (T049/T050), change scheduling (T029), or refix atomic
  demo/filter/projection transitions (T041).
- Do not move domain logic into `WorkbenchApp` or the UI cache.
- Do not add a generic store/ECS/message bus/global mutex.
- Do not redesign the visual theme or add product features.
- Do not make export completion part of analytical active truth.

#### Blocked By

T028, T029, T041, T049, T050.

#### Why It Is Blocked

One active aggregate is only meaningful after dataset admission, settled render
publication, tactical atomic changes, and final controller owners all exist.

#### Related Code

- `WorkbenchApp` fields and action-fragmented `app_*` modules after T050.
- T028 admitted dataset generation and T029 settled render generation.
- Current UI functions cloning catalogue/profile/summary/status structures.
- Error/degraded status and retry actions from T027/T043/T049/T050.

#### Implementation Touchpoints

- Read first: final controller views, every frame-time clone, all active-state
  writes, generation checks, degraded-error clearing, and render frame inputs.
- Edit first: active candidate/validation type, single commit path, then cached UI
  projections and facade field deletion.
- Symbols to search: `active_*`, dataset/cohort/projection/selection revisions,
  `.clone()` in frame/UI paths, error reset, and direct sibling state reads.
- Required structural changes: one immutable aggregate and domain-specific cache
  entries; no giant mutable `UiState` mirror.
- Do not edit: evidence schemas, job internals, GPU algorithms, or data storage.
- Verify in order: candidate mismatch/old-or-new tests, error persistence, cache
  invalidation/borrow tests, workbench behavior tests, format, workspace.
- Stop and ask: if a controller exposes mutable state needed by UI or if a field
  cannot be assigned to active truth versus operational transition state.

#### Implementation Details

```rust
pub struct ActiveWorkbenchGeneration {
    pub id: WorkbenchGenerationId,
    pub dataset: Arc<DatasetGeneration>,
    pub cohort: Arc<CohortSnapshot>,
    pub projection: Arc<ProjectionSnapshot>,
    pub render: Arc<SettledRenderGeneration>,
    pub selection: Arc<SelectionSnapshot>,
}

pub struct WorkbenchState {
    active: Option<Arc<ActiveWorkbenchGeneration>>,
    transition: WorkbenchTransition,
    degraded: Option<DegradedState>,
    ui_cache: UiProjectionCache,
}
```

`ActiveWorkbenchGeneration::try_new` verifies every nested dataset/cohort/view/
field/selection token and invariant. The event handler receives a fully prepared
candidate and performs one assignment to `active`; it does not update component
fields piecemeal. T041/T029 failures retain the prior `Arc`.

UI projections contain small formatted values and `Arc`/borrowed references to
large immutable data. Cache keys include the active ID and only operational view
revisions that affect the projection. Frame rendering reads one captured active
`Arc`, so a frame cannot observe mixed generations. Errors remain until the owning
retry succeeds or the user explicitly dismisses a dismissible classification.

#### Before / After

Before: app-visible components can be updated separately and UI rebuilds/clones
large projection data each frame.

After: one immutable generation is the frame truth, UI work is revision-cached,
and operational/degraded state remains explicit around it.

#### Migration Notes

- Migrate one candidate path at a time but remove component mirrors in the same PR
  once the single aggregate owns them.
- Preserve T041/T029 old-or-new behavior tests and current UI output.
- Export status is projected beside active truth, not embedded into it.

#### Misinterpretations To Prevent

- Wrong: add aggregate fields while retaining mutable mirrors. Correct: one owner.
- Wrong: cache a cloned whole dataset for UI. Correct: borrow/share immutable data
  and cache only presentation work.
- Wrong: clear all errors on any success. Correct: clear only matching recovery.

#### Invariants

- A frame captures one complete matching `ActiveWorkbenchGeneration`.
- No component-level mutable mirror can diverge from active truth.
- Candidate failure leaves active unchanged.
- UI cache invalidation is revision-driven and cannot become domain truth.
- Degraded/errors remain typed, visible, and owner-cleared.

#### Acceptance Criteria

- [ ] Dataset/cohort/projection/render/selection publish through one validated Arc
      assignment and no mutable component mirrors remain.
- [ ] Generation-mismatch and partial candidate paths retain prior active state.
- [ ] Large frame-time clones are replaced by borrowed/shared revision-cached views.
- [ ] Degraded/error state persists and clears only through matching recovery.
- [ ] `WorkbenchApp` is a thin lifecycle/router/composer facade.
- [ ] Focused atomic/cache/error/workbench tests, format, and workspace checks pass.

#### Testing Guidance

- Construct mismatched candidates for each token and assert the exact prior Arc
  remains; do not test implementation field order.
- Instrument cache builders to prove revision reuse/invalidation without timing.
- No live-window/screenshot smoke tests.
