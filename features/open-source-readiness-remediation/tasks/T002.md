### T002 — Pin Toolchain Lints And Supply-Chain Policy

#### Objective

Make compiler, lint, licence, source, advisory, and duplicate-dependency policy
reproducible and clean on a deliberately selected toolchain.

#### Scope

- Primary audit findings: RS-004, RS-005, RS-006, RS-008, RS-013, and RS-014.
- Select and document an MSRV independently from the contributor stable
  toolchain; do not treat the audit host's Rust 1.95.0 as an automatic MSRV.
- Add `rust-toolchain.toml` with `rustfmt` and `clippy` components and add
  `rust-version` to workspace package metadata.
- Fix the current `while-let-on-iterator` Clippy failure without changing Parquet
  behavior.
- Add `deny.toml` with reviewed licences, sources, bans/duplicates, and advisory
  policy.
- Resolve advisory roots through compatible direct dependency updates where
  possible; otherwise add narrow owner/expiry/reachability-tracked exceptions.

#### Out of Scope

- Do not add CI workflows; T003 consumes this policy.
- Do not force transitive upgrades merely to produce one version of every crate.
- Do not add broad lint allows or suppress all advisories from a dependency tree.
- Do not introduce Cargo features; T031 owns build-cost design after crate moves.

#### Blocked By

None.

#### Why It Is Blocked

Policy selection can proceed independently, but the implementing agent must stop
if no candidate MSRV satisfies locked direct dependencies or an advisory lacks
both an upgrade and a justifiable time-bounded exception.

#### Implementation Touchpoints

- Read first: all manifests, `Cargo.lock`, upstream release/advisory notes for
  each affected direct root, and the approved platform matrix from maintainers.
- Edit first: the local Clippy violation, then toolchain/MSRV, then dependency
  policy and targeted lockfile resolution.
- Symbols/keys to search: `while let Some(batch)`, `arrow`, `parquet`, `winit`,
  `wgpu`, `[advisories]`, `[licenses]`, `[bans]`, and `[sources]`.
- Required structural changes: `rust-toolchain.toml`; `deny.toml`; optional
  `rustfmt.toml`/`clippy.toml` only for deliberate non-default policy.
- Do not edit: public APIs, feature flags, workflows, evidence schemas, or UI.
- Verify in order: format, all-target/all-feature check, Clippy with
  `-D warnings`, Rustdoc with `-D warnings`, `cargo deny check`, and an MSRV
  check using the declared compiler.
- Stop and ask: if choosing/updating the MSRV changes the support promise, a
  dependency update needs a public API migration, or an exception cannot name
  an owner and expiry date.

#### Implementation Details

The toolchain file should have this shape with approved concrete versions:

```toml
[toolchain]
channel = "<approved contributor stable>"
profile = "minimal"
components = ["rustfmt", "clippy"]
```

The MSRV is a separate `rust-version = "<validated minimum>"`. Validate it
against every workspace target that is expected to support that compiler. The
policy must say how and when MSRV can be raised.

`deny.toml` must explicitly configure:

- allowed licence expressions and reviewed exceptions;
- crates.io/Git-only source policy;
- multiple-version rules with named, measured exceptions;
- vulnerability, unmaintained, unsound, and yanked handling;
- exception owner, reason/reachability, upstream issue, and expiry/review date.

Prefer targeted direct-root upgrades and inspect `cargo tree -i <crate>` before
changing lockfile families. If a transitive advisory is unreachable in RawScope
runtime, that may justify a temporary exception, not a permanent wildcard.

The Parquet lint fix is a behavior-preserving `for batch_result in reader`
iteration. Preserve source error context and exact batch accumulation behavior.

#### Before / After

Before: compiler/lint behavior depends on contributor state, Clippy fails, and
`cargo deny check` has no repository policy.

After: a documented MSRV/stable pair produces deterministic formatting/lints,
all policy phases pass or contain narrow expiring exceptions, and the lockfile
change is attributable to reviewed direct roots.

#### Migration Notes

- Commit `Cargo.lock` changes caused by manifest updates and explain each direct
  root; do not run indiscriminate major upgrades.
- Existing behavior and public API should remain unchanged.
- T003 must use exactly these toolchain and policy commands rather than inventing
  a second CI-only policy.

#### Misinterpretations To Prevent

- Wrong: pin the audit compiler and call it MSRV. Correct: find and validate a
  minimum separately from the contributor stable toolchain.
- Wrong: silence advisories with an unbounded ignore list. Correct: exceptions
  are narrow, owned, justified, and expiring.
- Wrong: ban every duplicate version. Correct: align direct families where safe
  and record ecosystem-driven duplicates after measuring them.

#### Invariants

- `cargo clippy --workspace --all-targets --all-features -- -D warnings` passes.
- Policy exceptions cannot omit owner, reason, or review/expiry date.
- Dependency changes remain at the narrowest direct roots.
- No lint configuration hides real correctness failures globally.
