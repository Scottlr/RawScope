### T005 — Introduce Checked Core Domain Contracts

#### Objective

Make foundational invalid ranges, dimensions, identities, revisions, and visual
selections unrepresentable or explicitly fallible while keeping
`rawscope-core` dependency-free and its facade narrow.

#### Scope

- Primary audit findings: RS-016 through RS-020 and RS-023.
- Privatize fields on range/grid/selection contracts and replace panicking public
  construction with domain-specific `Result` constructors.
- Separate observed f32/f64 extents that may be singletons from non-empty f32/f64
  display domains.
- Add stable `ColumnId` alongside `RowId`, a dependency-free
  `PositiveRowLimit`, and checked count/size types where units would otherwise mix.
- Replace contradictory `VisualSelectionKind + geometry` state with one validated
  geometry enum whose variant is the discriminator, plus coherent accessors.
- Provide owner-mintable typed generation tokens without Serde/global state.

#### Out of Scope

- Do not add Serde, WGPU, Arrow, filesystem, UI, evidence, or session dependencies.
- Do not move filters, analysis, or evidence implementations into core.
- Do not add a generic ID/maths framework or macro DSL.
- Do not preserve invalid public struct literals merely for source compatibility;
  provide a deliberate fallible migration path instead.

#### Blocked By

None.

#### Why It Is Blocked

This is the domain foundation for data, analysis, GPU limits, and job IDs. It can
start immediately but must inventory every public struct-literal call site before
privatizing fields.

#### Related Code

- `crates/rawscope-core/src/range.rs` — `F32Range`, `U64Range`.
- `crates/rawscope-core/src/density.rs` — `GridSize`, `DensityGrid`, count math.
- `crates/rawscope-core/src/row.rs` — `RowId`.
- `crates/rawscope-core/src/selection.rs` — IDs, geometry, kind discriminator,
  and sorted row-ID contract.
- `crates/rawscope-core/src/lib.rs` — public facade.
- Struct-literal consumers throughout data/render/workbench tests.

#### Implementation Touchpoints

- Read first: all core modules/tests and every `rg` call site for exported core
  structs, especially public field access and `new` calls.
- Edit first: focused domain modules; keep `lib.rs` to declarations/re-exports.
- Symbols to search: `F32Range {`, `U64Range {`, `GridSize {`,
  `VisualSelection {`, `VisualSelectionKind`, `SelectionId`, `ViewId`, and
  unchecked multiplication.
- Required structural changes: split `range.rs` only if observed/display domains
  cannot remain coherent together; add `column.rs` and `generation.rs` as
  domain owners, not `types.rs`.
- Do not edit: serializers/wire schemas directly; downstream migrations should
  use accessors/constructors and preserve artifact shapes.
- Verify in order: focused core tests, downstream package tests for migrated
  contracts, format, then workspace check.
- Stop and ask: if an external API must keep infallible construction or a wire
  format currently depends on Rust field visibility rather than an adapter.

#### Implementation Details

Use distinct checked concepts, for example:

```rust
pub struct ObservedF32Extent { min: f32, max: f32 } // min <= max, finite
pub struct ObservedF64Extent { min: f64, max: f64 } // min <= max, finite
pub struct F32Domain { min: f32, max: f32 }         // min < max, finite
pub struct F64Domain { min: f64, max: f64 }         // min < max, finite
pub struct GridSize { width: NonZeroU32, height: NonZeroU32 }
pub struct ColumnId(u32);
pub struct PositiveRowLimit(NonZeroU64);
```

Constructors return local errors with values/units:

```rust
impl GridSize {
    pub fn try_new(width: u32, height: u32) -> Result<Self, GridSizeError>;
    pub fn bin_count(self) -> Result<usize, GridSizeError>;
}
```

Display expansion from a singleton `ObservedF32Extent` belongs in an explicit
presentation function returning the chosen expansion; never fabricate a domain
inside the observed data contract.

Selection should have one source of truth:

```rust
pub enum VisualSelectionGeometry {
    Scatter(ScatterSelectionGeometry),
    Timeline(TimelineSelectionGeometry),
}

impl VisualSelection {
    pub fn try_new(
        id: SelectionId,
        view_id: ViewId,
        geometry: VisualSelectionGeometry,
        sorted_row_ids: Vec<RowId>,
    ) -> Result<Self, VisualSelectionError>;
}
```

Validate strict sorting/uniqueness once. `kind()` derives from geometry.
Generation support should be a small typed counter/token pair parameterized by
an owner marker, with token construction private to the counter. Owners retain
the counter; consumers receive comparable/copyable tokens only.

#### Before / After

Before: callers can create zero grids, inverted ranges, contradictory selection
kinds, unsorted row IDs, and arbitrary revisions; some public constructors panic.

After: invalid external input returns contextual domain errors, observed versus
display domains are explicit, and owner-issued identities/generations cannot be
silently fabricated through public fields.

#### Migration Notes

- Migrate call sites package-by-package using accessors and `TryFrom`; do not add
  temporary public fields plus setters.
- Preserve evidence/session bytes through their existing serializers; Rust API
  source compatibility may intentionally break before public release.
- Use checked conversion at allocation/dispatch boundaries; never `unwrap` a
  recoverable validation result in production.

#### Misinterpretations To Prevent

- Wrong: make all range equality invalid. Correct: observed singleton extents are
  valid; only non-empty display domains require strict width.
- Wrong: put Serde derives on core types for convenience. Correct: wire adapters
  live in session/evidence crates.
- Wrong: introduce a universal string ID. Correct: use domain-specific IDs and
  validated non-blank identifiers only where strings are externally meaningful.

#### Invariants

- `rawscope-core` has zero dependencies.
- No public constructor panics for recoverable input.
- Grid/bin arithmetic is checked before conversion/allocation.
- Selection kind, geometry, IDs, and sorted unique row IDs cannot contradict.
- Standard derives may be used; no business logic is macro-generated.

#### Acceptance Criteria

- [ ] Core domain fields with invariants are private and have read-only accessors.
- [ ] Observed singleton extents and non-empty display domains are separate.
- [ ] Grid/count construction and multiplication return typed errors.
- [ ] `ColumnId` and owner-minted generation tokens exist with clear units/owners.
- [ ] `VisualSelection` has one geometry source of truth and validates row IDs.
- [ ] Core/downstream focused tests and workspace check pass.

#### Testing Guidance

- Add table-driven tests for zero/inverted/non-finite/adjacent/singleton ranges,
  dimension overflow, and unsorted/duplicate selection rows.
- Tests should assert error variants and preserved valid boundary behavior.
- Keep tiny local invariant tests beside modules; broader API migration tests stay
  in existing package integration suites. No smoke app.

#### Agent Handoff Context

This task intentionally pays source-migration cost before publication so every
later crate receives trusted foundational inputs. Resist putting higher-level
convenience into core; T006/T013/T027 own domain-specific state and counters.

## Final Notes

- Recommended order: ranges/dimensions, row/column IDs, selection geometry,
  generation tokens, downstream call-site migration.
- Human review: naming of observed versus display domains and whether any current
  Rust API is already externally committed.
- Risk: evidence serializers may currently read public fields directly; migrate
  through accessors without changing their bytes.
