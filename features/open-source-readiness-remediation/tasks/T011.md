### T011 — Split Bounded Session Contracts

#### Objective

Create a dependency-light Rust owner for the versioned session wire contract so
manifests can be parsed, normalized, and bounded without pulling Arrow/Parquet or
persisting platform-dependent values.

#### Scope

- Primary audit findings: RS-118 through RS-122.
- Add workspace crate `crates/rawscope-session-contracts` depending only on
  `rawscope-core`, Serde, and Serde JSON.
- Inherit approved workspace package/legal metadata, set `publish = false`, and
  express every internal workspace dependency with compatible `version + path`.
- Move session v1 wire structs, format/view enums, profile identifier parsing,
  schema constants, and pure validation into the new crate.
- Change persisted row limits from `usize` to `u64`, bound them by a named schema
  maximum, and convert checked at application allocation boundaries.
- Normalize identifier-like strings at construction while deliberately preserving
  display text according to a documented policy.
- Bound manifest reads by metadata plus a limited reader before JSON allocation.
- Replace ad-hoc URI substring checks and vague path errors with schema-defined
  local-path semantics and role-specific context.

#### Out of Scope

- Do not load datasets, inspect profiles, open WGPU, or launch the workbench from
  the contracts crate.
- Do not add remote URI schemes or a general URI parser.
- Do not create session v2 merely to avoid migrating `usize`; preserve v1 wire
  field names and accept compatible old numeric values.
- Do not add Serde to `rawscope-core`.

#### Blocked By

T005.

#### Why It Is Blocked

The contract crate needs checked IDs/non-blank identifiers and fixed domain
limits from core, while remaining independent of the data implementation.

#### Related Code

- `crates/rawscope-session/src/manifest.rs` — wire models, parser, schema
  constants, validation errors.
- `crates/rawscope-session/src/resolved_session.rs` — bounded file IO and path
  resolution.
- `crates/rawscope-session/Cargo.toml` — unnecessary `rawscope-data` dependency.
- `crates/rawscope-data/src/dataset_profile.rs` — profile ID/parsing currently
  imported by session.
- `crates/rawscope-session/tests/session_manifest.rs`, `docs/schemas/session-v1.md`,
  and Python models/manifest tests.

#### Implementation Touchpoints

- Read first: every Rust/Python manifest fixture, CLI/session resolver call site,
  profile-ID consumer, and compatibility documentation.
- Edit first: new crate manifest/facade and pure contract modules, then make
  `rawscope-session` an IO/resolution adapter over those contracts.
- Symbols to search: `RawScopeSessionManifestV1`, `SessionDatasetV1`,
  `DatasetProfileId`, `usize`, `trim`, `contains("://")`, and `read_to_string`.
- Required structural changes: `manifest.rs`, `identifier.rs`, `limits.rs`, and
  `error.rs` under the contracts crate; no `types.rs` dumping ground.
- Do not edit: data profile hint implementation beyond importing the lightweight
  ID; Python implementation belongs to T012.
- Verify in order: contract unit/integration fixtures, session resolver tests,
  data/profile tests, format, workspace check.
- Stop and ask: if whitespace is semantically significant for any identifier,
  if non-local URIs are intended in schema v1, or if the maximum manifest/row
  limit requires a product decision.

#### Implementation Details

Keep in-memory validated types separate from Serde wire structs where necessary:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
struct SessionDatasetV1Wire {
    path: PathBuf,
    format: SessionDataFormat,
    display_name: Option<String>,
    limit: Option<u64>,
    evidence_key: Option<String>,
}

pub struct SessionDatasetV1 {
    path: LocalDatasetPath,
    format: SessionDataFormat,
    display_name: Option<DisplayName>,
    limit: Option<PositiveRowLimit>,
    evidence_key: Option<EvidenceKeyName>,
}
```

The unchanged v1 view wire owns optional `profile` on each scatter/timeline view
variant; it normalizes to `DatasetProfileId` there, never on `SessionDatasetV1`.
Preserve `#[serde(default, skip_serializing_if = "Option::is_none")]` on the
existing optional dataset/view fields and `deny_unknown_fields` behavior.

Parsing deserializes the bounded wire input, validates/normalizes once, then
returns the opaque validated manifest. Serialization converts back explicitly so
v1 field names/values remain stable. Use domain constants with units such as
`MAX_SESSION_MANIFEST_BYTES` and `MAX_SESSION_ROW_LIMIT` near `limits.rs`.

`load_session_manifest` checks file metadata, rejects oversized inputs, and reads
at most `MAX + 1` bytes so changing files or missing metadata cannot bypass the
bound. Errors preserve `io::Error`/`serde_json::Error` sources plus file role.

`rawscope-session` should depend on contracts, not `rawscope-data`. The workbench
maps a validated profile ID to data-owned profile hints after resolution.

#### Before / After

Before: parsing one manifest builds Arrow/Parquet transitively, whitespace can
pass validation unchanged, reads are unbounded, and `usize` bytes vary by target.

After: a small crate owns stable bounded wire semantics, session IO is contextual,
and concrete profile/data loading remains outside the contract layer.

#### Migration Notes

- Preserve the artifact kind/schema version and all valid v1 JSON field names.
- Existing numeric row-limit JSON remains valid when within the new maximum.
- Re-export contract types temporarily from `rawscope-session` if needed, with a
  documented removal point before publication.

#### Misinterpretations To Prevent

- Wrong: move concrete profile hints into the contract crate. Correct: only
  stable profile identity/parsing belongs there.
- Wrong: add Serde derives to core IDs. Correct: explicit contract wire adapters
  translate them.
- Wrong: check metadata only. Correct: also bound the actual read to handle races.

#### Invariants

- `rawscope-session-contracts` has no Arrow/Parquet/WGPU/UI dependency.
- Session v1 valid bytes/semantics remain compatible.
- Persisted limits are fixed-width and bounded before `usize` conversion.
- Identifier normalization is documented and deterministic across languages.
- Manifest IO is bounded and source-preserving.

#### Acceptance Criteria

- [ ] The new crate is in the workspace with a thin facade and narrow dependencies.
- [ ] Its manifest inherits workspace metadata, has `publish = false`, and uses
      `version + path` for internal workspace dependencies.
- [ ] `rawscope-session` no longer depends on `rawscope-data`.
- [ ] Validated v1 manifests use `u64` wire limits and checked application limits.
- [ ] Oversized manifests and invalid/ambiguous paths return role-aware errors.
- [ ] Rust compatibility/normalization fixtures pass and workspace check succeeds.

#### Testing Guidance

- Add boundary fixtures for exact max bytes, max+1, zero/max row limits, whitespace
  identifiers, local paths containing colons, and unknown fields.
- Assert valid legacy serialization exactly where byte stability is promised.
- Avoid filesystem smoke tests; use focused temporary-file behavior tests only
  for bounded/read-race semantics.

#### Agent Handoff Context

T012 consumes the same fixture vectors in Python. T028 uses the validated manifest
as a job input without pulling data parsing into the event loop.

## Final Notes

- Recommended order: crate/facade, wire-vs-validated model, normalization/limits,
  bounded IO, resolver migration, compatibility fixtures.
- Human review: row/manifest limits and local-path schema wording.
- Risk: public re-exports can accidentally create two long-term owners; mark the
  old path deprecated and remove it before T035.
