### T016 — Move The Canonical SelectionSnapshot Into Analysis

#### Objective

Move T038's already-correct immutable filtered snapshot into
`rawscope-analysis::selection`, replace caller-controlled revisions with typed
generations, and migrate pure consumers without changing selected truth.

#### Scope

- Structural migration of the RS-083-RS-085/RS-092 correction landed by T038.
- Add `rawscope-analysis::selection` with a checked `SelectionRequest` and opaque
  `SelectionSnapshot`.
- Intersect geometry with the active `CohortSnapshot`; filtered selections must
  never be disabled or recomputed against the full dataset.
- Derive sorted unique selected `RowId`s, counts, typed samples, selected bin IDs,
  and aggregate context in one bounded pass/reuse of analysis indexes.
- Determine selected bins from geometry and complete membership, never from a
  bounded row sample.
- Make linked view publication, summaries, drilldown, aggregate context, and
  evidence builders consume the same snapshot by reference/`Arc`.
- Keep legacy evidence unavailable when its schema cannot truthfully represent
  the active cohort.

#### Out of Scope

- Do not serialize evidence or add version fields; T018-T020 own wire artifacts.
- Do not redesign brush UI/geometry or add new selection shapes.
- Do not scan/reconstruct source rows independently in each consumer.
- Do not upload selection state to GPU or schedule background work.

#### Blocked By

T013, T014, T038.

#### Why It Is Blocked

The current snapshot must already prove correctness. Normative binning and
immutable cohorts let this task move it to the final owner/generation types without
combining a behavior rewrite.

#### Implementation Details

Use explicit generation inputs and immutable output:

```rust
pub struct SelectionRequest {
    selection_id: SelectionId,
    view_id: ViewId,
    geometry: VisualSelectionGeometry,
    sample_limit: SelectionSampleLimit,
}

impl SelectionRequest {
    pub fn try_new(
        selection_id: SelectionId,
        view_id: ViewId,
        geometry: VisualSelectionGeometry,
        sample_limit: SelectionSampleLimit,
    ) -> Result<Self, SelectionRequestError>;
}

pub struct SelectionSnapshot {
    dataset_generation: DatasetGeneration,
    cohort_generation: CohortGeneration,
    view_generation: ViewGeneration,
    selection_id: SelectionId,
    sorted_row_ids: Arc<[RowId]>,
    selected_bins: Arc<[BinIndex]>,
    selected_count: u64,
    typed_samples: Arc<[SelectionSample]>,
    source_availability: SourceAvailability,
    aggregate_context: SelectionAggregateContext,
}
```

`SelectionSnapshot::build` validates all generation tuples and row alignment,
iterates the active cohort once (or uses an equivalent prebuilt index), records
complete sorted IDs, and maintains deterministic bounded samples. Selected bins
are calculated from geometry/bin membership for every selected row or from exact
bin-range geometry; sample contents may illustrate but never define coverage.

Expose borrowed iterators/accessors and derived view objects. Consumers cannot
mutate row IDs/counts. Legacy evidence builders receive an explicit capability
check such as `snapshot.supports_legacy_unfiltered_evidence()`.

#### Before / After

Before: filtered evidence is disabled, linked scatter selection ignores filters,
selected bins can be inferred from samples, and finalization rescans repeatedly.

After: one snapshot contains the only authoritative selected cohort and every
consumer agrees by construction.

#### Migration Notes

- Preserve selection IDs and deterministic row/sample ordering where valid.
- Replace workbench fields incrementally with one `Arc<SelectionSnapshot>`; do
  not keep old row/count/sample caches after their consumers migrate.
- Existing v1-v3 behavior remains callable only for compatible unfiltered state.

#### Misinterpretations To Prevent

- Wrong: build evidence from the snapshot but linked views from the mask again.
  Correct: every selected-row consumer reads the same snapshot.
- Wrong: use sample presence to mark a bin selected. Correct: samples are bounded
  illustrations; complete membership/geometry defines bins.
- Wrong: include full-dataset rows then annotate a filter. Correct: intersect the
  active cohort before every count/sample/bin is derived.

#### Invariants

- All snapshot fields share one dataset/cohort/view generation tuple.
- `selected_count == sorted_row_ids.len()` within checked platform conversion.
- Row IDs are strictly sorted, unique, and members of the active cohort.
- Selected bins are complete for the selection, independent of sample limit.
- A consumer cannot mutate or caller-fabricate counts/generations.

#### Acceptance Criteria

- [ ] `rawscope-analysis::selection::SelectionSnapshot` is the sole finalized
      selection owner.
- [ ] Filtered scatter/timeline snapshots contain only active-cohort rows.
- [ ] Linked views, summaries, aggregate context, and evidence builders use the
      same snapshot handle.
- [ ] Selected-bin coverage remains correct when sample limit is zero/small.
- [ ] Incompatible legacy evidence fails explicitly rather than lying.
- [ ] Focused selection/linked-consumer tests and workspace check pass.

#### Testing Guidance

- Add a golden behavior fixture with full rows, active filter, selection geometry,
  selected bins, linked view, samples, and aggregate context all asserting one
  row set.
- Include zero sample limit, selected bin with no sampled row, empty cohort,
  stale generation, and row alignment failure.
- No broad snapshots; assert contract fields directly.

#### Agent Handoff Context

## Final Notes

- Recommended order: request/generation validation, one-pass builder, consumer
  migrations, compatibility capability, remove duplicate scans.
- Human review: complete row-ID retention versus a future compressed membership
  representation for very large selections.
- Risk: retaining all selected IDs has a memory cost; account it and do not replace
  truth with bounded samples.
