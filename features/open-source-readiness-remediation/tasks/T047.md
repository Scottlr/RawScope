### T047 — Migrate Timeline Evidence Adapters And Readers

#### Objective

Move timeline v1-v3 artifact adapters, strict readers, typed conversions, and
goldens into `rawscope-evidence` as a standalone PR, preserving every valid byte.

#### Scope

- Completes RS-095/RS-097 for timeline artifacts after T046 owns scatter.
- Add `rawscope-evidence::wire::timeline::{v1,v2,v3}` with exact constants,
  artifacts, writers, and bounded strict readers.
- Convert canonical/legacy timeline components directly without JSON/text
  inheritance.
- Move timeline golden/round-trip/malformed tests into evidence.
- Leave render delegation/callers until T048.

#### Out of Scope

- Do not touch scatter adapters or add timeline v4; T020 owns the new version.
- Do not migrate workbench/bundles or delete render modules.
- Do not change lane semantics already corrected by T037.
- Do not change valid JSON/Markdown bytes.

#### Blocked By

T019.

#### Why It Is Blocked

Timeline adapters need the canonical model but can be reviewed/tested independently
from five scatter versions and caller migration.

#### Related Code

- Current timeline evidence/export v1-v3 render modules/tests/docs.
- T019 canonical model and T037 corrected lane semantics.
- Render facade re-exports and workbench timeline report paths.

#### Implementation Touchpoints

- Read first: exact v1-v3 bytes/ordering/defaults and lane/source contracts.
- Edit first: timeline v1 adapter/reader, v2/v3, tests, temporary render delegation.
- Symbols to search: timeline schema/artifact constants, serializer helpers,
  `serde_json::Value`, schema_version, and render facade exports.
- Required structural changes: one module per timeline version and only truly shared
  typed components.
- Do not edit: workbench, bundle, scatter, shaders, or new v4 schema.
- Verify in order: per-version goldens, reader invalid/legacy cases, evidence tests,
  old render tests via delegation, format, workspace check.
- Stop and ask: if a version lacks canonical data; return validated legacy-only.

#### Implementation Details

Mirror the T046 explicit adapter/reader pattern with
`DecodedTimelineEvidence::{Canonical, LegacyOnly}`. Reader bounds bytes, dispatches
exact kind/version, validates lane/time/source fields, and never invents v4 data.
Schema constants come from adapters, not mutable model fields.

#### Before / After

Before: timeline artifacts are render-owned/write-only.

After: evidence owns readable validated v1-v3 artifacts; render only delegates.

#### Migration Notes

- Preserve current facade until T048 and every valid byte.
- T020 adds timeline v4 explicitly, not by changing v3.

#### Misinterpretations To Prevent

- Wrong: combine with scatter migration to “share helpers.” Correct: timeline is an
  independent reviewable owner and shares only typed canonical components.
- Wrong: encode corrected lane orientation by changing old artifact values.
  Correct: preserve established evidence semantics/bytes where valid.
- Wrong: fabricate canonical fields. Correct: legacy-only result.

#### Invariants

- V1-v3 bytes remain exact.
- Reader validates bounded kind/version/content.
- No text/Value inheritance or duplicated render implementation.
- Lane/time values preserve evidence contract.

#### Acceptance Criteria

- [ ] Timeline v1-v3 adapters/readers/goldens live in evidence.
- [ ] Valid bytes remain fixed and invalid/unknown inputs fail.
- [ ] Render delegates temporarily with existing tests passing.
- [ ] No scatter/caller/new-v4 behavior is mixed in.
- [ ] Focused checks pass.

#### Testing Guidance

- Exact golden per version plus malformed kind/version/contract and legacy-only.
- Assert lane/time source values directly.
- No workbench integration test here.

#### Agent Handoff Context

T020 adds v4; T048 removes render ownership after both families are complete.

## Final Notes

- Recommended order: v1, v2/v3, readers, tests, delegation.
- Human review: legacy-only policy.
- Risk: shared helpers can accidentally change scatter bytes; keep version owners
  explicit.
