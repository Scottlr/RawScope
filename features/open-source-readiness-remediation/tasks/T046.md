### T046 — Migrate Scatter Evidence Adapters And Readers

#### Objective

Move scatter v1-v5 artifact adapters, strict readers, direct typed conversions,
and byte goldens into `rawscope-evidence` without changing callers or introducing
new schema behavior in the same PR.

#### Scope

- Primary audit findings: RS-095 and RS-097 (scatter portion).
- Add `rawscope-evidence::wire::scatter::{v1,v2,v3,v4,v5}` with exact current
  constants/artifact structs/writers.
- Add bounded kind/version dispatch and `Deserialize`/validation readers for every
  supported scatter artifact.
- Replace v4/v5 text/`serde_json::Value` inheritance with direct typed component
  conversion while preserving valid bytes.
- Move scatter golden/round-trip/malformed tests into the evidence crate.
- Leave temporary render re-exports/callers in place; T048 removes them.

#### Out of Scope

- Do not migrate timeline adapters; T047 is independent.
- Do not add scatter v6/provenance/formatting changes; T020 owns them.
- Do not switch workbench/report imports or delete render modules.
- Do not change valid legacy JSON/Markdown bytes.

#### Blocked By

T019.

#### Why It Is Blocked

Adapters need the canonical private model/validation crate, but are independently
reviewable from timeline and caller migration.

#### Related Code

- Current render scatter evidence/export v1-v5 modules and artifact DTO modules.
- T018 validation wrappers and T019 canonical evidence components.
- Existing scatter evidence/export/v3/v4/v5 tests and schema docs.

#### Implementation Touchpoints

- Read first: exact bytes/ordering/default omission for every version and all
  current compatibility tests.
- Edit first: v1 adapter/reader as pattern, then v2-v5/direct typed composition,
  tests, and temporary render delegation.
- Symbols to search: scatter schema/artifact constants, `serde_json::Value`, parse/
  serialize inheritance, `expect`, and render `pub use` items.
- Required structural changes: one file/module per version plus shared typed
  scatter wire components only when genuinely byte-identical.
- Do not edit: timeline, workbench callers, bundle IO, safe v6 fields/formatting.
- Verify in order: per-version byte goldens, reader round trips/malformed dispatch,
  evidence tests, existing render tests via delegation, format, workspace check.
- Stop and ask: if a legacy version cannot map to canonical without fabricated
  fields; return `LegacyOnly` instead.

#### Implementation Details

Each version exposes explicit `encode`/`decode`; canonical struct derives do not
define wire layout. Reader first bounds input size, inspects artifact kind/schema
version, deserializes exact version, validates, and returns:

```rust
pub enum DecodedScatterEvidence {
    Canonical(EvidenceDocument),
    LegacyOnly(ValidatedLegacyScatterEvidence),
}
```

V4/v5 common data maps through typed structs/functions. No JSON string/value
round-trip or heading replacement. Schema version is adapter constant.

Temporary render APIs delegate directly and are marked for T048 removal; there is
only one implementation.

#### Before / After

Before: scatter artifacts live in render, are write-only, and later versions
inherit through text/value manipulation.

After: evidence owns strict readable scatter adapters with exact compatibility;
render is only a temporary facade.

#### Migration Notes

- Keep public function names through temporary re-exports until T048.
- Unknown/unsupported versions fail explicitly; legacy-only does not fabricate.

#### Misinterpretations To Prevent

- Wrong: derive Serialize on canonical model. Correct: explicit version adapters.
- Wrong: switch all callers now. Correct: isolate adapter move/review first.
- Wrong: auto-upgrade legacy-only missing data. Correct: preserve/read truthfully.

#### Invariants

- Valid v1-v5 bytes remain exact.
- Every reader validates kind/version/content.
- No text/Value inheritance remains.
- One implementation exists; render only delegates.
