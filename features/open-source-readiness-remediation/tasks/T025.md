### T025 — Share Scatter GPU Resources Across Validated Generations

#### Objective

Consolidate scatter/difference/point rendering around one immutable dataset GPU
resource generation, validated view/cohort configurations, stable large-count
normalization, and generation-cached bindings/stats.

#### Scope

- Primary audit findings: RS-061 and RS-063 through RS-068.
- Add a shared `ScatterDatasetGpuResources` handle for one packed point/mapping
  buffer generation; absolute/difference/point views reference it instead of
  retaining three copies.
- Keep independent cohort masks/count grids but cache bind groups by backing
  resource generation and rebuild only when handles/capacities change.
- Replace large-total f32 normalization with a documented numerically stable
  scaled/reciprocal representation and test error bounds above 2^24.
- Make point-reveal/config fields private and validated, including finite positive
  radius and bounded sample/count settings.
- Validate requested indices before packing/drawing and derive rendered stats from
  actual accepted indices.
- Derive `DensityFieldViewport`/quality metadata from validated compute config plus
  owner-minted field generation; callers cannot provide contradictory metadata.
- Retain previous field resources/config only while transition-compatible; T026
  completes transition/relief handling.

#### Out of Scope

- Do not precompute relief normals or quality caps; T026 owns relief cost.
- Do not add workbench atomic commit/coalescing; T029/T030 own it.
- Do not merge all scatter pipelines into one giant generic renderer.
- Do not claim exact ratio arithmetic if the approved shader representation has a
  documented tolerance.

#### Blocked By

T010, T013, T022, T023.

#### Why It Is Blocked

Shared resources need T010's precision/quantization contract, normative binning,
checked device plans/recovery, and nonblocking readback ownership before
generations can safely outlive views.

#### Related Code

- `scatter_density_gpu_state.rs` and split compute/render lifecycle modules.
- `scatter_difference_renderer.rs`/`scatter_difference_resources.rs`.
- `scatter_point_renderer.rs`, `scatter_point_reveal.rs`, and transition metadata.
- `difference_density.rs` normalization/fixed-point contracts.
- Workbench scatter resource/state fields and GPU tests.

#### Implementation Touchpoints

- Read first: every point-buffer upload/owner, bind-group creation, difference
  total conversion, point index/radius path, field metadata constructor, and
  transition previous-buffer lifetime.
- Edit first: `render/src/scatter/dataset_resources.rs`, validated configs/field
  generation, then difference/point consumers and stats.
- Symbols to search: point buffer creation, `as f32` totals, bind-group recreation,
  `PointRevealConfig`, `rendered_indices`, `DensityFieldViewport`, and previous
  grid fields.
- Required structural changes: immutable `Arc<ScatterDatasetGpuResources>` and
  small view-owned cohort/grid state; no shared mutable global cache.
- Do not edit: analysis selection truth, relief shader algorithm, workbench job
  scheduler, or evidence.
- Verify in order: pure config/normalization/index tests, resource generation/
  bind cache tests, existing ignored scatter/difference/point GPU tests, format,
  workspace check.
- Stop and ask: if large-count error tolerance cannot meet analysis semantics or
  if point buffer sharing requires an unsafe lifetime workaround (do not do it).

#### Implementation Details

Define resource ownership explicitly:

```rust
pub struct ScatterDatasetGpuResources {
    dataset_generation: DatasetGeneration,
    device_generation: DeviceGeneration,
    point_buffer: wgpu::Buffer,
    row_mapping_buffer: wgpu::Buffer,
    point_count: u64,
    allocated_bytes: u64,
}

pub struct ScatterFieldGeneration {
    dataset: Arc<ScatterDatasetGpuResources>,
    cohort_generation: CohortGeneration,
    view_generation: ViewGeneration,
    config: ValidatedScatterComputeConfig,
    /* grid/max resources */
}
```

Absolute/difference/point renderers receive handles; they do not upload their own
full point arrays. Mask/count state remains separate by cohort. Bind-group cache
keys are stable resource-generation IDs and layouts, not operation counters.

For normalized difference, select and document one representation with a proven
error bound for full supported counts—for example CPU f64 reciprocal split into
shader-consumable scaled components. Validate non-zero totals and compare GPU to
f64 CPU reference above 2^24. Do not cast totals/counts to one f32 and call exact.

Point reveal uses `PointRevealConfig::try_new(...)`; index validation returns an
error or filtered accepted set according to one documented policy. Stats report
actual drawn indices. Field viewport is constructed internally from compute config
and field generation.

#### Before / After

Before: difference mode triples point state, bind groups churn, large totals lose
meaning, invalid point config/indices pass, and metadata can contradict density.

After: one dataset resource generation feeds validated views with stable bindings,
truthful stats, and bounded numerical error.

#### Migration Notes

- Preserve existing scatter correctness wrappers and evidence-facing stats through
  read-only accessors/freshness markers.
- Resource handle replacement is all-or-nothing on dataset/device generation.
- T026 decides compatibility of previous/current resources for visual transitions.

#### Misinterpretations To Prevent

- Wrong: share a mutable point buffer across dataset generations. Correct: each
  immutable generation owns its resources until all handles drop.
- Wrong: cache bind groups by viewport update number. Correct: cache by actual
  backing resource/layout generation.
- Wrong: silently drop invalid point indices while reporting requested count.
  Correct: error or report the actual accepted/drawn set explicitly.

#### Invariants

- One packed point/mapping allocation exists per live dataset/device generation.
- Views cannot outlive their resource handle or mix generation tuples.
- Difference normalization has a documented tested error bound at max counts.
- Config/indices/metadata cannot be caller-contradictory.
- CPU-facing stats disclose generation/freshness.

#### Acceptance Criteria

- [ ] Absolute/difference/point paths share dataset GPU resources.
- [ ] Bind groups rebuild only when backing resource/layout generation changes.
- [ ] Large-total GPU difference matches f64 CPU reference within approved bound.
- [ ] Invalid point radius/indices fail and stats reflect actual draws.
- [ ] Field metadata is derived from validated config/generation.
- [ ] Focused pure/resource/adapter tests and workspace check pass.

#### Testing Guidance

- Add generation/resource identity tests, bind cache invalidation cases, totals at
  2^24 boundaries/u32 max, zero totals, invalid radii/indices, and stale metadata.
- Adapter-backed parity remains in the existing ignored suite.
- Do not use timing/allocation claims here; T033 measures product costs.

#### Agent Handoff Context

T026 builds compatible transitions/relief from these generations. T029/T030 swap
complete field generations atomically. Keep render resource ownership explicit.

## Final Notes

- Recommended order: shared resources, validated field/config, difference math,
  bind cache, point validation/stats, caller migration.
- Human review: acceptable normalized-difference error bound.
- Risk: `Arc` removes duplicate ownership only if old renderer-local point buffers
  are actually deleted and memory accounting includes all live generations.
