### T058 — Add GPU Adapter Policy And Recovery

#### Objective

Make adapter selection and WGPU validation/surface/device failure explicit,
observable, and generation-recoverable without mixing ABI/resource-limit proof or
renderer business logic into the same PR.

#### Scope

- Primary audit findings: RS-059 and RS-069.
- Add typed `AdapterPolicy` with power preference and explicit allow/deny software
  fallback; log selected adapter/backend/driver structurally.
- Add error scopes around fallible resource/context creation and structured
  uncaptured/device-lost handling.
- Model `Ready`, `SurfaceOutdated`, `DeviceLost`, `Recovering`, and `Fatal` context
  states/signals with owner-minted device generation.
- Reconfigure suboptimal/outdated surfaces and prepare a complete replacement
  context before active swap.
- Cancel/terminalize device-generation GPU tickets/jobs on loss through T023/T029.

#### Out of Scope

- Do not change host/WGSL ABI/resource arithmetic; T022 owns it.
- Do not implement readback state machine; T023 consumes recovery signals.
- Do not move renderer workflow/domain logic into `rawscope-gpu`.
- Do not always choose fallback or hide degraded performance.

#### Blocked By

T005, T022.

#### Why It Is Blocked

Recovery needs checked generations and validated resource plans/errors before a
replacement context can be built safely.

#### Related Code

- `rawscope-gpu/src/{adapter,compute,context,error}.rs`.
- WGPU context creation/surface handling and workbench error paths.
- T022 plans and T023/T043/T029 consumers.

#### Implementation Touchpoints

- Read first: adapter request options, context/surface lifecycle, WGPU 29 error/
  device-loss APIs, and current logs/errors.
- Edit first: `rawscope-gpu/src/{policy,recovery}.rs`, adapter/context/error facade,
  then workbench recovery event adapter.
- Symbols to search: `force_fallback_adapter`, `PowerPreference`, error scopes,
  uncaptured handler, surface errors, device lost, reconfigure.
- Required structural changes: narrow policy/recovery modules and immutable
  `GpuContextGeneration`; no renderer code.
- Do not edit: shaders/analysis/evidence/UI layout.
- Verify in order: policy/recovery state tests with injected events, context tests,
  adapter-backed fallback/reconfigure when available, format, workspace check.
- Stop and ask: default fallback policy, supported backend/capability floor, or any
  platform where recovery cannot preserve window/surface safely.

#### Implementation Details

```rust
pub struct AdapterPolicy {
    power_preference: wgpu::PowerPreference,
    fallback: FallbackPolicy,
}

pub enum GpuRecoveryState {
    Ready(GpuContextGeneration),
    SurfaceOutdated { generation: DeviceGeneration },
    DeviceLost { generation: DeviceGeneration, reason: DeviceLossReason },
    Recovering { previous: DeviceGeneration, request: RecoveryRequest },
    Fatal(GpuError),
}
```

Selection attempts preferred adapter then explicit fallback only if allowed and
records why. Error scopes wrap creation/rebuild; uncaptured errors carry operation/
generation. Recovery constructs a full new context/resources via downstream owners
before one active swap. Old-generation results cannot publish.

#### Before / After

Before: software fallback is excluded and WGPU errors/device loss can leave
partial/stale state.

After: policy/recovery is typed, observable, and generation-safe.

#### Migration Notes

- T023 depends on terminal loss signals; T043 uses nonblocking adapter requests;
  T029 reaps old tickets/resources.
- Do not claim fallback meets performance targets without T057.

#### Misinterpretations To Prevent

- Wrong: force fallback always. Correct: policy/attempt sequence explicit.
- Wrong: log and continue on device loss. Correct: transition/cancel/rebuild.
- Wrong: mutate active context while rebuilding. Correct: complete replacement.

#### Invariants

- Selected adapter matches policy and metadata is recorded.
- WGPU failures preserve source/operation/generation.
- Old device-generation work cannot publish after loss.
- Recovery is complete swap or prior/fatal state, never partial.
- GPU crate remains workflow-neutral.

#### Acceptance Criteria

- [ ] Typed adapter/fallback policy and metadata exist.

- [ ] Recovery generation rejects stale results and swaps complete context.
- [ ] Injected policy/recovery tests pass; adapter cases run when available.
- [ ] Workspace checks pass.

#### Testing Guidance

- No window startup smoke test.

#### Agent Handoff Context
