### T054 — Add Maintained Rust Examples

#### Objective

Add a small set of real compile-checked Rust examples that demonstrate stable
ingestion, selection, and evidence-reader contracts without creating fake demo
applications or requiring private datasets in CI.

#### Scope

- Primary audit finding: RS-142.
- Add `rawscope-data/examples/inspect_local_schema.rs` behind appropriate ingest
  feature, accepting a user path.
- Add `rawscope-analysis/examples/build_selection_snapshot.rs` using a small
  deterministic in-memory store/cohort and asserting selected IDs.
- Add `rawscope-evidence/examples/read_evidence.rs` accepting an artifact path and
  reporting validated kind/version/portable identity.
- Link examples from crate rustdoc/README and compile them in CI/all-target checks.

#### Out of Scope

- Do not add a new app/window, downloader, benchmark, screenshot, or bundled large
  dataset.
- Do not use private/internal APIs or stabilize APIs solely for an example.
- Do not execute path-requiring examples in normal CI without input.

#### Blocked By

T010, T011, T019, T031, T034.

#### Why It Is Blocked

Examples must target final stable facades/features after temporary re-exports and
module moves are gone.

#### Related Code

- Final data/analysis/evidence public facades/rustdoc/features.
- Existing deterministic fixtures and schema docs.
- T052 API documentation.

#### Implementation Touchpoints

- Read first: final public APIs and Cargo example packaging/feature behavior.
- Edit first: one example at a time plus minimal docs links.
- Symbols to search: public constructors/readers, feature flags, examples list.
- Required structural changes: crate-owned `examples/` only; no workspace app.
- Do not edit: production behavior, benchmarks, feature semantics.
- Verify in order: `cargo check --examples` per feature/package, rustdoc, format,
  workspace all-target check.
- Stop and ask: if an example would require a new public API or redistributed data.

#### Implementation Details

Examples return `Result`, handle typed errors, and demonstrate meaningful output/
assertion. Local schema/evidence readers accept CLI path and print bounded metadata,
not raw datasets/secrets. Selection example uses public builders and verifies exact
row IDs, not just “it ran.”

#### Before / After

Before: external Rust users have no maintained executable contract examples.

After: three stable library seams are compile-checked and documented.

#### Migration Notes

- Path examples compile but are not run in CI; commands show user-supplied input.
- Include/exclude examples intentionally in packages/releases.

#### Misinterpretations To Prevent

- Wrong: create a smoke/demo app. Correct: crate examples exercise real APIs.
- Wrong: embed flagship/private data. Correct: deterministic tiny/no input or user
  path.
- Wrong: use `unwrap`. Correct: typed errors.

#### Invariants

- Examples use public stable APIs only.
- No large/private/network fixture.
- Each example demonstrates meaningful contract behavior.
- Feature requirements are explicit.

#### Acceptance Criteria

- [ ] Three named examples exist and compile under documented features.
- [ ] Docs link accurate commands/inputs.
- [ ] No fake app/downloader/private data is added.
- [ ] Rustdoc/all-target checks pass.

#### Testing Guidance

- Compilation is appropriate for path-dependent examples; deterministic selection
  example may run/assert if normal Cargo example tests support it.
- Do not add separate smoke tests duplicating examples.

#### Agent Handoff Context

T035 inspects example inclusion and public package contents.

## Final Notes

- Recommended order: evidence reader, selection, local schema, docs/CI.
- Human review: which APIs are stable enough to teach.
- Risk: examples rot if feature/defaults change; T031/T003 must compile them.
