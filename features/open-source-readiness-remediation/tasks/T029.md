### T029 — Migrate Settling Into The Final Render Coordinator

#### Objective

Move T042's already-contained scatter/timeline gesture behavior into one final
render coordinator that coalesces previews, reserves capacity for exact settles,
retires every GPU ticket, and publishes only a complete matching render/analysis
generation.

#### Scope

- Structural migration task; primary tactical findings RS-108/RS-110 remain owned
  and proven by T042.
- Add a private `RenderCoordinator` with typed viewport intents, preview/exact
  requests, full dataset/cohort/view/job/field generation tuples, and immutable
  completion results.
- Reuse T042's reprojection/coalescing/release-settle behavior without changing
  pointer-event semantics.
- Add a named `MAX_LIVE_GPU_TICKETS` and reserve exact-settle capacity; suppress or
  replace coalesced preview requests when the preview share is saturated.
- Give exact work priority without exceeding the cap: obsolete previews become
  non-publishable/retire, and an exact request waits in one latest slot if the
  reserved slot is temporarily unavailable.
- On success, atomically publish one matching render field plus analytical/
  selection snapshot; failure preserves the last valid generation and typed error.
- Reap success, cancellation, timeout, stale completion, device loss, and submit
  failure exactly once from the ticket registry.

#### Out of Scope

- Do not refix pointer handlers, timeline math, or filtered selection truth.
- Do not own dataset startup/admission, evidence export, or UI caching.
- Do not introduce a busy render loop, detached polling thread, or unbounded queue.
- Do not call preview exact or allow it to feed evidence/selection publication.
- Do not split scatter/timeline/selection app controllers; T050 owns that move.

#### Blocked By

T016, T017, T023, T024, T025, T028, T042.

#### Why It Is Blocked

Final coordination requires canonical snapshots/indexes, durable nonblocking GPU
tickets, resident engines, admitted generations, and already-correct contained
interaction behavior.

- T023 ticket state, T024 timeline engine, T025 scatter resource generations.
- Current `app_render_schedule.rs`, exact-settle scans, and generation checks.

#### Implementation Details

```rust
const MAX_LIVE_GPU_TICKETS: usize = /* reviewed bounded value */;
const MAX_PREVIEW_GPU_TICKETS: usize = MAX_LIVE_GPU_TICKETS - 1;

pub struct RenderCoordinator {
    live: BoundedTicketRegistry,
    latest_preview: Option<ViewportIntent>,
    latest_exact: Option<ExactSettleIntent>,
    active: Option<Arc<SettledRenderGeneration>>,
}
```

Preview requests coalesce by view/generation. At the preview cap, do not submit
another ticket: replace the queued latest intent and obsolete an older preview
only according to the documented policy. The reserved capacity means preview
traffic cannot starve exact work. Exact requests supersede older unsubmitted exact
intent; accepted exact tickets remain tracked until terminal.

Every registry entry records kind, request generations, ticket/resource handles,
deadline, and publishability. Terminal processing removes it exactly once and
releases reservations. Device loss marks all matching-device entries
non-publishable, records a terminal reason, and drains via T023/T058 lifetime
rules. Timeout/cancellation/stale results follow the same retirement path.

Exact publication constructs a complete `SettledRenderGeneration` containing the
matching field metadata and T016/T017 snapshot results, validates the tuple, then
swaps one `Arc`; partial sub-result arrivals never mutate active state.

#### Before / After

Before: T042 fixes current behavior but scheduling ownership remains distributed
and ticket pressure/retirement is not the final bounded contract.

After: one coordinator enforces preview/exact priority, ticket bounds, terminal
cleanup, and all-or-nothing settled publication.

#### Migration Notes

- Port T042 behavior tests unchanged before deleting the current scheduler.
- Preserve latest-viewport semantics and exact-on-release behavior.
- T050 consumes typed coordinator commands/results; it must not duplicate tickets.

#### Misinterpretations To Prevent

- Wrong: exact priority means exceed the cap. Correct: reserve capacity and queue
  one latest exact intent.
- Wrong: dropping a stale result retires its resources automatically. Correct:
  terminal registry cleanup remains mandatory.
- Wrong: publish the field while selection is pending. Correct: swap one complete
  settled generation.

#### Invariants

- Live GPU tickets never exceed `MAX_LIVE_GPU_TICKETS`.
- Preview traffic cannot consume exact-reserved capacity or starve latest exact.
- Every accepted ticket reaches one terminal retirement path.
- Preview/reprojection never becomes exact analytical/evidence truth.
- Failed/stale/partial results cannot mutate the active settled generation.

#### Acceptance Criteria

- [ ] Final coordinator owns typed preview/exact requests and the bounded registry.
- [ ] Saturated previews coalesce/suppress without exceeding the cap; exact work
      uses reserved capacity or one latest waiting slot.
- [ ] Success/cancel/timeout/stale/device-loss/submit-failure cleanup is exact-once.
- [ ] Matching exact components publish through one aggregate swap; partial/failure
      preserves prior state.
- [ ] T042 behavior regressions pass after old scheduler ownership is removed.
- [ ] Focused coordinator/GPU lifecycle tests, format, and workspace checks pass.

#### Testing Guidance

- Use fake tickets/completions and barriers, never sleeps; fill preview capacity,
  request exact, complete entries in adversarial order, and inspect registry size.
- Test device loss/timeout for active and obsolete tickets and assert reservations
  and resource handles are reaped once.
- Keep actual latency measurement in T057.
