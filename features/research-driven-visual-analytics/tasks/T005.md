shows selected-vs-baseline context alongside selected rows and data-quality

#### Implementation Details

Create `apps/rawscope-workbench/src/app_comparison.rs`:

```rust
//! Workbench-selected comparison state for active visual selections.

use rawscope_render::{
    MissingnessSelectionComparison, ScatterSelectionComparison,
    TimelineSelectionComparison,
};

use crate::app::WorkbenchApp;

#[derive(Debug, Clone, PartialEq)]
pub(crate) enum WorkbenchComparison {
    Scatter(ScatterSelectionComparison),
    Timeline(TimelineSelectionComparison),
    Missingness(MissingnessSelectionComparison),
}

impl WorkbenchApp {
    pub(crate) fn rebuild_active_comparison(&mut self);
    pub(crate) fn clear_active_comparison(&mut self);
}
```

Add state in `apps/rawscope-workbench/src/app.rs`:

```rust
pub(crate) active_comparison: Option<WorkbenchComparison>,
```

Rebuild rules:

- After scatter brush finalizes and `selection_summary` is set, call
  `rebuild_active_comparison()`.
- After timeline brush finalizes and `selection_summary` is set, call
  `rebuild_active_comparison()`.
- After missingness cell selection builds `selection_summary`, call
  `rebuild_active_comparison()`.
- Any brush/selection clear must call `clear_active_comparison()`.
- Dataset switch, preset switch, or local input reload must clear comparison.

Implementation should branch on visible/active state:

```rust
match self.visible_surface {
    WorkbenchSurface::Primary => match self.demo_mode {
        DemoMode::Scatter => { /* use scatter_selection_comparison */ }
        DemoMode::Timeline => { /* use timeline_selection_comparison */ }
    },
    WorkbenchSurface::Missingness => { /* use missingness_selection_comparison */ }
}
```

For missingness baseline, compute baseline totals from the current
`MissingnessGrid`:

```rust
let baseline_missing_count = grid.cells.iter().map(|cell| cell.missing_count as u64).sum();
let baseline_total_count = grid.cells.iter().map(|cell| cell.total_count as u64).sum();
```

Create `apps/rawscope-workbench/src/ui_comparison.rs`:

```rust
//! egui rendering for bounded selected-vs-baseline comparison.

use egui::{RichText, Ui};

use crate::app_comparison::WorkbenchComparison;

pub(crate) fn show_selection_comparison(
    ui: &mut Ui,
    comparison: Option<&WorkbenchComparison>,
) -> bool;
```

UI rules:

- Use compact text rows and small headings.
- Show selected count, baseline count, selected percentage, and the largest
  absolute delta.
- For scatter/timeline, show top 3 ratio lines by absolute delta.
- For missingness, show selected missing ratio, baseline missing ratio, and
  delta percentage points.
- Do not add a new side panel; use the existing right panel.

Add `comparison: Option<WorkbenchComparison>` to `WorkbenchUiState` and render:

```rust
if show_selection_comparison(ui, state.comparison.as_ref()) {
    ui.separator();
}
```

#### Misinterpretations To Prevent

- Wrong interpretation: build a dashboard panel with arbitrary cards.
  Correct rule: add one bounded comparison section in the existing right panel.
- Wrong interpretation: allow multiple active selections.
  Correct rule: keep the existing single `active_selection` model.
- Wrong interpretation: compare by arbitrary source columns.
  Correct rule: first panel uses fixed comparison structs from T004.
- Wrong interpretation: hide row drilldown once comparison exists.
  Correct rule: comparison complements row evidence; it does not replace it.

#### Invariants

- Clearing a selection clears comparison state.
- Switching dataset or synthetic preset clears comparison state.
- Comparison state derives from current summaries and active records, not stale
  cached rows.
- UI does not create new selection semantics.
- The panel never claims benchmark or performance information.
