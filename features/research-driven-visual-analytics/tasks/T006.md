### T006 - Add Aggregate Overview Cache With Row Samples

#### Objective

Add a bounded CPU aggregate overview cache that preserves enough row identity to
connect dense visual regions back to source records. This turns the research
takeaway on multiscale aggregates into a concrete code path without building a
general query engine or pretending GPU heatmaps retain row-level evidence.

#### Scope

- Add a render-owned aggregate overview module for scatter and timeline views.
- Keep the first implementation to one full-view aggregate level plus stable row
  samples per bin.
- Store overview cache state in the workbench after dataset load or preset
  selection.
- Use the cache as source material for T007 evidence context and T008 diff
  surfaces.
- Keep all aggregation deterministic and bounded by explicit configuration.

#### Out of Scope

- Do not add a tile pyramid, remote cache, database, SQL layer, or DataFusion
  integration.
- Do not add benchmark claims or performance dashboards.
- Do not add a new demo app.
- Do not change shader density accumulation in this task.
- Do not preserve every row id for every dense bin.

#### Blocked By

T003

#### Why It Is Blocked

The aggregate cache should align with marginal and overview context semantics so
the workbench does not grow two competing definitions of "overview".

#### Implementation Details

Create `crates/rawscope-render/src/aggregate_cache.rs`:

```rust
//! Bounded aggregate overviews used by evidence and workbench context.

use rawscope_core::{F32Range, RowId, U64Range};
use rawscope_data::{ScatterPointRecord, TimelineEventRecord};

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct AggregateCacheConfig {
    pub grid_width: u32,
    pub grid_height: u32,
    pub max_row_ids_per_bin: usize,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AggregateBinSample {
    pub count: u32,
    pub row_ids: Vec<RowId>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterAggregateOverview {
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub grid_width: u32,
    pub grid_height: u32,
    pub max_bin_count: u32,
    pub bins: Vec<AggregateBinSample>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct TimelineAggregateOverview {
    pub time_range: U64Range,
    pub lane_count: u32,
    pub grid_width: u32,
    pub grid_height: u32,
    pub max_bin_count: u32,
    pub bins: Vec<AggregateBinSample>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum AggregateCacheError {
    EmptyGrid,
    EmptyTimelineLanes,
}
```

Add builders:

```rust
pub fn scatter_aggregate_overview(
    points: &[ScatterPointRecord],
    x_range: F32Range,
    y_range: F32Range,
    config: AggregateCacheConfig,
) -> Result<ScatterAggregateOverview, AggregateCacheError>;

pub fn timeline_aggregate_overview(
    events: &[TimelineEventRecord],
    time_range: U64Range,
    lane_count: u32,
    config: AggregateCacheConfig,
) -> Result<TimelineAggregateOverview, AggregateCacheError>;
```

The new module should consume the same `ScatterPointRecord` and
`TimelineEventRecord` streams used by `density_reference.rs`; do not add
parallel point/event structs.

Use deterministic sampling:

- Preserve row ids in encounter order until `max_row_ids_per_bin` is reached.
- Never allocate more than `grid_width * grid_height *
  max_row_ids_per_bin` row-id slots.
- Record full bin counts even after row samples stop growing.
- Clamp invalid or out-of-range records the same way existing density builders
  do.

Add owned state to the workbench:

```rust
pub(crate) scatter_aggregate_overview: Option<ScatterAggregateOverview>,
pub(crate) timeline_aggregate_overview: Option<TimelineAggregateOverview>,
```

Rebuild triggers:

- local dataset load
- synthetic preset selection
- demo mode switch when the backing record set changes
- explicit dataset clear

Avoid rebuilding on every pointer movement, brush drag, or right-panel paint.

Suggested constants should live near the workbench owner:

```rust
const DEFAULT_AGGREGATE_OVERVIEW_WIDTH: u32 = 96;
const DEFAULT_AGGREGATE_OVERVIEW_HEIGHT: u32 = 64;
const DEFAULT_AGGREGATE_ROW_SAMPLE_COUNT: usize = 8;
```

The names include units/count semantics and avoid a global constants module.

#### Before / After

**Before:**

Dense GPU pixels show where records accumulate, but evidence paths can only
explain selected records and summaries. Dense unselected regions do not carry a
bounded source-row sample for inspection.

**After:**

The workbench keeps an aggregate overview cache with counts and row samples for
scatter and timeline surfaces. Later evidence and diff tasks can point to dense
regions without inventing row-level certainty.

#### Migration Notes

- Existing renderer output remains unchanged.
- Existing selection evidence remains unchanged until T007.
- Existing workbench startup defaults remain unchanged.
- Cache memory is bounded by the explicit config, not dataset size alone.

#### Misinterpretations To Prevent

- Wrong interpretation: build a full multiscale query service.
  Correct rule: add one bounded overview level that future tasks can consume.
- Wrong interpretation: keep every row id per bin.
  Correct rule: keep full counts plus a deterministic sample.
- Wrong interpretation: replace GPU density with CPU rendering.
  Correct rule: this cache provides explainability context; it does not render
  the primary heatmap.
- Wrong interpretation: update the cache during every drag.
  Correct rule: rebuild only when backing records or bindings change.

#### Invariants

- `bins.len()` equals `grid_width * grid_height`.
- Every bin count is the full aggregate count, not the sample length.
- `row_ids.len()` never exceeds `max_row_ids_per_bin`.
- The same input records and config produce the same samples.
- Invalid config returns `AggregateCacheError`; invalid records follow the same
  inclusion/exclusion rules as density reference builders.
- Workbench state never exposes stale aggregate cache after dataset or preset
  switch.
