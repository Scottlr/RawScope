### T008 - Add Bounded Dataset Diff Surface

#### Objective

Add a local, bounded dataset-diff surface that compares two loaded tables for
schema, row count, and missingness changes. This brings the research takeaway on
data-quality and diff workflows into the codebase without turning RawScope into
an ETL platform.

#### Scope

- Add a render/data-facing diff summary for two source tables.
- Add a workbench path for loading an optional comparison input.
- Add a dedicated workbench surface that displays diff summary and changed
  missingness regions.
- Reuse selection comparison and aggregate concepts where useful.
- Keep comparison local, table-level, and bounded.

#### Out of Scope

- Do not add row-level joins, fuzzy matching, primary-key inference, or merge
  logic.
- Do not add SQL, remote connectors, or streaming ingest.
- Do not add a separate diff application.
- Do not add generated screenshots or visual regression tests.
- Do not write long usage docs.

#### Blocked By

T004, T006

#### Why It Is Blocked

The diff surface should reuse selected-vs-baseline ratio language from T004 and
aggregate context from T006 rather than introducing a separate comparison
vocabulary.

#### Implementation Details

Create `crates/rawscope-render/src/dataset_diff.rs`:

```rust
//! Bounded summaries for comparing two local source tables.

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum DatasetDiffColumnStatus {
    Unchanged,
    Added,
    Removed,
    TypeChanged,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DatasetDiffColumn {
    pub name: String,
    pub status: DatasetDiffColumnStatus,
    pub before_type: Option<String>,
    pub after_type: Option<String>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct DatasetDiffMissingnessDelta {
    pub column_name: String,
    pub before_missing_count: u64,
    pub after_missing_count: u64,
    pub delta_missing_count: i64,
    pub before_missing_ratio: f32,
    pub after_missing_ratio: f32,
}

#[derive(Debug, Clone, PartialEq)]
pub struct DatasetDiffSummary {
    pub before_row_count: u64,
    pub after_row_count: u64,
    pub row_count_delta: i64,
    pub columns: Vec<DatasetDiffColumn>,
    pub missingness: Vec<DatasetDiffMissingnessDelta>,
}
```

Add a builder that consumes the current local source table representation:

```rust
pub fn dataset_diff_summary(
    before: &LoadedSourceTable,
    after: &LoadedSourceTable,
) -> DatasetDiffSummary;
```

If `LoadedSourceTable` lives in `rawscope-data` and render cannot depend on it
cleanly, put the raw table comparison in `rawscope-data` and keep visual diff
projection in `rawscope-render`. Follow the existing crate dependency direction;
do not introduce a dependency cycle.

Workbench input:

- Add an optional CLI argument such as `--compare-input <path>`.
- Load the comparison input through the same local data loader as the primary
  input.
- If the comparison input cannot be loaded, return the existing user-facing
  load error path with context naming the comparison file.
- Store state:

```rust
pub(crate) comparison_dataset: Option<LocalDatasetState>,
pub(crate) dataset_diff_summary: Option<DatasetDiffSummary>,
```

Add `WorkbenchSurface::DatasetDiff` and render it only when
`dataset_diff_summary` exists.

UI rules:

- Show row count before/after/delta.
- Show added/removed/type-changed columns.
- Show top missingness deltas by absolute percentage-point change.
- Allow clicking a missingness delta row to reuse the missingness selection
  summary if the changed column still exists in the active dataset.
- Keep the panel compact and operational.

#### Before / After

**Before:**

RawScope can inspect one dataset at a time and show missingness, but users have
no bounded way to compare a candidate replacement dataset against a baseline.

**After:**

RawScope can load a primary and comparison input, compute a bounded summary of
schema and missingness changes, and expose those changes as a workbench surface.

#### Migration Notes

- Existing single-input behavior remains unchanged.
- Diff behavior is opt-in through an explicit comparison input.
- No persistent project format is introduced.
- No row-level data is modified.

#### Misinterpretations To Prevent

- Wrong interpretation: implement a data merge tool.
  Correct rule: compute and display bounded comparison summaries only.
- Wrong interpretation: infer keys or compare individual entities.
  Correct rule: compare table-level schema, row count, and missingness.
- Wrong interpretation: add a separate diff app.
  Correct rule: add a workbench surface using existing load and UI patterns.
- Wrong interpretation: add many docs.
  Correct rule: keep any docs limited to CLI argument behavior if needed.

#### Invariants

- Diff is opt-in; no comparison input means no diff surface.
- Primary dataset behavior is unchanged without `--compare-input`.
- Missingness ratios handle zero-row datasets without panics.
- Column comparison is by column name and observed type only.
- Diff summaries do not retain unbounded source rows.
- Workbench clears diff state when either dataset changes.

#### Agent Handoff Context

This task gives RawScope a practical data-quality workflow. The key is restraint:
the user gets useful before/after context, but the codebase does not become a
general diff or ETL system.

## Final Notes

- Recommended implementation order: dependency-correct summary module, summary
  tests, CLI load path, workbench surface, UI renderer.
- Unresolved questions: whether keyed row matching belongs in a later feature.
- Risks: crate dependency direction may push the raw comparison builder into
  `rawscope-data`; follow the existing architecture instead of forcing render
  ownership.
- Areas that need human review before implementation: CLI flag name and diff
  surface label.
