### T009 - Add Flagship Dataset Profile Contract

#### Objective

Add a code-level dataset profile contract for a human-reviewed flagship dataset
binding, starting with Lichess-style chess game data. This turns the research
takeaway on flagship demos into durable app behavior without adding a downloader,
license claims, or benchmark promises.

#### Scope

- Add a data-owned dataset profile module.
- Define required columns and default view bindings for the first flagship
  profile.
- Add workbench CLI/profile plumbing that applies bindings only when required
  columns exist.
- Surface profile identity in evidence/report metadata once T007 is available.
- Keep the profile local-file based and human-reviewed.

#### Out of Scope

- Do not download datasets.
- Do not claim any dataset size, license, or benchmark result in code comments
  or UI text.
- Do not add many dataset profiles at once.
- Do not add a synthetic flagship dataset.
- Do not add broad documentation beyond concise CLI/profile behavior notes if
  needed.

#### Blocked By

T007, T008

#### Why It Is Blocked

The profile should feed evidence metadata from T007 and should not conflict with
the comparison-input behavior introduced by T008.

#### Implementation Details

Create `crates/rawscope-data/src/dataset_profile.rs`:

```rust
//! Human-reviewed dataset profile contracts for local flagship datasets.

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum DatasetProfileId {
    LichessGames,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DatasetProfileColumnKind {
    Numeric,
    Integer,
    Text,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DatasetProfileColumn {
    pub name: &'static str,
    pub kind: DatasetProfileColumnKind,
    pub required: bool,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DatasetProfileViewBinding {
    pub view: DatasetProfileViewKind,
    pub x_column: &'static str,
    pub y_column: Option<&'static str>,
    pub lane_column: Option<&'static str>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DatasetProfile {
    pub id: DatasetProfileId,
    pub display_name: &'static str,
    pub required_columns: &'static [DatasetProfileColumn],
    pub default_bindings: &'static [DatasetProfileViewBinding],
}
```

Add functions:

```rust
pub fn dataset_profile(id: DatasetProfileId) -> &'static DatasetProfile;

pub fn parse_dataset_profile_id(value: &str) -> Result<DatasetProfileId, DatasetProfileParseError>;

pub fn validate_dataset_profile(
    profile: &DatasetProfile,
    available_columns: &[LocalDatasetColumn],
) -> Result<(), DatasetProfileValidationError>;
```

Map these profile kinds onto the existing `LoadedColumnKind::{Integer, Float,
String, Empty}` schema summaries. Do not invent timestamp or boolean kinds until
the loaders expose them.

First profile:

- Use a Lichess-style profile id and display name.
- Required columns must be conservative and human-reviewable.
- Bindings should choose one scatter and one timeline-friendly view only if the
  columns are present and typed compatibly.
- Profile code should not state dataset size, license, or download URL.

Workbench plumbing:

- Add optional CLI argument:

```text
--profile lichess-games
```

- Parse profile id before local dataset binding.
- Validate required columns after local dataset load.
- Apply default bindings only after validation succeeds.
- Store active profile identity:

```rust
pub(crate) active_dataset_profile: Option<DatasetProfileId>,
```

- Include active profile identity in evidence/report metadata from T007.
- If `--compare-input` from T008 is also present, profile applies to the primary
  input only unless later requirements say otherwise.

Error behavior:

- Missing required columns should list the missing column names.
- Type mismatches should name the column and expected kind.
- Unknown profile id should list supported ids.

#### Before / After

**Before:**

RawScope can load arbitrary local files, but there is no code-level contract for
the flagship dataset story. Any demo binding would be informal and easy to
break.

**After:**

RawScope has a typed, validated profile path that applies known view bindings
for a flagship local dataset when the input file matches the expected schema.

#### Migration Notes

- Existing local input behavior remains unchanged without `--profile`.
- Profile support is opt-in and local-file based.
- No downloader or bundled dataset is added.
- Profile metadata can later support more datasets without changing workbench
  load flow.

#### Misinterpretations To Prevent

- Wrong interpretation: bundle or fetch Lichess data.
  Correct rule: validate and bind a user-provided local file only.
- Wrong interpretation: make marketing claims about scale.
  Correct rule: profile code contains schema and binding facts only.
- Wrong interpretation: add many profiles before one is solid.
  Correct rule: add one human-reviewed first profile.
- Wrong interpretation: put profile strings only in the workbench.
  Correct rule: data crate owns the contract; workbench applies it.

#### Invariants

- `--profile` is optional.
- Unknown profiles fail before view binding.
- Missing required columns fail with actionable names.
- Profile application does not mutate source data.
- Comparison input from T008 is not silently treated as the profiled dataset.
- Evidence metadata includes profile identity only when a profile was actually
  applied.
