### T002 - Add Axis And Lane Context Overlays

#### Objective

Make scatter/timeline density views readable without relying on title-bar or
status-bar text. Add structured axis ticks, units, and timeline lane labels that
can be shown over the active density surface.

#### Scope

- Create `crates/rawscope-render/src/view_axes.rs`.
- Add dependency-free render-side axis context structs and deterministic tick
  generation for `F32Range` and `U64Range`.
- Add timeline lane-label selection for visible lane rows using
  `DatasetIdentity::lane_labels`.
- Create `apps/rawscope-workbench/src/ui_view_context.rs` for the egui overlay.
- Wire the overlay into `apps/rawscope-workbench/src/ui_controls.rs` or a
  similarly focused UI owner without adding more bulk to `ui.rs`.
- Keep the bottom status bar as a fallback; do not remove it in this task.

#### Out of Scope

- Do not implement a full charting axis system.
- Do not add free-form axis styling, themes, or a general UI framework.
- Do not render text through WGPU in this task; use the existing egui shell.
- Do not change data ingestion or density computation.
- Do not add screenshots, visual diff tests, or startup-only tests.

#### Blocked By

T001

#### Why It Is Blocked

The overlay should use the explicit density encoding context from T001 so the
view can show axes and encoding as one coherent visual truthfulness layer.

#### Implementation Details

Create `crates/rawscope-render/src/view_axes.rs`:

```rust
//! Axis and lane context for density views.

use rawscope_core::{F32Range, U64Range};

#[derive(Debug, Clone, PartialEq)]
pub struct AxisTick {
    pub fraction: f32,
    pub label: String,
}

#[derive(Debug, Clone, PartialEq)]
pub struct NumericAxisContext {
    pub label: String,
    pub ticks: Vec<AxisTick>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterAxesContext {
    pub x: NumericAxisContext,
    pub y: NumericAxisContext,
}

#[derive(Debug, Clone, PartialEq)]
pub struct TimelineLaneLabel {
    pub lane: u32,
    pub fraction: f32,
    pub label: String,
}

#[derive(Debug, Clone, PartialEq)]
pub struct TimelineAxesContext {
    pub time: NumericAxisContext,
    pub lanes: Vec<TimelineLaneLabel>,
}

pub fn scatter_axes_context(
    x_range: F32Range,
    y_range: F32Range,
    x_label: impl Into<String>,
    y_label: impl Into<String>,
    max_ticks: usize,
) -> ScatterAxesContext;

pub fn timeline_axes_context(
    time_range: U64Range,
    lane_count: u32,
    lane_labels: &[String],
    max_time_ticks: usize,
    max_lane_labels: usize,
) -> TimelineAxesContext;
```

Tick rules:

- `max_ticks` and `max_time_ticks` must be clamped to at least `2`.
- Fractions must be in `0.0..=1.0`.
- Float labels should use compact formatting such as `"{value:.1}"` for the
  first slice.
- Timeline time labels should remain integer strings for now.
- Lane labels should sample evenly from visible lanes and use
  `lane_labels[lane]` when available, otherwise `lane-{lane}`.

Export from `crates/rawscope-render/src/lib.rs`:

```rust
mod view_axes;

pub use view_axes::{
    scatter_axes_context, timeline_axes_context, AxisTick, NumericAxisContext,
    ScatterAxesContext, TimelineAxesContext, TimelineLaneLabel,
};
```

Overlay behavior:

- Place x-axis ticks along the bottom of the central view area.
- Place y-axis labels or lane labels along the left side of the central view
  area, inside the visible work area but away from the top toolbar.
- Use small monospace or restrained text. Do not create a card over the canvas.
- Keep overlay non-interactive so it does not steal brush/pan input.

#### Migration Notes

- Existing status bar axis labels remain intact.
- No public serialized schema changes in this task.
- Timeline timestamps remain raw integers until a later timestamp-normalization
  task is explicitly approved.

#### Misinterpretations To Prevent

- Wrong interpretation: build a generic charting axis library.
  Correct rule: only scatter x/y and timeline time/lane context for current
  density views.
- Wrong interpretation: push UI text rendering into WGPU.
  Correct rule: use egui overlay in the workbench for this slice.
- Wrong interpretation: show every timeline lane label.
  Correct rule: cap visible labels with `max_lane_labels` and sample
  deterministically.
- Wrong interpretation: replace row evidence with visual labels.
  Correct rule: axes make the view readable; evidence remains separate.

#### Invariants

- Axis ticks are deterministic for the same range and max tick count.
- Tick fractions are clamped to `0.0..=1.0`.
- Timeline lane labels use dataset lane labels when available.
- Overlay does not change density counts, brush geometry, or evidence.
- No general charting abstractions are introduced.
