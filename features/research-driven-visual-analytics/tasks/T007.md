### T007 - Add Evidence V3 Visual Context

#### Objective

Upgrade exported evidence so saved artifacts explain how the view was encoded,
what the selected rows mean against the baseline, and what aggregate context
surrounded the selection. This turns visual improvements into durable evidence
rather than transient UI hints.

#### Scope

- Add v3 evidence/export code paths for scatter and timeline selections.
- Include density encoding from T001.
- Include selected-vs-baseline comparison summaries from T004.
- Include aggregate overview context from T006 using bounded counts and row
  samples.
- Route the workbench report bundle to v3 exports by default while preserving
  existing v2 export functions.
- Split new export code into new modules rather than growing already large
  export files.

#### Out of Scope

- Do not remove existing v1 or v2 export APIs in this task.
- Do not add a new external file format.
- Do not add screenshots or image diff artifacts.
- Do not add benchmark claims or dataset-scale claims.
- Do not export unbounded row ids from aggregate bins.

#### Blocked By

T001, T004, T006

#### Why It Is Blocked

V3 evidence needs the explicit visual encoding contract, comparison summaries,
and aggregate overview cache before it can represent the research takeaways
truthfully.

#### Implementation Details

Use new schema constants:

```rust
pub const SCATTER_SELECTION_EVIDENCE_V3_SCHEMA_VERSION: u32 = 3;
pub const TIMELINE_SELECTION_EVIDENCE_V3_SCHEMA_VERSION: u32 = 3;
```

Create v3 evidence structs in focused modules. Follow the existing pattern:
evidence structs are Rust data models, and export modules own serde artifact
wrappers.

```rust
#[derive(Debug, Clone, PartialEq)]
pub struct ScatterSelectionEvidenceV3 {
    pub schema_version: u32,
    pub dataset_identity: DatasetIdentity,
    pub view: ScatterEvidenceViewV3,
    pub selected_row_count: usize,
    pub selected_percentage: f32,
    pub selected_row_id_sample: Vec<RowId>,
    pub selected_record_sample: Vec<SelectedPointSampleV2>,
    pub selected_source_column_names: Vec<String>,
    pub selected_source_row_sample: Vec<SelectedSourceRowSample>,
    pub comparison: ScatterSelectionComparison,
    pub aggregate_context: ScatterAggregateEvidenceContext,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ScatterEvidenceViewV3 {
    pub x_range: F32Range,
    pub y_range: F32Range,
    pub grid_width: u32,
    pub grid_height: u32,
    pub density_encoding: DensityEncoding,
}
```

Mirror the shape for timeline:


Aggregate evidence context should be compact and bounded:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AggregateEvidenceBin {
    pub bin_x: u32,
    pub bin_y: u32,
    pub count: u32,
    pub row_id_sample: Vec<u64>,
}
```

Only include bins that are relevant to the selection or to the densest context
around it. A useful first rule is:

- selected bins intersecting selected row samples;
- top N densest bins in the same aggregate overview;
- N controlled by a named constant near the export module, such as
  `MAX_AGGREGATE_CONTEXT_BINS`.

Do not serialize the entire aggregate cache by default.

Add export functions:

```rust
pub fn scatter_selection_evidence_v3_json(
    evidence: &ScatterSelectionEvidenceV3,
) -> Result<String, ScatterSelectionExportError>;

pub fn scatter_selection_evidence_v3_markdown(
    evidence: &ScatterSelectionEvidenceV3,
) -> String;

pub fn timeline_selection_evidence_v3_json(
    evidence: &TimelineSelectionEvidenceV3,
) -> Result<String, TimelineSelectionExportError>;

pub fn timeline_selection_evidence_v3_markdown(
    evidence: &TimelineSelectionEvidenceV3,
) -> String;
```

Route workbench exports:

- If v3 context exists, write v3 JSON and Markdown as the default evidence
  artifact names.
- Keep existing v2 functions callable for direct Rust users.
- Update report bundle `visual-context.txt` content so it states encoding,
  normalization, comparison baseline, and aggregate context limits.

Because existing export files exceed the preferred size, do not add v3
formatters to them. Add new files and re-export intentionally from `lib.rs`.

#### Before / After

**Before:**

Evidence can show selected rows and view metadata, but the artifact does not
fully explain density transform, comparison baseline, or dense-region aggregate
context.

**After:**

Evidence v3 captures visual encoding, selected-vs-baseline comparison, and
bounded aggregate context so reviewers can understand what the visual claim was
based on.

#### Migration Notes

- Existing v2 evidence structs and functions stay available.
- Report bundle defaults move to v3 when required inputs are available.
- JSON artifact readers should use `schema_version` rather than assuming shape.
- V3 Markdown should remain compact and evidence-focused.

#### Misinterpretations To Prevent

- Wrong interpretation: add more prose to existing reports.
  Correct rule: add structured v3 evidence fields and concise formatting.
- Wrong interpretation: dump the full aggregate cache into JSON.
  Correct rule: export bounded context bins only.
- Wrong interpretation: replace v2 immediately.
  Correct rule: preserve v2 APIs and route workbench defaults to v3.
- Wrong interpretation: put new code into already large export files.
  Correct rule: v3 gets dedicated modules.

#### Invariants

- `schema_version` is exactly `3` for v3 artifacts.
- Density encoding in evidence matches the active workbench setting.
- Comparison baseline is explicit and derived from T004 summaries.
- Aggregate context is bounded by a named constant.
- V2 exports continue to compile and pass existing tests.
- V3 export does not require a screenshot or external renderer.
- V3 serde wrappers live in export modules, matching the current v1/v2 pattern.
