### T003 - Add Generic Visual Row Records

#### Objective
Stop forcing both synthetic and local data through types named `SyntheticPointRecord` and `SyntheticEventRecord`. Add generic scatter/timeline view records that can support local evidence while preserving synthetic annotations where they exist.

#### Scope
- Add generic view-record types to `crates/rawscope-data/src/dataset.rs` or a narrow `crates/rawscope-data/src/visual_record.rs` module.
- Migrate density, brush, evidence, and workbench APIs from synthetic record names to generic record names.
- Keep synthetic generator-specific enums for synthetic pattern labels, but make them optional annotations on generic records.
- Preserve current behavior for synthetic datasets and CSV datasets.
- Update tests that construct records directly.

#### Out of Scope
- Do not remove synthetic generators.
- Do not add local row tables in this task; that belongs to T004.
- Do not change evidence JSON schemas; that belongs to T005.
- Do not add a generalized dataframe row type.
- Do not add GPU row-id preservation.

#### Blocked By
T002

#### Why It Is Blocked
Generic records should carry or reference the new dataset identity model, and local/synthetic source ownership should be explicit before renaming shared record paths.

#### Implementation Details
- Prefer a new file if `dataset.rs` grows beyond simple metadata:
```rust
// crates/rawscope-data/src/visual_record.rs
use rawscope_core::RowId;

use crate::{SyntheticEventType, SyntheticPointCategory};

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ScatterPointKind {
    Synthetic(SyntheticPointCategory),
    Unclassified,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ScatterPointRecord {
    pub row_id: RowId,
    pub x: f32,
    pub y: f32,
    pub kind: ScatterPointKind,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TimelineEventKind {
    Synthetic(SyntheticEventType),
    Unclassified,
}

#[derive(Debug, Clone, PartialEq)]
pub struct TimelineEventRecord {
    pub row_id: RowId,
    pub timestamp: u64,
    pub lane: u32,
    pub value: f32,
    pub kind: TimelineEventKind,
}
```

- Update render APIs to take `&[ScatterPointRecord]` or `&[TimelineEventRecord]`.
- Update selected counts:
  - `SelectedCategoryCounts` should either become `SelectedPointKindCounts` or keep the name while counting only `ScatterPointKind::Synthetic`.
  - Add `unclassified: usize` to selected point counts so CSV selections are not counted as cluster.
  - `SelectedEventTypeCounts` should add `unclassified: usize` or be replaced by `SelectedTimelineKindCounts`.
- Do not use type aliases as a compatibility shortcut if field names change from `category`/`event_type` to `kind`. A type alias would compile in some references but still break old field access and confuse future agents.
- If public compatibility is required, use explicit deprecated wrapper structs with the old fields and `From` conversions into the new records, or keep the old structs only inside synthetic generator modules until all call sites migrate. Prefer a direct migration if the API is still private enough.

#### Migration Notes
- Existing code that reads `point.category` should change to match `point.kind`.
- Existing code that reads `event.event_type` should change to match `event.kind`.
- Export v1 may continue formatting synthetic kind values, but CSV/unclassified values must not be reported as synthetic cluster/background/spike labels.
- Existing tests should be updated to assert unclassified local rows where applicable.

#### Misinterpretations To Prevent
- Wrong interpretation: "Rename the type but keep local CSV categorized as Cluster."
  Correct rule: local CSV records must use an unclassified/local-neutral kind.
- Wrong interpretation: "Create a generic dataframe row model."
  Correct rule: this task only adds view records required by scatter/timeline visual paths.
- Wrong interpretation: "Remove synthetic annotations."
  Correct rule: preserve synthetic labels as optional view-record kind metadata.
- Wrong interpretation: "Use `pub type SyntheticPointRecord = ScatterPointRecord` even though the fields changed."
  Correct rule: avoid field-incompatible aliases; migrate call sites or use explicit wrapper conversions.

#### Invariants
- Local data must not be labeled as synthetic cluster/background/outlier/spike/stale-lane.
- Field-incompatible type aliases must not be used as a migration shortcut.
- Scatter and timeline density outputs must remain count-equivalent before and after the rename.
- Existing synthetic tests must still prove deterministic injected patterns.
- No new broad dependency is introduced.
