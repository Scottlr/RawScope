### T005 - Publish Evidence Schema V2

#### Objective
Add source-aware scatter and timeline evidence v2 artifacts that can describe synthetic and local CSV selections honestly, including dataset identity, field bindings, view configuration, lane labels, and selected source-row samples.

#### Scope
- Add v2 evidence structs and artifact formatters in `rawscope-render`.
- Keep v1 JSON/Markdown functions and docs unless the user explicitly approves removal.
- Add v2 schema docs under `docs/schemas/`.
- Add workbench export routing that writes v2 artifacts by default or with an explicit transition constant.
- Include source-row samples for local CSV selections using T004 source rows.
- Include current view configuration and finalized brush range.
- Update manifest records to identify v2 artifacts.

#### Out of Scope
- Do not add screenshots/rendered image data; that belongs to T010.
- Do not add full selected row table UI; that belongs to T006/T007.
- Do not add GPU row-id preservation.
- Do not add HTML reports or styling.
- Do not remove v1 compatibility without human approval.

#### Blocked By
T003, T004

#### Why It Is Blocked
Evidence v2 needs generic visual records so local rows are not synthetic-labeled, and it needs retained source rows to include meaningful selected local row samples.

#### Migration Notes
- v1 should remain available for existing tests and schema docs.
- v2 can become the workbench default only if tests prove manifest records identify schema version 2.
- If both versions are exported, use distinct filenames or manifest entries so consumers do not confuse schemas.

#### Misinterpretations To Prevent
- Wrong interpretation: "Patch v1 in place."
  Correct rule: add v2 or explicit compatibility behavior; do not silently mutate v1.
- Wrong interpretation: "Include every selected row by default."
  Correct rule: include deterministic bounded samples unless T006 defines exact-table behavior.
- Wrong interpretation: "Call local evidence synthetic."
  Correct rule: v2 wording and JSON must distinguish synthetic and local CSV sources.
- Wrong interpretation: "Add serde to `rawscope-data` so DTO conversion is easier."
  Correct rule: keep serialization at the artifact boundary in `rawscope-render`.

#### Invariants
- Same selection over the same dataset and view must produce deterministic v2 row samples.
- v1 tests must still pass unless the user approves a breaking cleanup.
- v2 must include dataset identity and field bindings.
- v2 must serialize dataset identity through render-owned artifact DTOs, not serde derives added to data models.
- v2 must not claim screenshot, final report, benchmark, or GPU row-id support.
