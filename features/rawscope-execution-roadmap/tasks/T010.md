### T010 - Add Evidence Report Bundles

#### Objective
Upgrade individual JSON/Markdown exports into report bundles that preserve evidence, manifest metadata, and rendered visual context for a finalized selection.

#### Scope
- Add a report-bundle writer that creates a directory per export.
- Include evidence v2 JSON, Markdown, manifest metadata, and a rendered visual artifact.
- Add explicit screenshot/readback design before adding an image encoding dependency.
- Keep exports local-first under `target/rawscope-exports/` or a user-selected local path from the UI.
- Add tests for bundle paths, manifest records, and deterministic non-image metadata.

#### Out of Scope
- Do not add cloud publishing or collaboration.
- Do not add report templates beyond a minimal local bundle.
- Do not add HTML styling unless explicitly approved.
- Do not claim final audit/compliance reporting.
- Do not add performance benchmarks in this task.

#### Blocked By
T005, T007

#### Why It Is Blocked
Report bundles need source-aware evidence v2 and a UI/export surface that can present export status and eventually choose local output destinations.

#### Related Code
- `apps/rawscope-workbench/src/app_export.rs` - export routing.
- `apps/rawscope-workbench/src/app_export_files.rs` - path and manifest helpers.
- `crates/rawscope-render/src/scatter_selection_export.rs` and `timeline_selection_export.rs` - evidence formatters.
- `rawscope-gpu/src/context.rs` - render frame/surface ownership.
- `crates/rawscope-render/src/*density_renderer.rs` - current render passes.

#### Implementation Touchpoints
- Read first: T005 v2 export code, T007 UI state, `app_export_files.rs`, `rawscope-gpu/src/context.rs`.
- Edit first: `apps/rawscope-workbench/src/app_export_files.rs` or create `app_report_bundle.rs`.
- Symbols to search: `SelectionExportPaths`, `write_scatter`, `write_timeline`, `manifest.jsonl`, `render_frame`.
- Required structural changes: add bundle path type, bundle manifest type, visual context capture plan, and export route.
- Do not edit: Parquet, DataFusion, benchmarks, plugin systems.

- Stop and ask: before adding an image dependency or implementing WGPU surface readback if dependency choice has not been approved.

#### Implementation Details
- Add a bundle path type:
```rust
pub(crate) struct EvidenceReportBundlePaths {
    pub(crate) bundle_dir: PathBuf,
    pub(crate) evidence_json_path: PathBuf,
    pub(crate) evidence_markdown_path: PathBuf,
    pub(crate) visual_context_path: PathBuf,
    pub(crate) manifest_path: PathBuf,
    pub(crate) export_timestamp_unix_ms: u128,
    pub(crate) export_counter: u64,
}
```
- Add a manifest record:
```rust
#[derive(Serialize)]
struct EvidenceReportBundleManifestRecord<'a> {
    artifact_kind: &'static str,
    schema_version: u32,
    bundle_dir: &'a Path,
    evidence_json_path: &'a Path,
    evidence_markdown_path: &'a Path,
    visual_context_path: &'a Path,
    selected_row_count: usize,
    export_timestamp_unix_ms: u128,
    export_counter: u64,
}
```
- Bundle directory format:
```text
target/rawscope-exports/report-<view>-<unix-ms>-<counter>/
  evidence.json
  evidence.md
  visual-context.<ext>
  manifest.json
```
- For visual context, create a design note in `docs/TECH_DECISIONS.md` before implementation:
```markdown
## ADR-0018: Local Report Visual Context Capture

- Decision: ...
- Status: Accepted
- Context: ...
- Consequences: ...
```
- Preferred implementation path after human approval:
  - read back a render target or surface-compatible texture through WGPU;
  - encode PNG with a narrow dependency such as `png` if approved;
  - avoid broad `image` dependency unless the additional formats are needed.
- If image capture is not approved in the first PR, write a placeholder `visual-context.txt` that records view type, ranges, grid size, and the reason image capture is deferred. Do not call that the final visual report.

#### Migration Notes
- Existing flat export paths can remain available while report bundles mature.
- Bundle manifests should include enough metadata to locate all files without parsing evidence JSON.
- Screenshot/readback may be staged if dependency/design approval is not immediate.

#### Misinterpretations To Prevent
- Wrong interpretation: "A Markdown plus JSON pair is already a report bundle."
  Correct rule: bundle must include manifest metadata and visual context, or explicitly remain a staged placeholder.
- Wrong interpretation: "Upload reports."
  Correct rule: local filesystem only.
- Wrong interpretation: "Use screenshots as evidence without row/source context."
  Correct rule: visual context complements evidence v2; it does not replace row evidence.

#### Invariants
- Report bundles are local-first.
- Evidence v2 remains the source of analytical truth.
- Visual context must identify the exact view configuration it represents.
- No cloud, collaboration, or publishing features are added.

#### Acceptance Criteria
- [ ] Bundle path helpers create collision-safe directories.
- [ ] Bundle manifest records evidence, visual context, timestamps, and counters.
- [ ] Workbench can export a bundle for scatter and timeline selections.
- [ ] Screenshot/readback design is documented before image encoding lands.
- [ ] Tests cover path collision and manifest shape.

#### Testing Guidance
- Extend `apps/rawscope-workbench/src/app_export_files.rs` tests or add `app_report_bundle.rs` tests.
- Avoid GPU-dependent screenshot tests unless a headless render target is available and stable.
- Run `cargo test -p rawscope-workbench`.

#### Agent Handoff Context
This task turns RawScope evidence into a shareable local artifact. Keep it humble and reproducible. Visual context is important, but not at the cost of fuzzy evidence semantics.
