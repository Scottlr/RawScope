### T006 - Add CPU-Backed Row Drilldown

#### Objective
Add a CPU-backed selected-row drilldown model so users can inspect exact or bounded sampled rows from finalized selections without claiming GPU row-id preservation.

#### Scope
- Add a drilldown data model that can represent selected row ids, source row values, and visual record values.
- Build drilldown results from current CPU-held scatter/timeline records and T004 source rows.
- Add workbench methods that refresh drilldown when a brush finalizes and clear it when the selection clears or dataset changes.
- Add title/log hints only as a temporary surface until T007 adds visible UI.
- Add deterministic tests for selected row ordering, sample limits, and empty selections.

#### Out of Scope
- Do not add egui UI in this task.
- Do not add GPU row-id preservation.
- Do not export report bundles or screenshots.
- Do not add arbitrary query/filter expressions.
- Do not add full dataframe operations.

#### Blocked By
T004, T005

#### Why It Is Blocked
Drilldown needs retained source rows and should align with evidence v2 sample policy so UI, export, and logs do not disagree.

- `crates/rawscope-render/src/scatter_brush.rs` and `timeline_brush.rs` - selection containment logic.

#### Implementation Details
- Add `crates/rawscope-render/src/selection_drilldown.rs`:
```rust
use rawscope_core::RowId;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DrilldownColumn {
    pub name: String,
}

#[derive(Debug, Clone, PartialEq)]
pub struct DrilldownRow {
    pub row_id: RowId,
    pub values: Vec<String>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct DrilldownConfig {
    pub max_rows: usize,
}

impl Default for DrilldownConfig {
    fn default() -> Self {
        Self { max_rows: 100 }
    }
}

#[derive(Debug, Clone, PartialEq)]
pub struct SelectionDrilldown {
    pub selected_row_count: usize,
    pub displayed_row_count: usize,
    pub rows_are_sampled: bool,
    pub columns: Vec<DrilldownColumn>,
    pub rows: Vec<DrilldownRow>,
}
```
- Add build functions with explicit source-row inputs:
```rust
pub fn scatter_selection_drilldown(

    config: DrilldownConfig,
```

#### Migration Notes
- Existing brush/evidence behavior remains.
- Drilldown is CPU-backed and bounded by `DrilldownConfig::max_rows`.
- Existing exports can use evidence v2 samples; full UI appears in T007.

#### Misinterpretations To Prevent
- Wrong interpretation: "This proves GPU row ids."
  Correct rule: all drilldown in this task is CPU-backed.
- Wrong interpretation: "Dump every selected row into logs."
  Correct rule: logs include counts only; rows are held in state for UI/export use.
- Wrong interpretation: "Add SQL-like filtering."
  Correct rule: selection is still brush-defined.
- Wrong interpretation: "Assume loaded source rows are still available in workbench state."
  Correct rule: explicitly store source rows in workbench state or an active dataset owner before building drilldown.

#### Invariants
- Drilldown rows are deterministic lowest-row-id rows.
- Empty selections produce zero counts and no rows.
- Dataset changes and brush clearing remove stale drilldown.
- Source-row values preserve original column order.
- Workbench drilldown must use retained source-row state for local data and visual fallback rows for synthetic data.

#### Acceptance Criteria
- [ ] Scatter selection finalization builds `SelectionDrilldown`.

- [ ] Drilldown uses source rows for local CSV and visual fallback rows for synthetic data.
- [ ] Workbench state retains source rows or an active dataset owner for local datasets.
- [ ] Drilldown clears with brush clear and dataset changes.
- [ ] Tests cover ordering, limits, source rows, fallback rows, and empty selection.
