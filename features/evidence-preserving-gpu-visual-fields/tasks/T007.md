### T007 - Add Bounded Generic Category Channel Indexes

#### Objective

Extend the final typed store/index architecture with reusable row-aligned
category IDs and produce a bounded analysis-owned layer plan that gives category
composition exact, explicit Value/Other/Missing/Invalid semantics.

#### Scope

- Extend the category index created by open remediation T009/T015 rather than
  adding a second source-row category map.
- Assign stable category IDs to tracked dictionary values for one dataset
  generation and retain one compact row-aligned category code per row.
- Support every category kind admitted by T001 (`Utf8`, `Bool`, `I64`, and
  `U64`) without converting typed identity back into source-row strings.
- Represent missing and invalid values explicitly; never encode them as an empty
  string or ordinary category.
- Add an analysis-owned `CategoryLayerPlan` selecting a bounded reviewed set of
  visible categories plus explicit Other/Missing/Invalid layers as required.
- Build layer plans on a bounded job, cache them by dataset/column/selection
  identity, and derive only a bounded stable-value-to-layer lookup. Reuse the
  store-owned row-aligned category codes instead of copying all rows per plan.
- Carry exact/estimated/truncated accuracy from the underlying category index and
  prevent an estimated value from being labelled exact.

#### Out of Scope

- No GPU upload/aggregation, colors, UI selector, filtering changes, arbitrary
  group-by, user-defined category expressions, hierarchy, or profile-specific
  category list.
- Do not make category indexes unbounded to support composition.
- No plugin registry for categorical encoders.

#### Blocked By

T001.

#### Why It Is Blocked

The category channel must bind to one validated `VisualFieldMapping` and stable
`ColumnId`; it cannot use display names or scatter-specific records.

#### Related Code

- Final store category index from remediation T009.
- `rawscope-analysis/src/profile.rs` and T015 accuracy/leader contracts.
- `rawscope-analysis/src/cohort.rs` - missing/invalid policy and row alignment.
- Current `rawscope-data/src/visual_field_catalog.rs` and filter category counts,
  which must not become a second owner.
- T001 `VisualFieldMapping` and T003 resource budgets.

#### Implementation Details

Extend the final data index with equivalent concrete contracts:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct CategoryValueId(u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CategoryCodeKind {
    Value(CategoryValueId),
    Untracked,
    Missing,
    Invalid,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CategoryCodeLayout {
    pub tracked_value_count: u32,
    pub untracked_code: u32,
    pub missing_code: u32,
    pub invalid_code: u32,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub enum CategoryIndexValue {
    Utf8(Arc<str>),
    Bool(bool),
    I64(i64),
    U64(u64),
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct IndexedCategoryValue {
    pub id: CategoryValueId,
    pub value: CategoryIndexValue,
    pub label: Arc<str>,
    pub row_count: u64,
    pub accuracy: CategoryIndexAccuracy,
}

pub struct CategoryMembershipIndex {
    dataset_generation: DatasetGeneration,
    column_id: ColumnId,
    values: Arc<[IndexedCategoryValue]>,
    code_layout: CategoryCodeLayout,
    row_codes: Arc<[u32]>,
}
```

The store exposes a checked `code(row_id) -> CategoryCodeKind` accessor plus a
borrowed/shared packed-code slice for GPU upload. Tracked value IDs are dense and
the three special codes are checked, distinct, and outside the tracked range.
Do not inflate row storage to the illustrative typed enum.
`CategoryIndexValue` remains canonical identity. `label` is a presentation
projection and may not merge typed values that happen to format alike.

Create in analysis:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct CategoryLayerId(u8);

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum CategoryLayerKind {
    Value(CategoryValueId),
    Other,
    Missing,
    Invalid,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CategoryLayer {
    pub id: CategoryLayerId,
    pub kind: CategoryLayerKind,
    pub label: Arc<str>,
    pub row_count: u64,
    pub accuracy: CategoryIndexAccuracy,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct CategoryLayerLookup {
    pub value_layers: Arc<[CategoryLayerId]>,
    pub untracked_layer: Option<CategoryLayerId>,
    pub missing_layer: Option<CategoryLayerId>,
    pub invalid_layer: Option<CategoryLayerId>,
}

pub struct CategoryLayerPlan {
    dataset_generation: DatasetGeneration,
    column_id: ColumnId,
    layers: Arc<[CategoryLayer]>,
    lookup: CategoryLayerLookup,
    omitted_value_count: u64,
}
```

Use T001's one `MAX_CATEGORY_COMPOSITION_LAYERS`; human review approves its
final value. The maximum includes Other/Missing/Invalid. User-selected tracked
values are ordered deterministically by explicit selection order, otherwise
count descending then stable category ID. All unselected/untracked valid values
map to `Other` when any exist.

Missing/invalid rows map to their own layer only when cohort policy includes
them; otherwise they retain exclusion counts outside rendered membership. Every
cohort-included row maps to exactly one layer through `CategoryLayerLookup`.
`value_layers` is indexed by stable tracked `CategoryValueId`; untracked,
missing, and invalid codes use explicit assignments. The plan is therefore
bounded by tracked index values/layers and does not allocate one entry per row.

#### Migration Notes

- Reuse/remove old visual catalog category scans as remediation T015/T034
  requires; do not preserve them for UI convenience.
- Existing filters continue to match source category values through the final
  index and cohort owner.
- No wire compatibility changes occur in this task.

#### Misinterpretations To Prevent

- Wrong interpretation: take the first N category strings encountered. Correct
  rule: stable indexed values and deterministic reviewed ordering select layers.
- Wrong interpretation: omit values beyond the visible palette. Correct rule:
  exact residual membership maps to a named Other layer.
- Wrong interpretation: missing is Other. Correct rule: missing and invalid are
  distinct states governed by cohort policy.
- Wrong interpretation: rebuild a row string map for each frame/filter. Correct
  rule: reuse one generation-owned category membership index and cache plans.

#### Invariants

- Row category codes align one-to-one with dataset row IDs/generation.
- Packed code layout is checked, unambiguous, and shared with GPU consumers.
- Category identity remains typed; display formatting cannot merge values.
- Every included row maps to exactly one rendered layer.
- Changing visible layers does not rebuild the row-aligned category index.
- Other count equals all included valid values not represented by explicit
  value layers.
- Missing and invalid remain distinct and policy-driven.
- Layer count is positive, bounded, and fits GPU index representation.
- Accuracy/truncation is preserved from source index to UI/evidence consumers.

## Final Notes

- Recommended order: final index extension, typed accessors, layer plan,
  generation/cache identity, old scan removal.
- Unresolved questions: maximum layers and treatment of approximate heavy-hitter
  boundaries.
- Risk: a lookup indexed by every tracked value must remain within the existing
  bounded category-index budget and use checked GPU representation.
- Human review: category layer limit, Other color/label, missing/invalid display.

#### Completion Notes

- Added `rawscope_data::CategoryMembershipIndex`, a dataset-generation and
  `ColumnId`-bound typed index for `Utf8`, `Bool`, `I64`, and `U64` values. It
  retains one checked `u32` code per row, dense tracked IDs, and distinct
  Untracked/Missing/Invalid codes outside the tracked range.
- Category values retain typed identity separately from their display labels;
  high-cardinality candidate tracking is bounded and propagates `Truncated`
  accuracy instead of claiming exactness.
- Added analysis-owned `CategoryLayerPlan` and generation counter. Plans select
  explicit values first, use deterministic count/ID tie ordering otherwise, and
  map residual valid values to a count-complete Other layer while keeping Missing
  and Invalid separate. The lookup is bounded by the category index, not rows.
- Added compatibility identity accessors for dataset, column, and selection so
  later jobs/controllers can cache plans without rebuilding the store index.
- Focused data and analysis category tests, formatting, and workspace checks pass.
