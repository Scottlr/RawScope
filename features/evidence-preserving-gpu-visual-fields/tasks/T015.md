### T015 - Add Session V2 And Python Generic Field Bindings

#### Objective

Add an additive session contract and dependency-free Python API for generic
numeric-pair/time-value mappings with an optional category channel, while
preserving session v1 parsing and byte output for legacy views.

#### Scope

- Add a Rust session v2 manifest whose view bindings express numeric-pair,
  time-value, and existing discrete-lane timeline projections by source column.
- Keep profile identifiers optional hints; no profile is required for mapping or
  visual-mode availability.
- Parse v1 and v2 into one dependency-light resolved source/column-binding intent;
  after ingestion, the workbench resolves names to `ColumnId` and constructs the
  one checked T001 mapping without duplicating controller state.
- Extend Python `ScatterView` with an optional category binding and add a
  `TimeValueView`, using only the standard library and deterministic JSON.
- Route both file-backed preparation and the existing dataframe/bundle adapter
  path through the same Python view-to-manifest projection.
- Continue emitting exact legacy v1 output when a Python session uses only v1-
  representable scatter/timeline fields; emit v2 only for new semantics or an
  explicit v2 request.
- Validate duplicate/missing/incompatible columns through existing checked
  schema/session errors with source context.
- Document the small public v2 schema and compatibility behavior next to the
  existing session contract.

#### Out of Scope

- No render mode, palette, contour, ridge, tooltip, pan/zoom, filter, cohort,
  selection, or window-layout persistence.
- No data upload SDK, dataframe dependency, Arrow/Pandas dependency, network
  service, plugin ABI, or code generation.
- No mutation of v1 field names, ordering, defaults, parser semantics, or bytes.
- No profile-specific Python class.

#### Blocked By

T001, T014.

#### Why It Is Blocked

The external schema must target the final generic mapping and controller rather
than serialize temporary render state or create a second interpretation path.

#### Related Code

- T001 `VisualFieldMapping` and T014 visual-field controller/compatibility.
- Existing Rust session crate/contracts, v1 parser/validator/golden tests, source
  resolution, and workbench session adapter.
- Existing dependency-free Python SDK `ScatterView`, `TimelineView`, manifest
  writer, dataframe bundle adapter, validation, public exports, and package
  examples/tests.
- Schema/column identity and source provenance owners from remediation T009-T010.

- Do not edit: visual formulas, GPU resources, canonical evidence, source parser

#### Implementation Details

Add version-specific wire contracts in the session owner:

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct RawScopeSessionManifestV2 {
    pub schema_version: SessionSchemaVersionV2,
    pub source: SessionSource,
    pub view: SessionViewV2,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum SessionViewV2 {
    NumericPair {
        x: SessionColumnBinding,
        y: SessionColumnBinding,
        category: Option<SessionColumnBinding>,
        profile: Option<SessionProfileHint>,
    },
    TimeValue {
        time: SessionColumnBinding,
        value: SessionColumnBinding,
        category: Option<SessionColumnBinding>,
        profile: Option<SessionProfileHint>,
    },
    TimelineLane {
        time: SessionColumnBinding,
        lane: SessionColumnBinding,
        profile: Option<SessionProfileHint>,
    },
}
```

Use existing source/binding/profile wire types where their v1 semantics are
safe. Otherwise add narrowly named v2 wire types and adapters rather than
changing v1 serialization. Version dispatch rejects unknown versions with a
typed error containing the received/supported versions.

Adapt both versions into a version-neutral `ResolvedSessionView` containing
source identity and bounded column-binding names only. `rawscope-session` does
not depend on `rawscope-analysis` or `rawscope-data`. After the dataset store is
loaded, the workbench session adapter resolves each name once through the checked
schema and calls T001's constructor. Numeric-pair X/Y must be numeric; time must
be `TimestampMicros`; value must be numeric; category must be supported by T007's
index. Invalid mappings fail before controller/render work begins.

Python public surface:

```python
@dataclass(frozen=True)
class ScatterView:
    x: str
    y: str
    profile: str | None = None
    category: str | None = None

@dataclass(frozen=True)
class TimeValueView:
    time: str
    value: str
    profile: str | None = None
    category: str | None = None
```

Use the repository's supported Python syntax/version rather than blindly
copying this annotation if it is too new. Existing constructor calls remain
valid. Writer output ordering, newline behavior, escaping, and path handling
stay deterministic. `ScatterView` without `category` and existing
`TimelineView` continue selecting v1 by default.

#### Before / After

**Before:** external callers can bind only legacy scatter or lane timeline
fields, and category/time-value capabilities require manual app interaction.

**After:** Rust and Python callers can describe generic compatible field roles
without knowing renderer internals or adopting a dataset profile.

#### Migration Notes

- Treat v2 as additive; never rewrite a v1 file merely because the parser can
  represent it internally as a generic mapping.
- Preserve Python import paths and legacy constructor behavior.
- Do not serialize current visual mode/style. A session describes data/view
  bindings; canonical evidence records the analytical presentation used.

#### Misinterpretations To Prevent

- Wrong interpretation: session v2 is a render-state dump. Correct rule: it
  carries stable source and field-role intent only.
- Wrong interpretation: profile selects hidden capabilities. Correct rule:
  profile remains an optional hint over the same generic schema.
- Wrong interpretation: all Python output upgrades to v2. Correct rule: legacy-
  representable calls retain exact v1 default output.
- Wrong interpretation: SDK must ingest dataframe objects. Correct rule: this
  task bridges source column names into native checked contracts only.

#### Invariants

- Every valid v1 manifest remains readable and maps to unchanged behavior.
- Legacy Python calls retain deterministic v1 output bytes.
- New mapping validation happens once in the workbench against typed schema
  before GPU/UI work; session crates retain their dependency-light boundary.
- Wire serde remains in the session owner, not analysis/data/render.
- Python stays dependency-free and uses no renderer/domain duplication.
- Session fields are stable user intent, not implementation-specific resources.
