### T017 - Benchmark And Curate The Generic Visual Field Workbench

#### Objective

Complete the feature as a coherent product slice: exercise every generic mode
through real source/controller/render/inspection/evidence paths, measure its
production performance/resource behavior, curate visual defaults, and remove
superseded compatibility owners.

#### Scope

- Add deterministic neutral-schema behavior fixtures covering both numeric-pair
  and time-value mappings, optional bounded category, cohorts, missing/invalid
  rows, dense/sparse regions, and exact boundary values.
- Exercise real CSV/session/store/analysis/controller/GPU presentation paths
  where each behavior belongs; do not substitute a fake app or shader-only demo.
- Extend the existing benchmark harness/protocol with production-path scenarios
  for pointer submission, preview/exact settle, composition, comparison,
  time-value, ridges, semantic point planning, shared readback, and peak resident
  resources.
- Capture p50/p95 interaction submission and settle metrics separately, GPU
  adapter/backend/driver, quality decisions, grid dimensions, rows, visible
  category layers, derived resources, and active/pending/retiring bytes.
- Fix measured feature-owned regressions before release when they come from
  duplicate uploads, pointer-time work, avoidable full-row rebuilding,
  unnecessary retained generations, or incorrect resource admission; rerun the
  same scenario after each scoped correction.
- Curate reviewed defaults for resolution tiers, palettes, contour mass levels,
  semantic crossfade, category layer cap/purity treatment, comparison support/
  split, ridge scale/strength, controls, and reduced motion.
- Verify report/evidence output for each mode through the canonical T016 path.
- Remove obsolete scatter-only resources/controllers/UI modules, duplicate LUTs,
  temporary adapters, unused profile branches, and migration code whose callers
  are now fully generic.
- Update architecture, benchmark, session/SDK, and user-facing README material to
  describe only behavior that is implemented and measured.

#### Out of Scope

- No checked-in large external dataset, Lichess-specific fixture/assertion,
  screenshot test, startup/window smoke test, diagnostic script, dry run, fake
  demo app, wall-clock unit assertion, or unreviewed benchmark claim.
- No new mode, weighted aggregation, animation, plugin system, arbitrary
  composition grammar, or broad unrelated cleanup.
- No benchmark-only closure for a failed approved interaction/resource gate; fix
  the real owner or leave the affected mode explicitly unavailable/incomplete.
- No performance claim without the repository's full reproducibility record.
- No acceptance of duplicate old/new owners merely because both compile.

#### Blocked By

T003, T005, T006, T009, T010, T011, T013, T014, T015, T016.

#### Why It Is Blocked

Integration, performance measurement, default curation, and cleanup are valid
only after every mode and compatibility/evidence path is real. Running this
earlier would benchmark temporary architecture and encourage bolt-on code.

#### Implementation Details

Use at least two neutral deterministic schema shapes with stable generated rows:

```text
horizontal: f64, vertical: f64, segment: utf8, observed_at: timestamp_micros
recorded_at: timestamp_micros, measurement: i64, group: u64
```

Fixtures must include repeated bins, empty areas, ties, category overflow into
Other, explicit missing/invalid values, a baseline/active shift, a narrow band
visible at multiple ridge scales, and timestamp values large enough to expose
f32 epoch loss. Expected assertions target exact counts, membership, formulas,
generation identity, and action projection. They must fail if a mode is only a
label or static texture.

Extend the scenario contracts/runners landed by remediation T057 rather than add
a diagnostic binary. At minimum measure:

- Pointer path: pan/zoom/hover/split submission CPU p50/p95 separately from field
  completion, proving no row scan/dispatch/readback on the event path.
- Field lifecycle: preview and exact settle latency for named grid tiers with
  coalescing/stale cancellation counts.
- Derived work: mass/marginal shared readback, semantic point-plan build,
  category aggregation/presentation, paired comparison, time-value projection,
  and each ridge scale.
- Resources: source/coordinate/exact/category/comparison/ridge/palette/staging/
  transition bytes across active, pending, and retiring generations, plus the
  selected pressure decision/reason.
- Correctness context: rows, eligible rows, field dimensions, category layers,
  adapter limits, and checksum/summary values sufficient to identify the run.

Every recorded run follows `docs/BENCHMARKS.md`: command, scenario/config,
commit, date, OS, CPU/RAM, GPU adapter/backend/driver, dataset identity/shape,
and quality/resource policy. Benchmarks report observations; release docs make
no universal FPS/latency claim from one machine.

Curated defaults are named constants/config owned by their domains, not magic
numbers in egui/WGSL. Each is selected from correctness, accessibility, visual
hierarchy, and measured resource/latency evidence. External large datasets may
be used manually to reveal scale behavior, but CI and product capability remain
profile-neutral.

After migration, perform an ownership audit. Delete obsolete modules only when
all callers and compatibility tests use the final owner. Thin legacy wire
adapters remain only where required for v1/evidence compatibility and must be
named/documented as adapters, not live parallel state.

#### Before / After

**Before:** individual advanced modes may work, but defaults, performance,
compatibility, and ownership can still feel like separate feature additions.

**After:** RawScope presents one measured, generic visual-field instrument whose
modes share exact truth, interaction, resources, inspection, and evidence, with
old duplicate implementation paths removed.

#### Migration Notes

- Preserve all public compatibility explicitly covered by T015/T016; cleanup is
  not permission to remove legacy decoders/writers.
- Rename public Rust types only when the crate's compatibility policy permits it;
  otherwise keep a narrow deprecated type alias/adapter with a removal plan.
- README screenshots/examples may be refreshed manually after visual acceptance,
  but screenshots are documentation assets, never automated tests.
- Do not commit optional large datasets or machine-specific source paths.

#### Misinterpretations To Prevent

- Wrong interpretation: one beautiful large-dataset run proves performance.
  Correct rule: reproducible metrics and resource context support every claim.
- Wrong interpretation: neutral fixtures are toy smoke tests. Correct rule: they
  assert exact production behavior and adversarial boundaries deterministically.
- Wrong interpretation: generic means every dataset supports every mode. Correct
  rule: typed compatibility and explicit unavailable reasons still apply.
- Wrong interpretation: cleanup can remove legacy evidence/session codecs.
  Correct rule: remove duplicate runtime owners, preserve promised wire support.

#### Invariants

- Every enabled mode is exercised through a real compute/presentation path.
- Deterministic tests prove analytical behavior, not window startup or pixels.
- Pointer metrics exclude settle latency and pointer handlers retain bounded work.
- Resource reports include every retained and derived GPU allocation.
- Defaults are named, reviewed, and supported by measured/correctness evidence.
- CI requires no external profile/dataset and contains no wall-clock assertions.
- Exactly one final runtime owner remains for each major responsibility.
- Documentation claims only implemented, verified, reproducible behavior.

#### Testing Guidance

Use the focused tests named by T001-T016 plus integration behaviors such as
`all_enabled_modes_publish_real_generation_resources`,
`neutral_schemas_have_profile_independent_capabilities`,
`pointer_commands_do_not_perform_row_or_gpu_completion_work`,
`resource_report_accounts_active_pending_and_retiring_bytes`,
`session_to_controller_to_evidence_preserves_mapping_identity`, and
`legacy_and_generic_runtime_owners_do_not_both_receive_updates`.

Run the repository's production-path benchmark targets with documented small,
medium/high-volume, and interaction scenarios. Expected targets after
remediation T057 are:

```powershell
cargo bench -p rawscope-workbench --bench interaction_coordinator
$env:RAWSCOPE_ENABLE_GPU_BENCH='1'
cargo bench -p rawscope-render --bench gpu_density
cargo bench -p rawscope-workbench --bench evidence_export
```

Then run:

```powershell
cargo test --workspace
cargo fmt --all --check
cargo check --workspace
```

Run the existing Python SDK test command and any focused report/CLI profile
validation already owned by the repository. Do not invent a diagnostic command
or fake app when an owner has no such target.

## Final Notes

- Recommended order: neutral fixtures, production benchmarks, default curation,
  integrated compatibility/evidence tests, ownership cleanup, truthful docs.
- Unresolved questions become explicit reviewed decisions here; do not leave
  magic defaults or ambiguous compatibility in product code.
- Risk: the largest remaining failure mode is architectural duplication that
  looks harmless in isolation but doubles memory/state and causes drift.
- Human review: final visual beauty, interpretability, accessibility, interaction
  latency, resource fallback, and evidence honesty before release.
