### T004 - Add Perceptual Palette LUTs And Stable Color Semantics

#### Objective

Replace duplicated hard-coded shader/UI color stops with one curated,
linear-light palette LUT source while separating analytical transform/
normalization semantics from render-owned color presentation.

#### Scope

- Move dependency-free `DensityTransform` and `DensityNormalization` semantics
  into `rawscope-analysis::visual_field::encoding` without Serde derives.
- Add render-owned closed sequential, diverging, and categorical palette IDs.
- Generate fixed-size linear RGBA LUTs once per device generation and upload
  them as sampled textures or read-only buffers selected by validated pipeline
  design.
- Make density, timeline, difference, composition, legends, and exported visual
  context derive colors from the same palette definitions.
- Interpolate palette control points in linear light and convert only at the
  output boundary appropriate to the configured surface format.
- Add bounded stable final-color dithering only if needed to avoid visible banding;
  it must not alter exact-cell boundaries or analytical values.

#### Out of Scope

- No user palette editor, arbitrary colors, imported colormaps, broad color
  library, HDR compositor, bloom, glow, blur decoration, or mode-specific color
  knobs.
- No new transform/normalization formula except moving existing linear/log1p and
  viewport-max semantics to their correct owner.
- No category composition mode; T009 consumes the categorical palette.

#### Blocked By

T002, T003.

#### Why It Is Blocked

The LUT must be owned by the final visual-field renderer and accounted once per
device generation under the derived-field resource policy.

#### Implementation Details

Create in analysis:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum DensityTransform { Linear, Log1p }

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum DensityNormalization { ViewportMax }

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct DensityEncoding {
    pub transform: DensityTransform,
    pub normalization: DensityNormalization,
}
```

Retain the tested `density_intensity(count, max_count, transform)` CPU oracle in
analysis. Do not derive Serde; T016 maps it to wire enums.

Create in render:

```rust
pub const PALETTE_LUT_SIZE: usize = 256;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum ContinuousPalette {
    DensitySequential,
    TimelineSequential,
    CohortDifference,
}

pub enum CategoricalPalette {
    CategoryComposition,
}

pub struct ContinuousPaletteLut {
    palette: ContinuousPalette,
    linear_rgba: [[f32; 4]; PALETTE_LUT_SIZE],
}

pub struct CategoryPaletteEntries {
    pub palette: CategoricalPalette,
    pub linear_rgba: Arc<[[f32; 4]]>,
    pub mixed_neutral_linear_rgba: [f32; 4],
}

pub struct PaletteGpuResources {
    device_generation: DeviceGeneration,
    texture: wgpu::Texture,
    view: wgpu::TextureView,
    sampler: wgpu::Sampler,
    allocated_bytes: u64,
}
```

Use a small render-owned list of reviewed control points and deterministic CPU
LUT generation. Legends sample the exact LUT, not a separate four-color method.
Transitions blend linear colors. `CategoryComposition` has at least
T001's `MAX_CATEGORY_COMPOSITION_LAYERS` reviewed discrete entries plus one
reviewed mixed neutral; shaders index category texels exactly and never
interpolate or wrap category identity. Continuous LUT rows and categorical
entries may share one device-generation texture/catalog when the concrete WGPU
layout remains simpler and fully accounted.

If final-color dithering is retained, derive a stable screen-space value from
integer pixel coordinates, cap amplitude to less than one 8-bit code value, and
apply it after semantic color selection. Exact cell edges and alpha remain
unchanged.

#### Before / After

**Before:**

#### Misinterpretations To Prevent

- Wrong interpretation: copy a 256-entry array into every shader. Correct rule:
  one device-generation LUT is sampled by concrete presentations.
- Wrong interpretation: categorical colors may be smoothly mixed to invent a
  category hue. Correct rule: composition uses dominant category identity and a
  separate purity channel.
- Wrong interpretation: use gamma-space interpolation because inputs are RGB.
  Correct rule: interpolation/blending occurs in linear light.
- Wrong interpretation: add color sliders for flexibility. Correct rule: this
  bundle ships curated closed palettes only.

#### Invariants

- Shader, UI legend, and evidence palette identity share one source.
- Count transform/normalization behavior is GPU-independent analysis truth.
- LUT allocation is one accounted device-generation resource.
- Categorical palette identity is discrete.
- Categorical capacity covers the one analysis-owned maximum without color wrap.
- Dithering cannot change counts, boundaries, selection, or evidence.
- No new dependency or Serde leak enters analysis/render.

## Completion Notes

- Moved the dependency-free transform and normalization semantics into
  `rawscope-analysis::visual_field::encoding` and kept the existing evidence
  Serde model intact for bundle compatibility.
- Added render-owned continuous and categorical palette identities plus a
  deterministic, linear-light 256-sample RGBA LUT. The GPU stores normalized
  linear bytes in one `Rgba8Unorm` texture per device generation; CPU legends
  sample the same LUT implementation.
- `WorkbenchApp` creates one shared `Arc<PaletteGpuResources>` for the active
  device generation and passes it to scatter, timeline, and comparison
  presentation. Direct renderer constructors retain a fallback-owned palette
  for compatibility and isolated callers.
- Density, timeline, difference, and legend paths now consume the shared LUT;
  duplicated WGSL/UI stops were removed. T003 resource accounting includes
  the LUT once when aggregating multiple visual-field owners.
- Validation passed for the focused analysis, render palette, workbench legend,
  formatting, and workspace checks. GPU integration targets compile with
  `--no-run`; runtime GPU cases remain ignored here because no local WGPU
  adapter is available.
- No screenshot goldens, dithering, new palette formulas, or category-composition
  behavior were added. T016 still needs an explicit adapter between evidence
  wire encodings and the analysis-owned semantic encoding.
