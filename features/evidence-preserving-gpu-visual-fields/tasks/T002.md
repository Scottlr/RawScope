### T002 - Reorganize Scatter Rendering Into Visual Field Owners

#### Objective

Move the existing exact, topographic, relief, reprojection, transition, and
resident count behavior into focused generic visual-field owners so later modes
extend one pipeline instead of wrapping a scatter-specific renderer.

#### Scope

- Create `crates/rawscope-render/src/visual_field/` with vertical modules for
  generation metadata, dataset resources, exact count fields, reprojection, and
  density presentation.
- Rename/migrate `ScatterDatasetGpuResources`, `ScatterFieldGeneration`, and
  `ScatterViewGeneration` into generic visual-field equivalents tied to T001's
  mapping.
- Move existing scatter density compute/render lifecycle without changing count
  placement, presentation output, pan reprojection, transitions, or readback.
- Move the current difference renderer under a focused `comparison` owner while
  preserving behavior until T010 changes presentation.
- Migrate workbench/controller callers and delete old duplicate scatter modules
  or compatibility aliases in the same task.
- Keep discrete-lane timeline render resources separate.

#### Out of Scope

- No adaptive grid selection, new palette, mass contours, composition, new
  comparison lens, time-value execution, ridges, or UI changes.
- No generic renderer trait, render graph, plugin registry, dynamic pipeline map,
  or one giant enum-driven shader.
- Do not rewrite already-correct WGSL formulas during the move.

#### Blocked By

T001.

#### Why It Is Blocked

Resident field generations must carry the validated generic mapping rather than
introduce another render-owned mapping identity.

#### Implementation Details

Use concrete generation contracts, not a polymorphic renderer framework:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct VisualFieldViewGeneration(Generation<VisualFieldViewOwner>);

pub struct VisualFieldDatasetGpuResources {
    dataset_generation: DatasetGeneration,
    device_generation: DeviceGeneration,
    mapping: VisualFieldMapping,
    point_buffer: wgpu::Buffer,
    row_mapping_buffer: wgpu::Buffer,
    point_count: u64,
    allocated_bytes: u64,
}

pub struct VisualFieldGeneration {
    dataset: Arc<VisualFieldDatasetGpuResources>,
    cohort_generation: CohortGeneration,
    view_generation: VisualFieldViewGeneration,
    grid: GridSize,
    quality: VisualFieldQuality,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum VisualFieldQuality { Preview, Exact }
```

Actual buffers remain private and are exposed only through methods needed to
create concrete bind groups. `VisualFieldGeneration` is constructed by the
resource owner; callers cannot supply metadata separately from buffers.

Target module shape:

```text
rawscope-render/src/visual_field/
  mod.rs
  generation.rs
  dataset_resources.rs
  exact_field.rs
  exact_field_resources.rs
  reprojection.rs
  density_presentation/
    mod.rs
    exact.rs
    topographic.rs
    relief.rs
  comparison/
    mod.rs
    resources.rs
    compute.rs
    presentation.rs
```

Keep facades thin. The current difference renderer/resources already exceed the
review threshold when combined, so they must not be collapsed into one
`comparison.rs`; likewise, split density presentations by real pipeline/state
responsibility rather than moving the existing renderer wholesale.

Shader assets may move to `shaders/visual_field_*` only when every include and
test moves in the same change. Do not copy shaders under new names.

Existing `ExactCells`, `TopographicField`, and `ReliefField` output remains
pixel-equivalent for the same count grid/config. Reprojection still maps display
coordinates through data space and leaves uncovered regions empty. Previous
resources remain only while generation/mapping/grid compatibility validates.

**Before:**

**After:**


#### Migration Notes

- Preserve all current visual behavior and focused parity tests.
- Remove T001's temporary projected-scatter adapter; current render callers now
  consume the generic `VisualFieldPoint` coordinate seam while T003/T011 bind
  full `ProjectedVisualFieldGeneration` resources.
- Do not retain public old/new aliases after all repository callers migrate.
- Session/evidence wire shapes remain unchanged.

#### Misinterpretations To Prevent

- Wrong interpretation: add a `VisualFieldRenderer` trait implemented by each
  mode. Correct rule: concrete WGPU owners share validated resources explicitly.
- Wrong interpretation: leave `ScatterDensityRenderer` as the real owner and add
  a generic facade. Correct rule: implementation ownership moves and duplicates
  are deleted.
- Wrong interpretation: merge lane timeline into the same renderer. Correct rule:
  only continuous 2D visual fields share this path.
- Wrong interpretation: rewrite shaders while moving files. Correct rule:
  behavior stays fixed until later tasks.

#### Invariants

- One packed coordinate/row mapping allocation exists per live dataset/device/
  mapping generation.
- Count fields and metadata cannot reference different generations.
- Reprojection and transition compatibility include mapping and grid identity.
- Timeline lane resources remain specialized.
- Render facade stays thin and no broad registry/trait is introduced.
- No old scatter implementation remains as a second owner.
