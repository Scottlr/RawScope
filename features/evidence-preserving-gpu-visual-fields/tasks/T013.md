### T013 - Add Resident GPU Density Ridge Presentation

#### Objective

Compute and render T012's multiscale density ridges as a static, generation-safe
derived presentation of a settled resident exact field, preserving CPU/GPU
formula parity and avoiding any visual suggestion of row motion.

#### Scope

- Add ridge compute resources and pipelines under T002's visual-field owner.
- Execute the fixed smoothing, Hessian/eigen, discrete height-ridge/local-maximum,
  anisotropy, max-reduction, normalized-strength, and undirected orientation
  stages defined by T012 for one selected closed scale.
- Tie ridge resources to exact field generation, dimensions, config, and palette
  identity; publish only complete matching generations.
- Render bounded oriented ridge marks/highlights over a quiet density context,
  with strength controlling visibility and no animated phase/noise.
- Reproject the last compatible settled ridge presentation during gestures and
  coalesce new ridge work only after the exact field settles.
- Include ridge buffers, intermediates, pipelines, transitions, and staging in
  T003 resource accounting, with a documented pressure fallback.
- Add deterministic CPU/GPU parity fixtures including intermediate stages where
  needed to localize drift.

#### Out of Scope

- No animated flow, particles, trails, LIC, arrowheads, path integration,
  streamlines, perspective terrain, cluster boundaries, or row-level movement.
- No dispatch/readback on pointer events or every animation frame.
- No simultaneous ridge/category/comparison composite mode.
- No shader-only formula, arbitrary scale slider, or new render framework.

#### Blocked By

T002, T003, T004, T012.

#### Why It Is Blocked

GPU ridges need the final resident field architecture, checked resource policy,
one palette source, and frozen CPU formula/scale contracts.

#### Related Code

- T002 field resources/generation, T003 coordinator/budget, T004 palette LUT,
  and T012 CPU ridge reference.
- Existing relief/topographic compute/render pipelines, WGSL ABI tests,
  reprojection lifecycle, and active/pending/retiring generation ownership.
- WGPU limit/recovery/readback owners from remediation T022-T025 and T034.

#### Implementation Touchpoints

- Read first: field texture/buffer formats, compute bind layouts, relief shader
  derivatives, reprojection compatibility, resource plan arithmetic, and device
  recovery cache invalidation.
- Edit first: `rawscope-render/src/visual_field/ridges/resources.rs`,
  `compute.rs`, `presentation.rs`, and focused WGSL files; then coordinator intent.
- Symbols to search: `DensityGpuResources`, `Relief`, `Topographic`,
  `RenderResourcePlan`, `ActiveGeneration`, `Reprojection`, and ABI size tests.
- Required structural change: ridge stages consume shared exact field resources;
  they do not duplicate coordinates, cohort masks, or the exact count pipeline.
- Do not edit: T012 formulas except through a reviewed joint correction,
  workbench controls before T014, session/evidence wire, or source indexes.
- Verify in order: ABI/layout, stage parity, generation rejection, resource
  bounds, reprojection/settle behavior, presentation, format, workspace.
- Stop and ask: if target adapters cannot support required storage/compute limits,
  if a new dependency is proposed, or if pressure fallback would alter counts.

#### Implementation Details

Use explicit host/WGSL ABI contracts:

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct GpuRidgeCell {
    pub strength: f32,
    pub tangent_x: f32,
    pub tangent_y: f32,
    pub _padding: f32,
}

pub struct RidgeFieldGpuResources {
    pub generation: VisualFieldViewGeneration,
    pub config: RidgeConfig,
    pub cells: wgpu::Buffer,
    pub scratch_and_reduction_bytes: u64,
    pub resource_bytes: u64,
}

pub struct RidgeFieldGeneration {
    pub source: Arc<VisualFieldGeneration>,
    pub config: RidgeConfig,
    pub resources: Arc<RidgeFieldGpuResources>,
}
```

Checked arithmetic computes `width * height * size_of::<GpuRidgeCell>()` and all
intermediate storage before allocation. Validate workgroup dimensions, dispatch
counts, storage binding sizes, and total budget against the selected adapter.
All pipelines/cache keys include formats and ridge config; device recovery drops
device-owned caches and rebuilds from CPU/source generation state.

Prefer a small fixed sequence of separable smoothing, Hessian/candidate,
max-reduction, and normalization passes matching T012 over one opaque shader.
The candidate pass performs the minor-eigenvector local-maximum and anisotropy
tests; reduction finds the generation/config raw-strength maximum before the
final cutoff. Reuse scratch buffers within a generation when lifetimes do not
overlap and doing so remains clear in the resource plan. Production does not
read back ridge fields; focused parity tests may use the bounded existing async
readback path.

The presentation transforms normalized-field tangents through the current
plot-space scale, renormalizes them, and draws short antialiased unoriented marks
or a continuous highlight aligned to that visible tangent. It is clipped to the
plot and modulated by strength. It must not use arrowheads, traveling phase,
moving texture, or asymmetric lighting. The quiet context still communicates
total density and exact focus inspection remains available from the source field.

On resource pressure, first disable transition retention, then choose a lower
validated field tier or mark ridge presentation unavailable with an explicit
reason. Never subsample source rows, change the scale silently, or publish a
partial ridge generation.

#### Before / After

**Before:** users can see height/contours but must infer elongated density shape
from color alone.

**After:** a static GPU-derived overlay reveals local multiscale field structure
while exact counts and the absence of movement semantics remain clear.

#### Migration Notes

- Relief and topographic modes keep their current meanings and can share common
  field sampling/palette resources without sharing ridge state.
- Do not expose ridge controls until parity/resource fallbacks are complete.
- T016 serializes formula/config identity, not GPU buffer formats or pipeline
  implementation details.

#### Misinterpretations To Prevent

- Wrong interpretation: marks point in a direction. Correct rule: tangent is
  undirected and presentation must look symmetric under sign reversal.
- Wrong interpretation: ridges follow individual rows. Correct rule: they derive
  only from a smoothed aggregate count field.
- Wrong interpretation: lower-quality fallback may change scale invisibly.
  Correct rule: every quality/config change is explicit state.
- Wrong interpretation: animation makes ridges more GPU-native. Correct rule:
  motion would add unsupported meaning and is forbidden.

#### Invariants

- GPU stages implement T012's reviewed coefficients, edges, and normalization.
- Ridge generation identity includes exact source generation, dimensions, and
  config; stale or partial results never publish.
- All GPU sizes/dispatches are checked against limits and accounted in budgets.
- Pointer/animation handlers never schedule ridge compute or readback.
- Presentation is static, undirected, clipped, finite, and reduced-motion safe.
- Plot aspect changes transform orientation at draw time and do not require
  ridge recomputation.
- Exact count inspection and evidence remain owned by the source field.

#### Acceptance Criteria

- [ ] GPU ridge strength/orientation matches CPU reference within documented
      tolerance on deterministic fixtures.
- [ ] Fine/medium/coarse produce visibly and mathematically distinct results.
- [ ] Ridge resources publish atomically and reject stale/mixed generations.
- [ ] Gestures immediately reproject compatible settled output and settle through
      the coordinator without per-pointer dispatch.
- [ ] Resource pressure has explicit truthful fallback/unavailable behavior.
- [ ] Presentation contains no directed or animated motion cues.
- [ ] Focused tests, formatting, and workspace check pass.

## Final Notes

- Recommended order: resources/ABI, compute stages, parity tests, generation
  lifecycle, resource fallback, static presentation, inspection context.
- Unresolved questions: mark style, context strength, parity tolerance, and the
  reviewed minimum-strength default for each scale.
- Risk: a dense overlay can obscure the underlying evidence even when its math
  is correct; presentation density needs restrained human curation.
- Human review: verify no direction/motion implication on unrelated horizontal,
  diagonal, crossing, sparse, and noisy fields.
