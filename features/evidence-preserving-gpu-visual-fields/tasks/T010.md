### T010 - Add Cohort Comparison Split Lens And Contextual Difference Shading

#### Objective

Rework cohort comparison as two presentations of the same exact baseline and
active count fields: an interpretable signed-difference field with visible
baseline support and a movable split lens that compares identical render
semantics without recomputation.

#### Scope

- Move the existing normalized difference formula and comparison resources into
  T002's visual-field comparison owner rather than retaining a scatter-only
  difference renderer.
- Require baseline and active generations to share mapping, axis domains, grid
  dimensions, count aggregation, transform, normalization, palette, and the same
  dataset row domain while retaining their distinct cohort membership masks.
- Render signed active-share-minus-baseline-share over quiet neutral baseline
  density so sparse unsupported color does not appear as strong evidence.
- Add a vertical split presentation showing baseline on one side and active on
  the other, with one plot-space split fraction updated by uniform only.
- Derive active and baseline marginals from T005's shared settled snapshots and
  show both against the same marginal scale.
- Extend exact-cell inspection with both counts, normalized shares, signed
  delta, denominator totals, and freshness/generation identity.
- Keep comparison publication atomic and reject stale or mixed-generation
  baseline/active pairs.

#### Out of Scope

- No statistical significance, confidence interval, hypothesis test, causal
  language, automatic cohort discovery, multi-pane dashboard, or arbitrary
  blend between cohorts.
- No separate grids, palettes, transforms, normalization scales, or axis domains
  on opposite sides of the split.
- No compute dispatch, readback, row scan, or field rebuild while the split is
  dragged.
- No composition-plus-comparison or ridge-plus-comparison mode in this bundle.

#### Blocked By

T002, T003, T004, T005.

#### Why It Is Blocked

Comparison needs one generic resident field owner, checked paired-resource
budgets, shared palette semantics, and settled exact counts/marginals before a
split or support-aware difference can be truthful.

#### Implementation Details

Keep the analytical formula in `rawscope-analysis`:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct DifferenceCellContext {
    pub baseline_count: u32,
    pub active_count: u32,
    pub baseline_share: f64,
    pub active_share: f64,
    pub signed_delta: f64,
    pub support_share: f64,
}

pub fn summarize_difference_cell(
    baseline_count: u32,
    baseline_total: u64,
    active_count: u32,
    active_total: u64,
) -> Result<DifferenceCellContext, ComparisonError>;
```

Keep presentation selection and the checked uniform value in `rawscope-render`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ComparisonPresentation {
    SignedDifference,
    VerticalSplit,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ComparisonSplit {
    fraction: f32,
}

impl ComparisonSplit {
    pub fn new(fraction: f32) -> Result<Self, ComparisonPresentationError>;
    pub fn fraction(self) -> f32;
}
```

Reject a zero baseline or active total, preserving existing comparison
availability. `signed_delta` remains `active_count / active_total -
baseline_count / baseline_total`. Define `support_share` as
`(baseline_share + active_share) / 2`, giving each cohort equal influence despite
different row totals. It may modulate alpha or chroma, but never delta magnitude,
and UI/evidence must call it support rather than significance.

Render comparison from one paired resource:

```rust
pub struct ComparisonFieldGeneration {
    pub baseline: Arc<VisualFieldGeneration>,
    pub active: Arc<VisualFieldGeneration>,
    pub baseline_total: u64,
    pub active_total: u64,
    pub shared_density_max_count: u32,
    pub max_abs_delta: f64,
    pub max_support_share: f64,
    pub compatibility: ComparisonCompatibility,
}
```

Construction validates dataset generation, mapping, domains, dimensions,
transform, normalization, and each mask's row-domain/generation identity before
publication; it does not require equal membership. Signed difference first
draws neutral baseline context, then the reviewed diverging LUT with support-
aware visibility. Normalize signed color symmetrically by `max_abs_delta` and
support visibility linearly by `support_share / max_support_share`, with explicit
zero-field behavior. For split density, both sides use
`shared_density_max_count = max(baseline_max_count, active_max_count)` through
the same T004 transform. Vertical split samples baseline for
`plot_x < fraction` and active otherwise. The split boundary, handle, and labels
are overlays; dragging changes only a uniform and controller state.

Inspection uses exact cell counts from the paired settled context. It reports
both cohort totals and shares so the user can reconstruct the delta. Marginals
share one scale and distinguish cohorts with line style/color that remains
legible with the diverging field.

#### Before / After

**Before:** normalized difference color can lose baseline context, while direct
comparison requires mentally switching views.

**After:** users can inspect exact normalized change with visible support or
drag a zero-cost split across identically encoded baseline and active fields.

#### Migration Notes

- Preserve the existing normalized difference formula and cohort meaning.
- Existing comparison session/evidence decoders remain unchanged until T016;
  adapters map old scatter comparison state into the generic owner.
- If current difference resources duplicate coordinates or masks, delete those
  copies after the shared visual-field resources own them.

#### Misinterpretations To Prevent

- Wrong interpretation: low-support fading means statistically insignificant.
  Correct rule: it is a presentation aid only; exact counts remain inspectable.
- Wrong interpretation: split sides may autoscale independently. Correct rule:
  both sides use identical field and color semantics.
- Wrong interpretation: dragging the split schedules a new field. Correct rule:
  it updates one bounded uniform only.
- Wrong interpretation: delta is raw count subtraction. Correct rule: it stays
  normalized active share minus baseline share.
- Wrong interpretation: each split side may use its own viewport maximum.
  Correct rule: one shared count maximum drives both density presentations.

#### Invariants

- Baseline and active fields are generation-compatible before publication.
- Empty comparison cohorts are unavailable; non-empty difference math is finite
  and CPU/GPU-consistent.
- Support changes visibility, never the reported signed delta.
- Diverging delta, support, and split-density normalization record their shared
  maxima explicitly.
- Split movement performs no allocation, upload, dispatch, readback, or row work.
- Exact inspection counts and shares reconstruct the displayed formula.
- Resource accounting includes both cohorts, transitions, and readback staging.
