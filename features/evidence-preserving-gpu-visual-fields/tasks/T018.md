### T018 - Add A Rounded Professional Analytical Workbench Shell

#### Objective

Rework the existing egui workbench chrome into a simpler Blender/modern-Visual-
Studio-inspired analytical workspace: compact, dark, rounded, information-dense,
and centred on the GPU viewport without weakening evidence, interaction, or
accessibility behavior.

#### Scope

- Keep one curated RawScope shell with a compact top command bar, a narrow
  activity/tool rail, a central plot viewport, a collapsible properties/evidence
  inspector, and a concise bottom status strip.
- Give the viewport and secondary regions consistent rounded panel frames,
  spacing, borders, elevation, typography, and interaction states from one
  RawScope-owned theme token source.
- Move existing navigation, interaction-mode, export/reset/clear, dataset
  identity, visual controls, drilldown, and status content into explicit shell
  regions without creating new analytical state or commands.
- Add a deterministic responsive layout policy: collapse low-priority labels and
  secondary panels before reducing the central viewport below named usable
  dimensions; keep every collapsed region keyboard-reachable and reversible.
- Preserve the current authoritative egui-to-physical plot allocation used by
  WGPU viewport/scissor, axes, pointer routing, brush, crosshair, tooltip, and
  inspection.
- Keep reduced-motion behavior authoritative for any bounded panel transition;
  immediate state changes remain the fallback.
- Split `ui_shell.rs` by vertical responsibility if the landed implementation
  would push it beyond the repository's roughly 400-line boundary.

#### Out of Scope

- No generic docking framework, arbitrary panel graph, detachable/floating
  windows, saved workspace layouts, multi-document tab system, or new UI crate.
- No copy of Blender or Visual Studio branding, icons, terminology, or exact
  layout. They are references for density, hierarchy, and calm professional
  chrome only.
- No visual-field mode, transform, aggregation, renderer formula, evidence,
  session, source-store, or cohort behavior change.
- No blur, acrylic/translucent GPU effect, animated background, ornamental
  shader, or fake rounded clipping over the rectangular WGPU plot.
- No dashboard cards, marketing panels, tutorial flow, screenshot tests, smoke
  app, or diagnostic utility.

#### Blocked By

T003.

#### Why It Is Blocked

T003 establishes the physical-plot-driven resource policy and names the final
plot-size contract. The shell must consume that contract without redefining its
resource semantics or creating a second viewport measurement path.

#### Implementation Details

Use named shell metrics owned by the theme/layout domain rather than scattered
panel literals. Exact values remain a human visual-tuning decision, but the
contract should make units and responsive priorities explicit:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub(crate) struct WorkbenchChromeMetrics {
    pub(crate) outer_margin_points: f32,
    pub(crate) region_gap_points: f32,
    pub(crate) panel_corner_radius_px: u8,
    pub(crate) command_bar_height_points: f32,
    pub(crate) activity_rail_width_points: f32,
    pub(crate) inspector_width_points: f32,
    pub(crate) status_bar_height_points: f32,
    pub(crate) minimum_plot_width_points: f32,
    pub(crate) minimum_plot_height_points: f32,
}
```

Keep explicit, closed regions rather than a docking tree:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum ShellRegionState {
    Collapsed,
    Expanded,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) struct WorkbenchShellState {
    pub(crate) activity_rail: ShellRegionState,
    pub(crate) inspector: ShellRegionState,
}
```

The responsive policy computes a presentation projection without silently
overwriting the user's preferred expanded state. On constrained windows it
first hides secondary text, then presents the inspector collapsed, then presents
the activity rail collapsed. If the named minimum viewport still cannot fit,
render the existing unavailable/insufficient-area state rather than allowing
overlap or invalid physical dimensions.

The rounded visual treatment applies to egui-owned chrome. The GPU plot remains
the exact rectangle returned by `allocate_plot_surface`; axes, input routing,
WGPU viewport/scissor, and inspection all consume that same result. A rounded
viewport surround may frame the plot, but it must not paint over data pixels or
claim a hit region different from `PlotSurfaceLayout`.

Use the existing icon source and typed `UiActions`. Activity-rail selection is a
projection of existing `WorkbenchSurface`, `ActiveView`, and interaction-mode
commands, not a second navigation state. T014 later places generic field mapping,
mode, legend, and evidence controls into these stable regions.

#### Before / After

**Before:** functional top/right/bottom panels use mixed hard-coded dimensions;
the viewport is central but the shell reads as a collection of controls rather
than one composed analytical instrument.

**After:** a restrained rounded workspace gives the plot clear visual primacy,
keeps high-frequency tools close, makes inspector content progressively
disclosable, and remains truthful to the same GPU and interaction geometry.

#### Migration Notes

- Preserve every existing shortcut and typed action. Relocation must not change
  command meaning or create duplicate state.
- Preserve dataset provenance: concise identity may remain in chrome, but full
  source details stay reachable as required by T014.
- Migrate `InspectorState` to the final closed region state only once; remove the
  superseded type/constants rather than retaining adapters indefinitely.
- Do not persist responsive presentation collapse as a user preference. Restore
  the user's chosen expanded state when sufficient space returns.
- Keep the current dark RawScope palette unless human review approves token
  changes; rounded panels are not permission for low-contrast borders or text.

#### Misinterpretations To Prevent

- Wrong interpretation: Blender-like means reproduce Blender's docking system.
  Correct rule: borrow compact hierarchy and viewport focus for one fixed shell.
- Wrong interpretation: modern means every control becomes a pill or card.
  Correct rule: use restrained radii and elevation to group regions, not decorate
  every row.
- Wrong interpretation: round the plot by masking its corners. Correct rule:
  preserve the authoritative rectangular GPU/hit-test region; round its egui
  surround only.
- Wrong interpretation: responsive means discard panel preference. Correct rule:
  temporary presentation collapse is separate from user-expanded state.
- Wrong interpretation: shell work can redesign visual controls. Correct rule:
  T018 supplies stable regions and tokens; T014 owns final mode controls.

#### Invariants

- One `WorkbenchShellState` owns user shell preferences; responsive projection
  is derived and does not become a second mutable source of truth.
- One `PlotSurfaceLayout` remains authoritative for axes, pointer math, brush,
  crosshair, tooltip, inspection, WGPU viewport, and scissor.
- Secondary chrome never overlaps the plot and collapses before named minimum
  plot dimensions are violated.
- Rounded frames, spacing, borders, shadows, typography, and animation duration
  come from one theme token owner.
- Every shell action projects to an existing typed command or visibility change;
  no egui callback mutates renderer or analytical resources directly.
- Collapsed regions remain keyboard reachable, clearly labelled, and reversible.
- Reduced motion makes any shell transition immediate.
- No new runtime dependency or generic docking/window abstraction is introduced.
