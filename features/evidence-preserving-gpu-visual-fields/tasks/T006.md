### T006 - Complete Continuous Density-To-Point Semantic Zoom

#### Objective

Replace the current competing density-cell/point overlay with one continuous,
generation-cached semantic zoom that performs row selection off the pointer path
and truthfully discloses exact versus sampled point rendering.

#### Scope

- Split settled point selection from frame presentation and move the former into
  an analysis/job result tied to dataset/cohort/mapping/view generations.
- Reuse final projected points, cohort snapshot, and existing deterministic row
  priority; consume any final generation-owned bin/spatial membership index when
  it can answer exact viewport rows, and do not rescan source strings or build a
  competing source index.
- Build point plans only for settled viewport intents on the native job
  coordinator; pan/zoom reprojects the last compatible plan or temporarily
  favors density.
- Define one bounded density/point crossfade from rows per physical plot pixel.
- Render anti-aliased glyphs with density alpha reduced as point alpha rises;
  remove equally prominent exact-cell blocks beneath a fully revealed point set.
- Preserve hover emphasis, filter alignment, maximum point budget, and sampled/
  full disclosure.

#### Out of Scope

- No per-frame CPU scan, pointer-time compute, GPU sorting experiment, force
  layout, trails, random jitter, category composition coloring (T009), or new
  point-shape editor.
- No claim that a sampled reveal renders every row.
- Do not change selection/evidence membership; point reveal is presentation.

and palette rather than preserve current scatter-only/frame-owned behavior.

#### Implementation Details

Create analysis contracts:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct SemanticZoomPolicy {
    pub density_only_above_rows_per_pixel: f32,
    pub points_only_below_rows_per_pixel: f32,
    pub max_rendered_points: NonZeroU32,
    pub point_radius_px: f32,
}

#[derive(Debug, Clone, PartialEq)]
pub struct PointRevealPlan {
    pub dataset_generation: DatasetGeneration,
    pub cohort_generation: CohortGeneration,
    pub view_generation: VisualFieldViewGeneration,
    pub row_ids: Arc<[RowId]>,
    pub eligible_count: u64,
    pub sampled: bool,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct SemanticZoomFrame {
    pub density_alpha: f32,
    pub point_alpha: f32,
}
```

`SemanticZoomPolicy::try_new` validates finite ordered thresholds, positive
radius, and bounded point count. `build_point_reveal_plan` iterates the immutable
projected generation/cohort at most once on a worker for a settled viewport, or
queries the final exact membership index when one has landed. It applies the
stable row priority and returns sorted unique row IDs. It allocates at most the
approved point budget plus bounded selection workspace; use partial selection,
not a full sort of every eligible row. Do not add a second row-proportional
index solely for point reveal without measured/human-reviewed justification.

`semantic_zoom_frame(rows_per_physical_pixel, policy)` is continuous and
monotonic. At points-only, density may remain a low-contrast contextual field
but exact-cell edges/contours cannot remain equally dominant. Reduced motion
changes transition timing, not alpha endpoints.

The renderer resolves row IDs through the existing row mapping/point buffer;
invalid/stale IDs fail the plan rather than being silently omitted. Hover
emphasis is a constant-size uniform update.

#### Before / After

**Before:**

```rust
let selection = select_points_for_reveal(points, mask, viewport, plot, config);
// rebuilt from app/frame paths
```

**After:**

```rust
let frame = semantic_zoom_frame(rows_per_pixel, policy);
renderer.draw_cached_plan(&plan, frame);
```

#### Misinterpretations To Prevent

- Wrong interpretation: move the current full scan into `render()`. Correct rule:
  build once for settled generation on a job and cache it.
- Wrong interpretation: hide the sampled label because points look complete.
  Correct rule: eligible/rendered/sample status remains visible and exported.
- Wrong interpretation: fade in points while leaving opaque density cells.
  Correct rule: one crossfade hierarchy controls both channels.
- Wrong interpretation: random sample each frame. Correct rule: row-ID priority
  is deterministic across runs for the same generation.

#### Invariants

- Point plans match dataset/cohort/mapping/view generation.
- Pointer/frame paths do no row-proportional work.
- Rendered row IDs are sorted, unique, valid, and bounded.
- Density and point alpha are continuous, finite, and bounded 0..=1.
- Sample disclosure cannot be omitted when eligible count exceeds rendered count.
- Selection and evidence truth do not depend on point reveal.

## Final Notes

- Recommended order: validated policy, off-thread plan, controller cache,
  crossfade shader, old scan removal, disclosure projection.
- Unresolved question: point-plan workspace strategy at very large eligible
  counts.
- Risk: sorting all eligible rows can dominate settle latency; use bounded
  deterministic selection and benchmark the production path.
- Human review: crossfade thresholds, glyph radius, and contextual density alpha.

#### Completion Notes

- Added analysis-owned `SemanticZoomPolicy`, `SemanticZoomFrame`, and generic
  `PointRevealPlan` contracts. Plans use one projected-point pass and a bounded
  priority heap, return sorted unique row IDs, and retain eligible/rendered/
  sampled disclosure counts.
- Added render-owned point presentation frames and a resident-buffer plan upload
  path. Stale or non-resident row IDs are rejected; hover emphasis remains a
  constant-size uniform update.
- Workbench point planning now runs through the native job coordinator only for
  settled revisions. Pointer viewport changes retain the resident plan and only
  update its viewport/frame, while stale completions are ignored by the full
  dataset/cohort/view/viewport identity.
- Density opacity is reduced to a subdued contextual level as point opacity rises;
  the point overlay uses the existing anti-aliased glyph shader and keeps sampled
  disclosure in the existing UI/export projection.
- Focused analysis, render, and workbench point-reveal tests plus formatting and
  workspace checks pass. GPU runtime coverage remains adapter-gated in this
  environment.
