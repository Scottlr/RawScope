### T011 - Add Generic Time-Value Density Projection

#### Objective

Let any validated timestamp column and numeric value column use the common exact
2D visual-field pipeline, preserving original timestamp precision for axes,
brushing, inspection, and evidence while using bounded relative coordinates on
the GPU.

#### Scope

- Implement T001's `TimeValue` projection from typed `TimestampMicros` and
  numeric store columns, filtered by the same immutable cohort masks as numeric
  pairs.
- Normalize timestamps relative to a checked origin/span before f32 GPU upload;
  retain original integer microseconds in analytical and inspection state.
- Use the same adaptive resolution, exact count, palette, contour, marginal,
  semantic zoom, and ridge paths as compatible numeric-pair fields.
- Preserve the optional compatible category mapping/channel identity so T009's
  generic composition path can consume the field once both tasks have landed;
  do not create a time-specific category pipeline.
- Add exact time/value rectangle brushing and constant-time settled-cell
  inspection with profile-neutral timestamp formatting.
- Keep the existing timestamp-by-discrete-lane timeline as a separate view with
  its current lane semantics.
- Record time quantization disclosure in state for T016 evidence.

#### Out of Scope

- No animated playback, trails, inferred row continuity, trajectories, event
  ordering beyond source timestamps, seasonality decomposition, calendar heat
  map, or discrete-lane replacement.
- No string parsing in render/workbench code and no profile-identity gate.
- No absolute epoch microseconds cast directly to f32.
- No new time/date dependency; use existing typed timestamp/formatting owners.
- No category-composition implementation in this task; T014/T017 prove the
  already-generic T009 path against time-value fields.

#### Blocked By

T001, T002, T003, T004.

#### Why It Is Blocked

Time-value must be a projection variant of the generic mapping and resident
field architecture, with checked resolution and one palette source, rather than
a parallel timeline-like renderer.

#### Implementation Details

Add an analysis-owned checked transform:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct TimeAxisTransform {
    pub origin_micros: i64,
    pub span_micros: u64,
}

impl TimeAxisTransform {
    pub fn from_domain(min_micros: i64, max_micros: i64)
        -> Result<Self, TimeValueProjectionError>;
    pub fn normalized(self, value_micros: i64) -> f64;
    pub fn denormalized(self, normalized: f64) -> i64;
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum VisualAxisSelectionRange {
    I64 { min: i64, max: i64 },
    U64 { min: u64, max: u64 },
    F64(F64Domain),
    TimestampMicros { min: i64, max: i64 },
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct VisualFieldBrushSelection {
    pub x: VisualAxisSelectionRange,
    pub y: VisualAxisSelectionRange,
}
```

For a non-zero domain, normalize as `(time - origin) / span` using `i128` for
differences before checked conversion to `u64`/`f64`, then upload the bounded
result. Never subtract extreme `i64` timestamps directly. A zero-span time
domain maps all valid rows to the center bin and retains the exact single
timestamp. Axis labels and tooltip values always come from `TimestampMicros`,
never from f32 round trips.

The projection constructor validates mapping kinds and returns T001's
`ProjectedVisualFieldGeneration` with `VisualAxisDomain::TimestampMicros` on X.
It skips rows according to the same missing/invalid policy as numeric-pair
projection, preserves stable `RowId`, and records eligible/projected counts.

Brushing transforms plot coordinates back through the time transform, rounds
lower/upper boundaries outward, clamps to the exact typed source domain, and
tests membership against typed store values through the canonical selection
owner. The visual quantization/error remains disclosed; it is not described as
microsecond screen precision. If legacy `ScatterRect` is public wire state,
retain its decoder and add the generic typed variant rather than changing old
bytes.

#### Before / After

**Before:** time can be shown only against discrete lanes, while continuous
measurements over time require reshaping into a less accurate view.

**After:** any timestamp/value pair becomes a precise, brushable GPU density
field with the same truthful analytical and presentation hierarchy as numeric
pairs.

#### Migration Notes

- Do not rename or reinterpret the existing lane timeline session/evidence view.
- Numeric-pair output must remain unchanged for the same mapping and settings.
- T015 adds external session/Python bindings after the internal mapping and UI
  are stable.

#### Misinterpretations To Prevent

- Wrong interpretation: time-value is animated scatter. Correct rule: it is a
  static aggregate of timestamp/value rows.
- Wrong interpretation: rows sharing an ID form a path. Correct rule: this task
  infers no continuity or trajectory.
- Wrong interpretation: f32 GPU coordinates are evidence timestamps. Correct
  rule: integer microseconds remain authoritative and quantization is disclosed.
- Wrong interpretation: lane timeline is deprecated. Correct rule: discrete
  lane and continuous value questions remain separate views.

#### Invariants

- Timestamp precision is retained in analytical, brush, inspection, and evidence
  state even when GPU coordinates are normalized.
- Projection uses typed store values and stable row IDs with no render parsing.
- Time-value and numeric-pair use one exact field/resource/presentation path.
- Zero-span and extreme valid timestamp domains produce finite coordinates.
- Pointer-time brushing/inspection performs bounded coordinate/cache work only.
- Profile identity never controls availability or formatting behavior.
