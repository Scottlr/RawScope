### T001 - Add Generic Visual Field Mapping And Projection Contracts

#### Objective

Replace scatter-only projection identity with one checked mapping for generic
numeric-pair and time-value fields, plus an immutable projected generation that
all later visual modes consume.

#### Scope

- Add `rawscope-analysis::visual_field` as the semantic owner of 2D visual
  mappings, projection kinds, axis domains, modes, and projected points.
- Validate stable `ColumnId` bindings against `DatasetSchema` and reject wrong
  kinds, duplicate axes, absent category fields, and unsupported mode/channel
  combinations with typed errors.
- Extend generic dataset field roles with `Value` and `Category` without
  changing existing role meaning.
- Migrate current numeric scatter projection into the new generation contract.
- Leave the discrete time-by-lane timeline contract separate.
- Add a temporary internal compatibility conversion for current scatter callers;
  T002 must remove it after renderer migration.

#### Out of Scope

- No GPU buffers, WGPU packing, render modes, UI controls, session wire changes,
  evidence serialization, category indexing, or time-value execution.
- No weighted aggregation, calculated fields, expressions, arbitrary axis types,
  or generic chart grammar.
- Do not move mapping types into `rawscope-core`; schema-aware validation belongs
  in analysis.

#### Implementation Details

Create these closed contracts in `mapping.rs`:

```rust
pub const MAX_CATEGORY_COMPOSITION_LAYERS: u8 = 8;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum VisualFieldProjection {
    NumericPair { x: ColumnId, y: ColumnId },
    TimeValue { time: ColumnId, value: ColumnId },
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct VisualFieldMapping {
    projection: VisualFieldProjection,
    category: Option<ColumnId>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum VisualFieldMode {
    Density,
    CategoryComposition,
    CohortComparison,
    DensityRidges,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum VisualFieldMappingError {
    MissingColumn { column_id: ColumnId },
    DuplicateAxes { column_id: ColumnId },
    AxisKindMismatch { column_id: ColumnId, expected: VisualAxisKind },
    CategoryKindMismatch { column_id: ColumnId },
    CategoryMatchesAxis { column_id: ColumnId },
    CategoryRequired,
}
```

`VisualFieldMapping::try_new(schema, projection, category)` validates:

- numeric-pair axes are `I64`, `U64`, or `F64` and differ;
- time-value `time` is `TimestampMicros`, `value` is numeric, and they differ;
- category is `Utf8`, `Bool`, `I64`, or `U64`, differs from both axes, and is
  optional; integer-coded groups remain exact while `F64`/timestamps stay
  continuous until a separate equality policy is specified;
- `supports(mode)` returns a typed availability result, not a string.

`MAX_CATEGORY_COMPOSITION_LAYERS` is the one semantic upper bound, including
Other/Missing/Invalid. Eight is a candidate requiring palette/resource/human
review before implementation; later tasks consume this constant rather than
repeat a numeric limit.

Create projection types in `projection.rs`:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ProjectedVisualPoint {
    pub row_id: RowId,
    pub x: f64,
    pub y: f64,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum VisualAxisDomain {
    I64 { min: i64, max: i64 },
    U64 { min: u64, max: u64 },
    F64(F64Domain),
    TimestampMicros { min: i64, max: i64 },
}

#[derive(Debug, Clone, PartialEq)]
pub struct ProjectedVisualFieldGeneration {
    dataset_generation: DatasetGeneration,
    mapping: VisualFieldMapping,
    points: Arc<[ProjectedVisualPoint]>,
    x_domain: VisualAxisDomain,
    y_domain: VisualAxisDomain,
}
```

Construction reads typed normalized store cells, excludes or rejects rows only
according to the already-validated cohort/invalid policy, and records exact time
and integer endpoints even when projected/GPU coordinates later use f64/f32.
The quantization disclosure landed by remediation T010 remains attached to the
generation path. It must not retain a second copy of raw source rows or synthetic
category annotations.

Extend `DatasetFieldRole` with `Value` and `Category`. Derive identity bindings
from `VisualFieldMapping`; profiles may propose a mapping but do not alter
validation or mode availability.

#### Migration Notes

- Numeric scatter output remains behaviorally identical for finite values.
- Keep one crate-private conversion to the current packed scatter input only
  until T002 migrates GPU consumers; mark its removal in rustdoc/TODO with T002.
- Do not add a public type alias that permanently preserves scatter-only naming.
- Existing session/evidence bytes are unchanged.

#### Misinterpretations To Prevent

- Wrong interpretation: add optional category/time fields to
  `ScatterPointRecord`. Correct rule: source columns stay in the store; the
  validated mapping and channel indexes bind them by `ColumnId`.
- Wrong interpretation: use column names as analysis identity. Correct rule:
  names are presentation/wire metadata; runtime identity uses stable IDs.
- Wrong interpretation: make every current timeline use the generic field.
  Correct rule: only time-versus-numeric-value uses this 2D field; discrete lanes
  retain their specialized timeline semantics.
- Wrong interpretation: retain `ScatterPointKind` as a generic category.
  Correct rule: synthetic annotations are fixture/legacy concerns, not product
  category semantics.

#### Invariants

- Mapping validity is independent of dataset profile identity.
- One mapping identifies every axis and optional category channel.
- Projected points preserve stable `RowId` and immutable dataset generation.
- Exact integer/timestamp endpoints remain available for axes/evidence.
- Analysis remains free of WGPU, egui, Serde, and evidence dependencies.
- No permanent second scatter projection owner remains after T002.
