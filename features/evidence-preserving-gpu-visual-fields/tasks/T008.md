### T008 - Add Resident GPU Category Composition Aggregation

#### Objective

Upload one reusable category-code channel for a validated dataset column, upload
only a bounded lookup when the visible layer plan changes, and compute bounded
per-layer count fields sharing the exact visual-field coordinates, cohort mask,
grid, and generation lifecycle.

#### Scope

- Add category-channel GPU resources with dataset-column lifetime separated from
  layer-plan lifetime.
- Upload one packed row-aligned `u32` category-code buffer and reuse it until the
  dataset, category column, or device generation changes.
- Upload a bounded category-value-to-layer lookup only when the T007 layer plan
  changes; do not rewrite one layer ID per source row.
- Add a compute pipeline that clears and atomically bins each included row into
  exactly one layer count field using the same coordinate/bin boundary contract
  as the exact total field.
- Reuse the existing total count field; do not compute/store a duplicate total.
- Add double-buffered layer fields for safe active/pending publication,
  generation-cached bind groups, optional asynchronous exact readback for T009,
  and complete resource accounting.
- Add a deterministic CPU reference and ignored real-adapter parity test.

#### Out of Scope

- No composition colors, entropy, tooltip, point coloring, UI, filtering, or
  evidence wire changes.
- No unbounded layer count, per-category pipeline creation, or separate point
  coordinate upload.
- No readback during pointer movement or every rendered frame.

#### Blocked By

T002, T003, T007.

#### Why It Is Blocked

Aggregation requires final shared coordinate resources, checked grid/budget
policy, stable store category codes, and a complete bounded layer plan.

#### Implementation Details

Create:

```rust
pub struct CategoryChannelGpuResources {
    dataset_generation: DatasetGeneration,
    device_generation: DeviceGeneration,
    column_id: ColumnId,
    category_codes_buffer: wgpu::Buffer,
    row_count: u64,
    code_layout: CategoryCodeLayout,
    allocated_bytes: u64,
}

pub struct CategoryLayerPlanGpuResources {
    plan_generation: CategoryLayerPlanGeneration,
    value_to_layer_buffer: wgpu::Buffer,
    special_layer_params_buffer: wgpu::Buffer,
    layer_count: NonZeroU8,
    allocated_bytes: u64,
}

pub struct CategoryCompositionFieldGeneration {
    exact_field: Arc<VisualFieldGeneration>,
    category_channel: Arc<CategoryChannelGpuResources>,
    layer_plan: Arc<CategoryLayerPlanGpuResources>,
    active_layer_counts: wgpu::Buffer,
    pending_layer_counts: wgpu::Buffer,
    readback: Option<ReadbackTicket<Vec<u32>>>,
    allocated_bytes: u64,
}
```

Keep actual mutable WGPU state private; public metadata/accessors expose
generation, layer/grid sizes, freshness, and accounted bytes only.

Use an explicit `#[repr(C)]` special-layer parameter block for Untracked,
Missing, Invalid, and layer count. Pack absent assignments as one named invalid
sentinel such as `NO_CATEGORY_LAYER = u32::MAX`; an included row resolving to
that sentinel is a validation/publication error, not a silently skipped row.

Buffer layout is layer-major:

```text
index = layer_id * grid_bin_count + y_bin * grid_width + x_bin
```

Validate every tracked/special lookup result against `layer_count` on CPU before
upload and in WGSL defensively. For each included point, load its stable category
code, resolve it through the bounded value/special lookup, compute the same X/Y
bin as total density, and `atomicAdd` one layer count. The sum across layers for
every bin must equal the exact active total count for that bin. A mismatch
prevents publication.

`GpuResourcePlan` checks the stable row-code channel, bounded lookup,
`layer_count * grid_bin_count * sizeof(u32)` for both active/pending fields, and
readback staging with checked arithmetic/device limits. Bind groups cache by
coordinate resource, mask resource, channel resource, plan generation, grid
capacity, and device generation.

#### Before / After

**Before:**

```text
point buffer + mask -> one total count field
```

**After:**

```text
shared point buffer + mask + stable category codes + bounded layer lookup
  -> existing total count field + bounded layer-major count field
```

#### Migration Notes

- Absolute density remains unchanged and does not allocate composition resources
  until the mode/channel is requested/admitted.
- Layer-plan replacement uploads only a pending bounded lookup/field and
  publishes atomically; the row category channel remains reusable and failure
  retains the prior active field.
- No evidence/session change in this task.

#### Misinterpretations To Prevent

- Wrong interpretation: allocate one renderer/pipeline per category. Correct
  rule: one bounded layer-major field and one compute pipeline.
- Wrong interpretation: duplicate point coordinates inside composition. Correct
  rule: share the T002 dataset coordinate resource.
- Wrong interpretation: rewrite/upload all row layer IDs when visible categories
  change. Correct rule: stable row category codes use one bounded plan lookup.
- Wrong interpretation: recompute total density in composition. Correct rule:
  layer counts must sum to the existing exact total field.
- Wrong interpretation: read back layers to choose colors every frame. Correct
  rule: presentation is GPU-side; exact readback is settled/O(1) inspection data.

#### Invariants

- Dataset/device/mapping/cohort/plan/grid generations all match before publish.
- Every included row contributes to exactly one category layer/bin.
- Per-bin layer sum equals exact total count.
- Layer/grid resources are bounded and fully accounted active+pending+staging.
- Row channel upload occurs only on dataset/column/device change, not layer-plan
  or viewport changes.
- Pointer/frame paths perform no composition readback.

#### Acceptance Criteria
