### T009 - Add Anchored Animated Inspection Tooltip

#### Objective

Turn the current pointer-following popup into a stable, edge-aware analytical
tooltip that is anchored to the inspected bin, explains the cached metrics, and
uses short motion without degrading interaction performance.

#### Scope

- Replace raw pointer offset placement with pure bin-anchored placement.
- Add deterministic right/left/above/below candidate selection and viewport
  clamping that avoids covering the exact bin.
- Present exact ranges/count first, then active share/density percentile or
  difference explanation, then explicitly secondary neighborhood context.
- Add 110 ms enter/bin-change fade plus at most 4 px rise, and 80 ms exit.
- Drive the WGPU focus `presentation_alpha` from the same transition frame.
- Retain the last immutable summary only for exit animation.
- Respect reduced motion and schedule frames only while a transition is active.
- Suppress absolute-mode tooltip/focus for empty exact cells; in difference mode
  allow cells where either active or baseline count is nonzero.

#### Out Of Scope

- No spring chase, cursor trailing, perpetual pulse, blur backdrop, sound,
  source-row table, category scan, pin redesign, evidence change, or arbitrary
  tooltip configuration.
- No change to analytical formulas from T006/T007.

#### Blocked By

T006, T007, T008.

#### Why It Is Blocked

Placement and motion must operate on final summary content and drive the
dedicated focus overlay rather than the old brush probe.

#### Implementation Details

Pure types:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub(crate) struct InspectionPresentationKey {
    pub(crate) viewport_revision: u64,
    pub(crate) filter_revision: FilterRevision,
    pub(crate) bin_x: u32,
    pub(crate) bin_y: u32,
    pub(crate) density_mode: ScatterDensityMode,
}

pub(crate) struct TooltipPlacementInput {
    pub(crate) bin_rect: egui::Rect,
    pub(crate) tooltip_size: egui::Vec2,
    pub(crate) viewport_rect: egui::Rect,
    pub(crate) gap_px: f32,
}

pub(crate) struct InspectionPresentationFrame {
    pub(crate) opacity: f32,
    pub(crate) translate_y_px: f32,
    pub(crate) running: bool,
}
```

Constants live near this owner:

- `TOOLTIP_GAP_PX = 10.0`
- `TOOLTIP_VIEWPORT_MARGIN_PX = 8.0`
- `TOOLTIP_ENTER_DURATION_MS = 110`
- `TOOLTIP_EXIT_DURATION_MS = 80`
- `TOOLTIP_ENTER_TRANSLATE_Y_PX = 4.0`
- `TOOLTIP_REPAINT_INTERVAL_MS = 16`

Placement order is right, left, above, below, choosing the first candidate that
fits within the viewport margin without intersecting the exact bin. If none
fits, choose the candidate with the largest visible area, clamp it, and preserve
the gap from the bin on the axis where possible. Placement uses the logical
projection of the exact bin rect, not `pointer_hover_pos`.

Measure the tooltip with an egui sizing pass or a stable constrained width of
`240..=300` logical px. Do not let content width change placement every frame.
Use 4 px corner radius maximum, restrained border/shadow, and no nested card.

Motion state transitions only when `InspectionPresentationKey` changes or
visibility changes. Compute progress from elapsed milliseconds through a pure
easing function so behavior tests do not sleep. On reduced motion, opacity is
immediately 1/0, translation is zero, and `running=false`.

While `running`, call `context.request_repaint_after(16 ms)`. Do not call
`WorkbenchApp::request_redraw` every idle inspect frame. Apply opacity with
`ui.set_opacity(frame.opacity)` and pass the same opacity to T008 overlay input.

Content hierarchy:

1. compact x/y ranges using existing axis formatter rather than fixed `.3`;
2. exact row count and active cohort percentage;
3. absolute: "Nth percentile among occupied cells"; difference: directional
   active/baseline shares plus percentage-point delta and strength percentile;
4. "Nearby 3x3" count/share in muted text;
5. bounded sample disclosure only when a row sample exists.

Do not say "probability," "significant," or "better."

#### Before / After

**Before:** popup follows every pointer pixel, may leave the viewport, and shows
only count/ranges with abrupt appearance.

**After:** one stable tooltip belongs to one data bin, explains its meaning, and
enters/exits cleanly without analytical work or redraw after settling.

#### Migration Notes

- Keep Inspect mode and click-to-pin event semantics unchanged.
- Existing reduced-motion toggle now governs tooltip/focus motion too.

#### Misinterpretations To Prevent

- Wrong: lerp tooltip toward cursor every frame. Correct: anchor to bin rect.
- Wrong: animate indefinitely. Correct: finite enter/change/exit only.
- Wrong: animate by mutating evidence/hover truth. Correct: presentation only.
- Wrong: label sample/category facts as exact. Correct: explicit disclosure.
- Wrong: make empty absolute cells noisy. Correct: suppress them.

#### Invariants

- Same presentation key drives content, focus rect, and animation alpha.
- Tooltip never changes the inspected hit or pin target.
- Edge placement keeps text visible and does not cover the exact cell.
- Settled hover schedules no additional frames.

#### Acceptance Criteria

- [ ] Placement handles center and all four viewport edges deterministically.
- [ ] One-bin hover is stable under pointer motion within that bin.
- [ ] Content uses T006/T007 metrics with truthful wording.
- [ ] Enter/change/exit durations and translation are bounded.
- [ ] Reduced motion is immediate and schedules no animation frames.
- [ ] Empty absolute cells are silent; meaningful difference cells remain.
