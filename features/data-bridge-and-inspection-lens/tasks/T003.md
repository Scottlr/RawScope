### T003 - Load Session Manifests In The Workbench

#### Objective

Make `rawscope-workbench --session <manifest>` open the same real scatter or
timeline path as direct CLI bindings while retaining validated session context
for UI and evidence.

#### Scope

- Add the `rawscope-session` dependency to the workbench.
- Parse `--session path` and `--session=path`.
- Make `--session` mutually exclusive with `--demo`, `--input`,
  `--compare-input`, binding, limit, and profile flags.
- Resolve the manifest before entering the event loop so startup failures return
  a non-zero process error with manifest context.
- Project resolved scatter/timeline view fields into the existing
  `WorkbenchInput` and `DemoMode` paths rather than building another loader.
- Validate the optional evidence key after the source table is loaded.
- Store an `ActiveSessionContext` with manifest path, display name, format, and
  validated evidence-key descriptor.
- Use session display name in short dataset identity while preserving the rule
  that full paths do not appear in persistent chrome.
- Split CLI tests out of the already over-400-line `cli.rs`.

#### Out Of Scope

- No live dataset reload, file dialog, drag-and-drop, mapping wizard, comparison
  session, filter preset, Python behavior, or network input.
- No change to direct CLI meanings or synthetic default.
- No evidence schema change; T011 owns it.

#### Blocked By

T001, T002.

#### Why It Is Blocked

The app needs the resolved session DTO and evidence-key validator before it can
map startup state without duplicating either contract.

#### Implementation Details

Refactor startup into an explicit app-owned result:

```rust
pub(crate) struct WorkbenchStartup {
    pub(crate) demo_mode: DemoMode,
    pub(crate) input: Option<WorkbenchInput>,
    pub(crate) compare_input: Option<PathBuf>,
    pub(crate) session: Option<PendingSessionContext>,
}

pub(crate) fn resolve_workbench_startup(
    args: WorkbenchArgs,
) -> Result<WorkbenchStartup, WorkbenchStartupError>;
```

`WorkbenchArgs` records either `session_path` or the current direct fields. The
parser must also track whether `--demo` was explicitly supplied: the implicit
scatter default is not a conflict, while an explicit `--demo` beside
`--session` is. Use one `saw_direct_startup_flag` predicate rather than trying
to infer this from post-parse default values.
`main` calls parser, then resolver, then `WorkbenchApp::new(startup)`. Do not
parse JSON inside `WorkbenchApp` or during each render.

Map a resolved session as follows:

- scatter -> `DemoMode::Scatter` and `WorkbenchInput::Scatter` with path,
  explicit x/y, resolved profile, and limit;
- timeline -> `DemoMode::Timeline` and `WorkbenchInput::Timeline` with path,
  explicit time/lane, resolved profile, and limit.

Do not run profile defaults twice or let a profile override explicit session
bindings. Existing resolver behavior already treats complete explicit bindings
as overrides after schema validation; reuse it.

After loading `LoadedSourceTable`, call `validate_evidence_key` only when the
pending session declares one. Commit the resulting descriptor into:

```rust
pub(crate) struct ActiveSessionContext {
    pub(crate) manifest_path: PathBuf,
    pub(crate) display_name: Option<String>,
    pub(crate) data_format: SessionDataFormat,
    pub(crate) evidence_key: Option<DatasetEvidenceKey>,
}
```

Do not retain a second source table or decoded manifest. If key validation
fails, fail startup with dataset path, key name, and validation source.

Move the existing `cli.rs` test module to `cli_tests.rs` using an explicit
`#[cfg(test)]` path/module declaration, then add session parser tests there.

#### Misinterpretations To Prevent

- Wrong: implement a separate session loader. Correct: adapt to `WorkbenchInput`.
- Wrong: allow `--session` plus overrides. Correct: v1 manifest is authoritative.
- Wrong: show manifest/data paths in the title. Correct: use short identity.
- Wrong: validate the evidence key during every inspection. Correct: once/load.

#### Invariants

- A session and equivalent direct flags load identical rows and bindings.
- Manifest current-directory independence survives workbench launch.
- Session metadata is absent for synthetic/direct CLI input.
- `cli.rs` is below its pre-task size and remains parsing-focused.
