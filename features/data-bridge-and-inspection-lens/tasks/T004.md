### T004 - Add Python File Bridge And Native Launcher

#### Objective

Give Python users a small typed API that references an existing local CSV or
Parquet file, writes the exact session v1 contract, and launches the native
RawScope workbench without requiring callers to assemble CLI flags.

#### Scope

- Add a non-published Python package under `sdk/python` with import name
  `rawscope` and distribution name `rawscope-sdk`.
- Require Python 3.10 or newer and keep the core package standard-library only.
- Add frozen dataclasses for `ScatterView`, `TimelineView`, `DatasetSource`, and
  `PreparedSession`.
- Validate file extension, binding names, non-blank optional profile, positive limit,
  display name, and evidence-key spelling before writing.
- Write canonical UTF-8 session JSON with relative dataset paths when the
  manifest and source share a sensible local parent; otherwise use an absolute
  local path.
- Write manifest files atomically through a sibling temporary file plus replace.
- Add `prepare`, `launch`, and `view` public functions for file sources.
- Resolve the workbench executable explicitly and launch with `--session`.

#### Out Of Scope

- No dataframe objects or Parquet materialization; T005 owns them.
- No package publication, wheel signing, bundled Rust executable, installer,
  auto-update, network fetch, REST/IPC, notebook widget, or async API.
- No initial filters, visual style, comparison input, arbitrary view grammar, or
  schema introspection of path-only inputs.

#### Blocked By

T001, T003.

#### Why It Is Blocked

Python must write the frozen Rust field contract and launch a workbench that
already consumes `--session`.

#### Implementation Details

Public API:

```python
@dataclass(frozen=True, slots=True)
class ScatterView:
    x: str
    y: str
    profile: str | None = None

@dataclass(frozen=True, slots=True)
class TimelineView:
    time: str
    lane: str
    profile: str | None = None

def prepare(
    source: str | os.PathLike[str],
    *,
    view: ScatterView | TimelineView,
    destination: str | os.PathLike[str],
    display_name: str | None = None,
    evidence_key: str | None = None,
    limit: int | None = None,
) -> PreparedSession: ...

def launch(
    session: PreparedSession | str | os.PathLike[str],
    *,
    executable: str | os.PathLike[str] | None = None,
) -> RawScopeProcess: ...

def view(source, *, view, destination, executable=None, **dataset_options) -> RawScopeProcess: ...
```

For this task `destination` is required and names either a bundle directory or
a `.rawscope.json` path; pick one convention and keep it unambiguous. Preferred:
a directory containing `analysis.rawscope.json`. Existing source files are not
copied. `PreparedSession` exposes `manifest_path`, `dataset_path`, and
`persistent=True`.

Executable resolution order:

1. explicit `executable` argument;
2. `RAWSCOPE_WORKBENCH` environment variable;
3. `rawscope-workbench` found by `shutil.which`.

Do not assume a repository checkout or search `target/debug`. Resolution failure
raises `RawScopeExecutableNotFound` with the three supported remedies.

`RawScopeProcess` wraps `subprocess.Popen` and exposes `pid`, `poll`, `wait`, and
`terminate`. Do not use `shell=True`. Command arguments are a sequence:
`[executable, "--session", manifest_path]`.

Python manifest generation must use exactly:

- `artifact_kind = "rawscope.session"`
- `schema_version = 1`
- lowercase `csv`/`parquet`
- tagged view object with `kind = "scatter"` or `"timeline"`
- omitted optional keys rather than JSON null
- two-space indentation and a trailing newline.

Keep validation exceptions typed under `RawScopeError`; include field/path
context without printing data values.

Do not hard-code the Rust list of supported profile ids in Python. Python
rejects a blank profile value and writes a non-blank value unchanged;
`rawscope-session`/`rawscope-data` remain authoritative for whether that profile
is supported. This avoids a second versioned registry in the SDK.

#### Before / After

**Before:** Python can only spawn RawScope by reconstructing several CLI flags.

**After:** a file user can call `rawscope.view(path, view=ScatterView(...),
destination=...)` and receive a handle to the native process.

#### Migration Notes

- Package remains local/source-installable and is not published.
- The JSON compatibility fixture becomes a cross-language contract; changes
  require a future session schema version.

#### Misinterpretations To Prevent

- Wrong: wrap Rust through PyO3. Correct: v1 uses files plus subprocess launch.
- Wrong: copy every existing dataset. Correct: path inputs are referenced.
- Wrong: use shell command strings. Correct: pass an argument sequence.
- Wrong: silently search repo build folders. Correct: explicit/env/PATH only.
- Wrong: put pandas in base dependencies. Correct: core remains stdlib-only.

#### Invariants

- Python output is accepted by the Rust T001 parser.
- Preparing a file does not mutate or upload it.
- Atomic replace prevents a partially written manifest.
- Paths with URI schemes are rejected before launch.

#### Acceptance Criteria

- [ ] Typed scatter/timeline sessions write exact compatible JSON.
- [ ] CSV/Parquet formats and optional fields are validated.
- [ ] Executable resolution order and argument quoting are deterministic.
- [ ] `view` composes real `prepare` plus `launch` behavior.
- [ ] Base package imports without pandas, Polars, or PyArrow installed.
