### T010 - Refine Pinned Inspection And Persistent Focus

#### Objective

Make a pinned region feel like durable analytical state: keep it visible on the
GPU canvas, present exact versus sampled facts clearly, and show natural source
keys when a bridged session declares one.

#### Scope

- Keep the pinned exact cell/neighborhood focus visible after hover leaves.
- Render pinned focus beneath transient hover when both exist.
- Prevent pinning an empty absolute-density cell; allow meaningful difference
  cells where baseline or active count is nonzero.
- Refine the right-rail pinned section into a compact hierarchy with clear
  ranges, counts, shares, percentile/difference meaning, sample disclosure,
  category summaries, and bounded source/evidence-key rows.
- Label category counts as sample-derived and show `sample_count of bin_count`.
- Show evidence-key values for bounded sampled rows when available.
- Use an icon command with tooltip for clearing pin and preserve keyboard focus.
- Clear pin on dataset/projection changes, but preserve it through repaint,
  panel collapse, density presentation change, and hover movement while its
  cache revision remains valid.

#### Out Of Scope

- No multiple pins, pin-to-pin comparison, annotations, editable labels, filter
  creation, arbitrary columns, full row table, exact all-row recovery, or export
  schema changes.
- No new per-pin source scan; use bounded row samples already materialized.

#### Implementation Details

Replace pin payload shape with:

```rust
pub(crate) struct PinnedScatterInspection {
    pub(crate) summary: ScatterInspectionSummary,
    pub(crate) difference: Option<DifferenceInspectionSummary>,
    pub(crate) category_summaries: Vec<PinnedCategorySummary>,
    pub(crate) source_rows: Vec<LoadedSourceRow>,
    pub(crate) evidence_keys: Vec<PinnedEvidenceKeyValue>,
    pub(crate) cache_viewport_revision: u64,
    pub(crate) cache_filter_revision: FilterRevision,
}
```

`PinnedCategorySummary` must include `sample_row_count` and `bin_row_count` or
inherit them from the pin. Its value counts sum to no more than sample count.
Do not label them "top categories in region" without "sample". Preferred copy:
"Sample categories (16 of 842 rows)."

Natural key values are projected only from `source_rows` through the validated
`DatasetEvidenceKey`; never scan the full source table. Display at most the
existing row sample limit. Key label and values use monospace and elision/copy
tooltip for long values; no full persistent path.

Visual hierarchy:

- eyebrow/section: `Pinned region` plus clear icon;
- exact x/y range rows;
- primary `row_count` and active share;
- density percentile or difference direction/delta/strength;
- muted neighborhood context;
- sample disclosure, then sampled categories and key values.

Do not put a card inside the right-rail card/section. Use spacing, rules, and
typography. Keep heading sizes compact.

Pin validity: compare stored revisions to current cache before rendering. A
filter change may either clear immediately or rebuild/rebind only if exact data
ranges still map to a current cell; choose immediate clear for v1 to avoid
silently changing the pinned cohort. Dataset/projection changes always clear.
Presentation/transform/relief changes preserve the pin.

#### Before / After

**Before:** pin appears only as rail text after the hover rectangle disappears,
and sampled category counts can look exact.

**After:** pin remains visibly tied to one GPU cell and its rail clearly
separates exact grid facts from a bounded row/category/key sample.

#### Misinterpretations To Prevent

- Wrong: sampled categories describe all bin rows. Correct: label sample size.
- Wrong: pin is a filter/selection. Correct: persistent inspection only.
- Wrong: keep stale pin after filter change. Correct: clear on cohort revision.
- Wrong: reveal arbitrary source columns. Correct: bounded configured summaries
  and optional evidence key only.
- Wrong: create nested cards. Correct: one restrained rail section.

#### Invariants

- Pin, persistent focus, rail summary, and exported v4 pin refer to one cell.
- Exact facts are cache-derived; sample facts are explicitly bounded.
- No full-table work occurs on pin beyond existing bounded row lookup.
- Hover cannot overwrite or silently move pinned state.
