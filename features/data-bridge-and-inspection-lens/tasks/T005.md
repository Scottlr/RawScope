### T005 - Add Python Dataframe To Parquet Adapters

#### Objective

Let Python analysts send a pandas DataFrame, Polars DataFrame/LazyFrame, or
PyArrow Table/RecordBatch to RawScope by materializing one typed Parquet file
inside a session bundle and preserving that bundle for the native process.

#### Scope

- Add optional pandas, Polars, and PyArrow adapter modules.
- Detect supported objects without importing every ecosystem at base-package
  import time.
- Validate required view/evidence-key columns against the dataframe schema.
- Materialize to `data.parquet` while preserving column names, nulls, row order,
  and supported Arrow-compatible scalar types.
- Reject zero-row inputs, duplicate column names, unsupported nested/object
  columns, incomplete Polars lazy schemas, and evidence keys containing null or
  duplicate values.
- Add temporary-bundle behavior for `view(dataframe, ...)` and persistent bundle
  behavior for `prepare(..., destination=...)`.
- Return a process wrapper that keeps temporary artifacts alive until the child
  exits and cleans only its owned directory.

#### Out Of Scope

- No dataframe transformations, expressions, joins, remote reads, query
  pushdown, streaming transport, zero-copy claim, background server, or Rust
  extension module.
- No automatic categorical filter generation or inferred x/y choice.
- No arbitrary Python iterator/list-of-dicts ingestion in this bundle.

#### Implementation Details

Extend source typing through an internal adapter protocol, not a public plugin
system:

```python
class DataframeAdapter(Protocol):
    def column_names(self) -> tuple[str, ...]: ...
    def row_count(self) -> int: ...
    def validate_evidence_key(self, column: str) -> None: ...
    def write_parquet(self, path: Path) -> None: ...
```

Adapter selection is explicit type recognition in a small ordered function.
Unsupported objects raise `UnsupportedDataSource` and list file paths, pandas,
Polars, and PyArrow as accepted categories. It is not an external registration
API.

Optional dependency groups:

- `pandas`: pandas plus PyArrow as its Parquet engine;
- `polars`: Polars;
- `arrow`: PyArrow;
- `test`: all three plus the package's chosen focused test runner, if any.

Keep versions compatible with Python 3.10 and do not claim package publication.

Polars `LazyFrame` must call schema collection before writing and may collect to
Parquet once. The API must disclose this is materialization, not streaming.
PyArrow `RecordBatch` converts to a one-batch table. pandas object columns are
accepted only when conversion to a supported flat Arrow scalar type succeeds;
surface the offending column/type on failure.

Column validation happens before writing. Evidence-key validation uses native
dataframe operations where available but must match T002: no null/blank and no
duplicates after string-equivalent representation. The generated manifest names
the key; Rust remains authoritative and validates again after loading.

Temporary lifecycle:

- `view(dataframe, destination=None)` creates an owned directory under the OS
  temp root with prefix `rawscope-session-`.
- It writes `data.parquet` and `analysis.rawscope.json`, then launches.
- `RawScopeProcess.wait()` cleans the owned directory after child exit.
- `terminate()` waits for exit before cleanup.
- Dropping a wrapper while its child is alive must not delete the dataset.
- Cleanup verifies the resolved target is inside the exact owned temp directory;
  never recursively delete a caller-provided destination.
- Persistent `prepare(..., destination=...)` never auto-cleans.

Do not promise cleanup after interpreter crash. Document that stale OS-temp
directories may remain after abnormal termination; do not add a sweeping cleanup
daemon or broad age-based deletion.

#### Before / After

**Before:** users must manually export a dataframe and construct CLI flags.

**After:** users can call:

```python
process = rawscope.view(
    games,
    view=rawscope.ScatterView("white_rating", "black_rating"),
    evidence_key="game_id",
)
```

and RawScope opens a real Parquet-backed native view.

#### Migration Notes

- Path-source behavior from T004 stays dependency-free and unchanged.
- Dataframe support is optional; missing extras produce actionable import errors.

#### Misinterpretations To Prevent

- Wrong: serialize dataframe rows to JSON. Correct: materialize Parquet.
- Wrong: claim zero-copy. Correct: dataframe conversion and file I/O copy data.
- Wrong: eagerly import all frameworks. Correct: select only installed adapter.
- Wrong: delete temp data immediately after `Popen`. Correct: keep for lifetime.
- Wrong: add an adapter plugin registry. Correct: three owned adapters only.

#### Invariants

- Generated Parquet opens through the existing Rust loader without a special
  Python code path.
- Row order remains stable, preserving dense ordinal `RowId` alignment.
- Required binding and evidence-key columns exist before launch.
- Cleanup cannot remove caller-owned files.

#### Acceptance Criteria

- [ ] One real minimal dataframe from each supported ecosystem produces a
  Rust-loadable Parquet session.
- [ ] Unsupported/missing/duplicate schema cases fail with column context.
- [ ] Temporary bundles survive while the child is live and clean after wait.
- [ ] Persistent destinations are never automatically deleted.
- [ ] Base `rawscope` import still works with no optional extras.
